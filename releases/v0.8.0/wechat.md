# 行影集 v0.8.0 发布：文件夹浏览、自动化工具与更稳的照片整理

行影集 v0.8.0 正式发布。本次更新围绕三个真实使用场景展开：保留原有目录习惯来浏览照片、把更多管理能力交给命令行与 AI 工具，以及让照片清理和账户恢复更加可靠。

从 v0.7.1 升级到 v0.8.0 不需要执行新的数据库迁移。无论你是日常管理家庭照片，还是维护一套规模较大的自托管图库，这一版都能带来更直接的体验提升。

## 文件夹浏览：沿着熟悉的目录找照片

很多人的照片在接入行影集之前，就已经按照“年份 / 旅行地点 / 活动名称”整理在硬盘中。过去进入相册后，这层目录关系不够直观；v0.8.0 新增了完整的**文件夹层级浏览**，原有整理方式终于可以直接延续下来。

你可以从扫描根目录逐层进入子文件夹，通过面包屑快速返回上级目录，并在网格与列表视图之间切换。列表支持按名称、拍摄时间和文件大小排序，进入目录后仍可选择照片、下载、加入相册、加入人物或删除。

例如，把多年旅行照片分散保存在不同城市文件夹中的用户，现在可以像使用本地文件管理器一样进入“2026 / 青海 / 环湖自驾”，同时继续使用行影集的缩略图、人物与相册能力。文件夹统计也改为更高效的批量处理，大型照片库展开目录时会更加顺畅。

## 断舍离：网络波动也不打断清理节奏

“断舍离”适合快速筛掉模糊、重复或不再需要的照片，但连续操作时最怕网络波动：明明已经做出选择，却不知道删除是否成功。

新版本会在离线时暂存删除操作，连接恢复后自动同步。滑动过程中偶尔出现旧卡片闪现的问题也已修复。现在可以更连贯地完成一轮筛选，不必频繁停下来确认状态。

## 页面缓存：返回后还在刚才的位置

首页和照片页加入了页面缓存。打开照片详情、切换到其他功能再返回时，原有浏览状态会被保留，减少重复滚动和重新加载；页面重新激活时又会主动获取最新数据，兼顾连续浏览与内容更新。

这项变化看起来不大，但对于拥有数万张照片、经常在多个页面间切换的用户，日常操作会轻松不少。

## 忘记密码：新增服务器验证码兜底

自托管环境中，邮件服务不一定随时可用，安全问题也可能被忘记。v0.8.0 在原有方式之外，新增了**服务器日志验证码**重置流程。

验证码只会出现在服务器日志中，不会直接返回浏览器；同时设置了 10 分钟有效期、60 秒重发间隔、失败次数限制和用后失效机制。只要仍能管理自己的服务器，就多保留了一条找回账户的路径。

## CLI 与 AI 自动化能力扩展

TrailSnap CLI 新增后台任务和工具箱命令。现在可以在命令行中查询任务进度、等待任务完成、取消或重试失败任务，也能启动重复照片扫描、相似照片查找、照片整理、批量重命名和文件名时间提取等操作。

这些能力尤其适合脚本、定时任务和 AI 助手调用。AI Agent 同时获得了文件夹上下文，可以理解目录结构并查询指定文件夹中的照片。命令行错误也支持结构化输出，自动化流程更容易判断成功与失败。

## 演示模式：更放心地开放在线体验

项目维护者现在可以通过 `DEMO_MODE=true` 启用演示模式。开启后，系统会限制会修改数据的操作，并隐藏密钥、存储路径等敏感配置；普通部署不启用该变量时不受影响。

这让公开演示站、团队试用环境和产品预览更容易控制风险，也省去了逐个页面处理写操作权限的麻烦。

## 稳定性与兼容性

- 修复 `uploads` 目录照片数量显示为 0 的问题。
- 修复照片颜色数据异常导致后台任务持续停留在处理中的问题。
- 整理文件夹视图工具栏，移除重复入口。
- 统一主要接口的成功响应结构，官方前端与 CLI 已同步适配。

需要特别提醒自行开发客户端或自动化脚本的用户：部分接口的业务数据现在位于 `data` 字段中，成功响应格式为 `{code: 0, msg: "success", data: ...}`，升级后请检查相关读取逻辑。

## 如何升级

**Docker Compose 部署**

```bash
git pull
docker compose pull
docker compose up -d
```

**源码部署**

```bash
git pull
cd package/server && uv sync
cd ../ai && uv sync --extra cpu
cd ../website && pnpm install && pnpm build
```

完整更新内容可查看 [GitHub Release v0.8.0](https://github.com/LC044/TrailSnap/releases/tag/v0.8.0)。
