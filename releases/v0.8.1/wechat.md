# 行影集 v0.8.1 发布：外部图库向导、全局通知与更稳定的 AI 助手

行影集 v0.8.1 正式发布。本次更新聚焦自托管相册最常见的三个使用环节：把已有照片目录接入系统、及时了解后台处理状态，以及在更大的图库和更长的对话中稳定使用 AI 助手。

我们也集中修复了重新安装、启动健康检查和照片上传链路中的问题，并扩充了覆盖前端、后端和 AI 服务的自动化测试，让日常升级与后续迭代更可靠。

## 外部图库向导：接入 NAS 和硬盘目录更简单

许多用户的照片已经按照年份、家庭成员或旅行地点整理在 NAS、移动硬盘和服务器目录中。以往接入外部图库时，需要同时理解主机路径、容器路径和扫描目录，配置门槛并不低。

v0.8.1 新增了**外部图库一键接入向导**。你可以在设置中选择目录，按照步骤完成路径映射和扫描配置，并直接确认接入结果。已有部署也可以继续追加新的照片目录，不必删除原环境或从头安装。

重新安装到同一目录时，安装脚本现在会复用原数据库密码，避免配置与已有数据不一致。管理员界面刷新后外部图库不显示的问题也已修复，目录管理状态会更加清晰。

## 全局通知中心：任务进度不再散落

照片扫描、缩略图生成、AI 识别等操作往往在后台持续一段时间。新版本加入了**全局通知中心**，桌面端通过铃铛入口集中展示后台任务和系统消息，并实时同步状态。

无论是在照片页、设置页还是工具箱中发起操作，都可以回到同一个入口查看处理进度与完成结果。后台定时任务也完成统一调度，并加入版本更新检查，方便及时了解新版本。

## AI 助手：长对话和复杂检索更稳定

当图库规模变大，或围绕同一批照片连续追问时，对话上下文会逐渐变长。v0.8.1 优化了 AI 助手的上下文整理与照片检索方式，让助手在保留关键信息的同时减少无关内容干扰。

图片向量请求也增加了超时保护。当 AI 服务暂时不可用或响应异常时，对话会及时结束等待并给出反馈，避免页面长时间卡住。演示模式现在同样支持 AI 助手，同时完善了示例照片补足、访问频率和上传限制，公开体验更完整。

## 安装与上传链路修复

本次更新修复了两类影响首次体验的问题。

安装健康检查现在固定使用本机 IPv4 地址，并延长合理等待时间，避免系统将 `localhost` 解析为 IPv6 或服务启动稍慢时误报失败。对于已经正常启动、却被安装脚本提示失败的情况，这项修复会带来直接改善。

照片上传方面，修复了上传完成后元数据请求返回 404、后续处理任务未派发的问题。新照片会继续进入元数据提取、缩略图和其他配置好的后台流程，无需手动补跑任务。

## 体验与质量保障

- 合并文件夹视图中的操作入口，让工具栏更简洁。
- 修复部分弹层主题色和 AI 助手悬浮按钮半隐藏效果。
- 统一前端、后端与 AI 服务测试工作流，并支持手动触发。
- 新增照片、位置、人物、搜索、工具箱、年度报告、设置和 AI 路由等多场景自动化测试。

这些测试不会改变页面上的功能，但能更早发现更新对常用流程的影响，为后续版本提供更扎实的质量保障。

## 如何升级

**Docker Compose 部署**

```bash
git pull
docker compose pull
docker compose up -d
```

**源码部署**

```bash
git pull
cd package/server && uv sync
cd ../ai && uv sync --extra cpu
cd ../website && pnpm install && pnpm build
```

本版本包含通知中心相关数据库迁移。通过项目的 `start.py` 或 Docker Compose 启动时会自动执行，无需手动修改数据库；升级前仍建议按日常维护习惯备份数据库。

完整更新内容可查看 [GitHub Release v0.8.1](https://github.com/LC044/TrailSnap/releases/tag/v0.8.1)。
