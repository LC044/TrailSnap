# TrailSnap Desktop（Tauri 2）

桌面应用使用 Tauri 2 管理 PyInstaller 打包的 FastAPI Sidecar。Vue 构建产物
直接内嵌到 WebView，Rust 首次分配并保存服务端口、启动后端、执行健康检查，并在退出
时清理后端进程树。桌面端使用本地 SQLite 数据库，无需安装 PostgreSQL。

## Windows 安装版与 ZIP

普通启动在后台准备网页与后端，不弹出迁移窗口；仅首次升级进入实际迁移阶段时显示独立的原生进度窗口，启动失败时显示恢复操作。已有 `instance.json` 的实例不再执行旧库发现与迁移，之前启动留下的进度不会触发窗口。首次升级显示旧文件检查、原照片基准、复制与完整校验、数据库升级、数据切换和启动验证等阶段；已知总量时显示实际进度，复制阶段显示包含校验的处理量与平均处理速度，未知总量时显示活动进度和耗时。重复点击三个启动入口只唤回当前迁移或主窗口，不重复复制；不同安装文件夹仍可独立使用。

检查、复制和可中断校验期间可点“稍后继续”，在文件处理安全点停止，旧库保留；关闭窗口在可中断阶段请求安全暂停，在数据库升级或切换阶段仅最小化，不强制结束写入。失败或暂停后可在原生窗口重试、查看日志或退出。未完成的复制会重新进行，不是按文件断点续传。暂停请求绑定本次启动，旧请求不会中止下次正常启动。

设置 → 照片与数据位置只展示并打开实际的“行影集文件夹”，不向普通用户展示内部数据子目录。搬迁时安全退出后移动整个文件夹，从新位置运行 `TrailSnap.exe` 并更新快捷方式。外部原照片仍需保留；高级配置了独立资料位置的实例会提示，移动程序文件夹不会搬走那些资料。

安装包安装完成或 ZIP 解压后，运行根目录 `TrailSnap.exe`（安装快捷方式也进入同一启动器）。首次启动会生成当前文件夹的
`instance.json` 和 `userdata/`；`app/<build-id>/` 只存程序版本。不同文件夹拥有
独立图库、配置、端口、浏览器数据、模型和认证密钥，可同时使用。移动文件夹前使用
设置页“安全退出”；换盘符或换电脑后，托管照片和任务路径从当前实例重新解析。
仅支持同平台、同架构且满足系统要求的电脑，外部图库引用需要另行携带或重新配置。

安装器暂时解压到根目录的 `server/` 在版本目录生成、重装恢复准备成功后清理，正式运行使用 `app/<build-id>/server/`，避免保留两份后端。清理前检查正式程序是否存在，并拒绝删除图库目录或含链接的资源目录；安装中断时保留临时资源供重装恢复。

覆盖安装和应用内更新默认自动清理旧程序：新版通过验证并且正式客户端启动就绪后，`app/` 只保留当前一个构建。首次启动新版前、更新中断或候选验证尚未完成时，暂时保留旧版用于失败回滚。成功清理后不再保留可直接切换的上一版程序，图库和 `userdata/backups/` 快照保留。清理前同步发行配置和实例指针，文件占用导致的未完成清理记录在 `maintenance/`，下次正常启动后重试；含图库、链接或无法识别的目录保留，不按版本号直接删除未知文件夹。

当前图库配置由实际程序目录的 `instance.json` 决定，默认使用同级 `userdata/`。首次启动在创建空库之前检查安装目录旁的旧 `data`、`%LOCALAPPDATA%/TrailSnap`、`%LOCALAPPDATA%/com.trailsnap.desktop` 和历史 `TrailSnap-desktop.json`。仅发现一个可确认的旧库时，自动复制到当前安装的 `userdata`，不要求另选文件夹；保留账号、认证密钥和历史连接端口。外部原照片继续使用原位置，不自动移动或删除。

自动迁移逐文件校验复制内容，仅为本次实际复制的照片记录内容基准，并在最终位置进行独立候选启动验证。未复制的外部原照片不读取、不计算哈希，也不会因外部照片被其他软件修改或磁盘离线而阻止升级。旧版迁移记录中的外部原照片也按此规则跳过；已复制照片丢失、损坏或引用越出新图库时仍停止验证。正式客户端的本地服务启动成功后才提交并清理旧版受管理数据；程序目录、外部原照片、浏览器缓存和未知的附属文件保留。旧库仍运行、空间不足、目标非空、多个来源或验证失败时，停止迁移并保留源；不创建替代空库。多个来源可在启动器原生对话框中选择包含 `data` 的旧目录，取消不会改动数据。

候选启动中的媒体校验结果按本次启动身份复用，并发请求和超时重试不会重复读取全图库；失败也保留本次结果，新一轮启动才重新尝试。普通程序更新的数据库与配置快照不复制原照片，因此不为其计算照片哈希。手动导入或备份只有勾选复制外部原照片时，才将这些外部文件纳入副本完整性校验。

事务保存在 `maintenance/automatic-upgrade.json`。复制中断后重做自己的暂存副本，发布中断后恢复配置并重新验证；验证失败可修复程序后重新启动。清理中断后按记录继续，仅删除本次已复制、源内容仍匹配的受管理文件。旧数据发生变化时停止清理，记录 `maintenance/automatic-upgrade-cleanup-error.json`，已验证的新图库仍可使用。已完成升级不再导入或重复验证。不要在迁移期间打开旧版或拔出磁盘。

安装器默认选择唯一已有安装位置，保留显式 `/D` 选择；多个已安装实例需要在向导中明确选择，静默模式必须指定 `/D`。同版本重装会检查实际程序文件并修复损坏、缺失或多余的程序资源，保留 `instance.json` 与 `userdata`。三个启动入口均由嵌入行影集图标的启动器提供。

**手动找回其他旧版本照片（高级操作，创建独立副本）**：

1. 完全退出旧版本，点击首次提示的“检查旧照片”，或进入 **设置 → 数据目录 → 找回旧版本照片**。
2. 选择检测到的旧目录，或手动选择包含 `data` 文件夹的那一级。以前更改过保存位置时，选择改后的目录。旧磁盘离线、配置损坏或数据库不可读时会说明原因；选择 `data` 子目录会提示正确的上一级，不创建空库。
3. 选择来源后会自动检查，请核对来源和照片数。检查只读，尚未导入；失败时可纠正位置或点击 **重新检查图库**。
4. 默认勾选 **同时备份其他文件夹中的原照片**；取消时仍依赖原磁盘。自定义存储的原图、缩略图、分块和配置一起复制，保持媒体读取与继续上传所需的目录结构。
5. 选择新的空文件夹（例如 `D:\行影集-旧照片`），新位置也不能在外部照片目录内部，避免将副本再次纳入扫描或复制。界面自动检查并显示含程序、外部原照片和数据库快照余量的空间需求。更改来源、目标或外部照片选项后自动重新检查。
6. 点击 **导入并使用这些照片**。复制期间显示阶段及文件进度；原图库保留，不合并当前图库。当前图库已有照片时会额外提醒。
7. 新副本发布到最终位置后，再核对来源照片的读取基准并进行真实启动验证，通过后才切换。原启动入口保存目标位置和图库身份，之后原快捷方式也打开导入后的图库，正常更新不重复提示导入。手机需重新连接、登录。导入前的图库始终保留返回入口，即使没有照片，也能在高级信息中切换回来访问票夹和设置；两边不自动合并。

目标磁盘离线或目标身份改变时，原入口明确报错，不静默打开旧库或空库。移动导入后的整个文件夹后，可从新位置运行 `TrailSnap.exe`，也可从原入口按提示重新选择搬迁后的文件夹；不会自动扫描磁盘或绑定其他图库。

**备份当前图库**：保存独立副本，完成后重启并继续使用当前图库，不改变启动关联。副本不会自动同步；完整备份需勾选复制其他位置的原照片。

**失败恢复**：目录预检失败可直接纠正。等待后台任务超过 30 秒会返回说明并提供“继续等待”，后台仍安全收尾，不开始复制、不强杀写入任务；此时也拒绝直接重启。任务结束后可重启恢复使用，重新处理导入或备份。其他排空、安全退出或复制失败提供“重启并恢复使用”。操作记录先于服务停止保存；中断后启动会提示继续处理。已发布副本可“重新验证并继续”，不重复复制；未完成的临时文件可清理后从头重试。清理仅删除本操作标识对应、带匹配标记的临时目录，原图库和已发布副本始终保留。复制未完成时不支持按文件断点续传。

**新用户与备份**：设置中的“照片与数据位置”默认展示保存位置和备份入口；发现尚未处理的旧库才展开找回流程，未完成的复制优先展示恢复。选定来源和新位置后自动检查图库与空间。导入和备份默认勾选复制外部原照片；取消勾选时，副本仍依赖原磁盘，不能当作外部原照片的完整备份。导入后持续提示保留外部原照片，备份完成记录也说明是否额外复制了外部原照片。不要仅凭照片数量或“备份完成”就删除原照片，先打开副本核对。

安装覆盖导致旧 `data` 与新 `userdata` 共存时，复制排除新实例的数据、锁、浏览器缓存和程序目录。导入后仍将安装包覆盖至原安装位置时，新程序会转交实际图库目录，由该目录的启动器执行正常的备份、候选验证和失败回滚；较低版本不会自动降级。

两个发行格式都使用独立的 `portable-latest.json` 和签名 ZIP 更新。安全停止任务后备份数据库和配置，再验证候选程序；验证期间不开放写入。失败或断电后恢复旧程序及升级前快照；已提交的升级不会自动恢复旧快照。设置页显示失败原因与备份位置，失败版本不会自动重复下载，可手动重试。安装包覆盖安装同样通过启动器验证新版本。

移动前安全退出，并携带整个安装目录（包括 `instance.json`、`userdata/`、`app/`）。不要只移动 exe。配置损坏、数据盘不可用或数据库丢失会显示错误，不会自动建立空库替代。启动失败界面可以打开数据/日志目录并重启；修复前请保留原目录和备份。卸载仅删除程序，保留图库、配置和升级快照；多个安装目录的卸载项和快捷方式相互独立。

如果导入后又搬迁整个图库，原快捷方式找不到目标时会提供 Windows 原生目录选择入口。选择搬迁后的行影集根文件夹（不是 userdata 或 data），启动器仅接受与原关联具有相同实例身份、包含程序入口及图库数据的目录，并拒绝循环关联。取消或选错不会改写原关联，也不会新建空库。磁盘只是暂时断开时，连接磁盘后重新打开即可。

构建便携包：

```powershell
pwsh .\package\desktop\scripts\build-portable.ps1
# 已完成桌面和后端构建时仅打包
pwsh .\package\desktop\scripts\build-portable.ps1 -SkipBuild
```

标准包使用电脑已有的 WebView2。要构建离线完整包，可用 `-WebViewRuntime <Fixed Version目录>`
附带含 `msedgewebview2.exe` 的同架构运行时；其后续更新包也应包含对应运行时。
`userdata/` 不应放在网络共享上供多台电脑同时写入。配置或磁盘不可用时会明确报错，
不会回落到新的 C 盘空图库。

Docker 用户无需修改挂载、环境变量或目录。新的存储引用字段默认为 NULL，旧绝对路径保持
原有读写与查询行为；`start.py` 沿用原来的 PostgreSQL/SQLite Alembic 升级入口。
便携路径转换仅在桌面便携模式下执行，不在 Docker 普通升级中搬动或重写照片。

## Windows 本地构建

需要预先安装 Node.js/pnpm、Python/uv、Rust stable，以及 Tauri 对应平台的系统依赖。
在仓库根目录执行：

```powershell
pwsh .\scripts\build-windows-installer.ps1
```

构建脚本会检查必要工具，并依次完成依赖安装、Vue 构建、PyInstaller Server 与 AI 分别打包、
Sidecar 暂存和 Tauri NSIS 打包。重复构建时可以用 `-SkipInstall` 跳过依赖安装，
用 `-OpenOutput` 在成功后打开产物目录：

```powershell
pwsh .\scripts\build-windows-installer.ps1 -SkipInstall -OpenOutput
```

Windows NSIS 安装包位于：

```text
package/desktop/src-tauri/target/release/bundle/nsis/
```

首次启动会在安装目录的 `userdata/data/trailsnap.sqlite` 创建数据库、执行独立的
SQLite Alembic 迁移并创建本地管理员。界面启动时会自动换取标准 JWT，因此看起来无需登录，
后端的用户隔离与鉴权行为仍与服务器端一致。运行日志位于安装目录的 `userdata/logs` 目录。

GitHub Actions 在 Windows、macOS 和 Linux 原生 runner 上分别打包 PyInstaller Sidecar 与
Tauri 安装包，产出 NSIS、DMG、AppImage 和 DEB。正式标签构建还会使用仓库 Secret
`TAURI_SIGNING_PRIVATE_KEY` 为更新包签名并发布 `latest.json`；客户端启动后自动检查、
后台下载并验签，下载完成后可一键安装。

桌面 CSP 单独通过 `style-src-attr 'unsafe-inline'` 允许元素的内联样式。
Tauri 会为入口 HTML 的 `<style>` 注入 hash/nonce，此时 `style-src` 中的
`'unsafe-inline'` 不再允许元素的 `style` 属性。位置相册的天地图照片标记、
轨迹缩略图和数量/日期标签依赖这些属性；缺少独立指令会导致照片尺寸和叠加布局失效。
此配置保留 Tauri 对脚本与样式表的 CSP 处理，修改后需要重新构建桌面应用才能生效。

3D 足迹使用 Cesium：`worker-src 'self' blob:` 允许其本地计算 Worker 与
跨来源 Worker 的 Blob 引导脚本；当前 Cesium 的 Knockout 和 WebAssembly
依赖需要 `script-src` 中的 `'unsafe-eval'`。`connect-src` 仅额外允许
`https://elevation3d.arcgis.com`，用于可选的 ArcGIS 三维地形。
调整 CSP 时需同时验证内置 Natural Earth 底图、天地图影像与地形开关，
避免只显示城市和连线而不显示地球底图。

天地图 SDK 及其子脚本、样式表由本地 Server 的 `/api/system/map-proxy/`
代理返回。桌面页面与 Server 不同源，Server 端口还会动态分配，因此
`script-src` 与 `style-src` 均需允许 `http://127.0.0.1:*`。
仅在 `connect-src` 中允许本地请求不会放行 `<script>` 或 `<link rel="stylesheet">`，
缺少对应指令时会出现 `Failed to load map script`。

安装与卸载前，NSIS hook 会按安装目录检查桌面程序、Server、AI 与 llama-server 进程。
发现仍在运行就停止安装或卸载，不关闭窗口、不强杀后台写入。请先在“设置 → 照片与数据位置”
中选择“安全退出行影集”，等待上传和任务结束后重试；旧版没有该按钮时，请先等待任务结束再退出。
检查只匹配所选安装目录，不影响另一个目录中的行影集。窗口已关闭但后台仍在收尾时，也需等待进程退出。

## 修改数据目录

默认数据随安装目录存放在 `userdata/`。搬迁时安全退出后移动整个实例目录，重新运行该目录的 `TrailSnap.exe`。设置 → 数据目录可预检、复制当前图库或显式指定的旧图库，目标必须为空，不能与源目录或当前安装目录互相包含。源目录保留；复制失败时界面提供原因、目录入口和重新启动操作。符号链接、目录联接、不足的磁盘空间及不可用外部照片需要先处理。

高级用户可在停机并备份 `instance.json` 后修改其中的 `dataRoot`；相对路径从当前安装目录解析，绝对路径会继续依赖指定磁盘，因此不会随程序目录搬迁。不要让两个实例同时写同一数据目录；启动器会加锁阻止此操作。

## 手机连接

后端监听局域网，首次分配的端口保存在安装目录的 `instance.json`，以后重启和迁移沿用。
默认自动模式优先复用上次成功端口；端口被占用或系统拒绝访问时自动分配新端口，启动后提示手机重新扫码。旧安装同样支持自动恢复。
设置 → 连接手机 App 可选择自动或自定义端口（1–65535），保存后等待上传和后台任务结束并重启。
自定义端口不可用时，启动失败页可直接修改端口或切回自动模式，无需先进入程序。
只有后端通过健康与身份检查后才保存自动分配的端口。设置 → 连接手机 App 提供实际局域网地址和二维码；
手机保存地址后可继续连接并备份照片。电脑需保持运行，系统防火墙需允许专用网络访问。
电脑 IP 由路由器分配，改变时可重新扫码或通过手机的 mDNS 自动查找；建议配置 DHCP 地址保留。
连接二维码只包含地址，手机仍需使用已有账户登录。首次使用可在桌面“用户管理”中为
`desktop-admin` 重置密码，手机使用此账号即可备份到同一照片库。
照片查看器“更多”菜单支持在文件管理器中定位原文件。

## 内置 AI 与整体更新

桌面安装包和便携包均包含 Server 与 CPU AI。两者分别用 PyInstaller 构建，
各自保留完整依赖，不共享 Python 模块；用户只安装和更新行影集。

AI Gateway 从当前版本的 `ai/` 启动内置程序，首次调用时按需启动，空闲十分钟后退出。
运行日志保存在数据目录的 `logs/ai.log` 和 `logs/ai.err.log`。
模型仍按需下载，在“设置 → AI 模型管理”查看；模型位于持久数据目录，更新不重复下载。
本地大模型所需 llama.cpp 由应用在使用时自动准备并校验，无需服务地址或手动连通性检测。

构建顺序为前端、独立 Server/AI、完整应用打包和签名。`validate_components.py`
在打包前检查两组件入口与版本。Windows 安装器使用 LZMA；安装版和 ZIP 均把 AI 放入
`app/<build-id>/ai/`，完整更新 ZIP 包含两组件。macOS/Linux 同样包含完整内置 AI。

更新先验证签名与完整文件，再安全排空任务、响应和模型下载。候选阶段实际验证内置 AI
及 Server，任一失败整体回滚。成功启动后清理旧构建，保留照片、模型、配置和备份。
升级会清除历史“等待安装/更新 AI 扩展”状态，不改变用户暂停；旧扩展只在新版成功后
按受管理目录清理，含模型、图库、链接或未知内容的目录保留。历史 Release 附件保留。

独立 Docker 部署仍通过原有 AI 服务配置连接，不受桌面打包调整影响。

## 当前 SQLite 边界

SQLite 首轮覆盖用户/认证、照片、相册、标签、元数据、任务和向量存储；PostgreSQL 专属统计
查询需要逐项补充方言实现。该边界不影响服务端完整版的远程 AI 配置，也不改变已有 AI 模型
与数据库数据。
