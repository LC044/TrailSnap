### 一、 本地化与语言提示 (Localization)
- 现状 ：Windows 的 install.ps1 几乎是全英文提示，Linux/Mac 的 install.sh 仅有少量中英双语。
- 优化建议 ：改成中文的控制台输出。小白用户在看到大段英文（尤其是带有 [WARN] 或 [ERROR] 的红黄字）时容易产生恐慌。
- Windows下终端默认是gbk编码，但是中文字符在控制台显示时会显示为乱码，需要确保不乱码
### 二、 成功后的“局域网 IP”展示 (LAN IP Display)
- 现状 ：安装成功后的 Banner 只展示了 http://localhost:8082 。
- 优化建议 ：小白用户搭建相册最大的诉求之一是 在手机上查看 。可以在脚本最后获取本机的局域网 IPv4 地址（如 192.168.1.100 ），并在成功界面直接打印出：
  - 💻 本机访问: http://localhost:8082
  - 📱 手机访问: http://192.168.1.100:8082 (需连接同一 Wi-Fi)
### 三、 简化多目录输入的交互 (Simplify Directory Input)
- 现状 ：当用户有多个照片文件夹时，脚本要求使用“逗号分隔”输入（comma-separated for multiple）。
- 优化建议 ：对于小白来说，“逗号分隔”的格式容易输错（中英文逗号、路径自带空格等）。可以改成 向导式的循环输入 ：
  1. 提示：“请输入您的照片文件夹路径：”
  2. 校验成功后，提示：“已添加。是否还要添加其他照片文件夹？(y/N)”
  3. 如果选 y 则继续要求输入，选 N 则进入下一步。
### 四、 硬件资源“预检” (Hardware Pre-flight Check)
- 现状 ：脚本直接开始拉取 Docker 镜像。
- 优化建议 ：TrailSnap 包含 AI 镜像、数据库和后端服务，下载解压后可能会占用几 GB 甚至上十 GB 的空间。
  - 建议在 拉取镜像前 检测安装目录所在磁盘的 剩余空间 。如果低于 10GB 或 15GB，给出黄字警告，防止下载到一半磁盘爆满导致各种奇怪的 Docker 报错。
  - （可选）检测系统内存，低于 4GB 时提示运行 AI 服务可能会卡顿。
### 五、 中断后的“断点续传”引导 (Interruption Recovery)
- 现状 ：在 Windows 上，如果没有开启 WSL2，脚本会执行安装并提示用户“需要重启电脑，请重启后重新运行本脚本”，然后退出。
- 优化建议 ：小白用户重启电脑后，经常会找不到之前的脚本在哪里，或者忘记要重新运行。
  - 极客做法 ：在用户的桌面自动创建一个临时的 继续安装 TrailSnap.bat 快捷方式，重启后双击就能接着装，装完自动删除。
  - 简单做法 ：用极其醒目的高亮边框框住提示语，强调：“⚠️ 注意：重启电脑后，请再次找到本文件夹，双击运行 install.ps1 以继续安装！ ”
### 六、 Mac 下 Docker 安装的降级方案 (Mac Docker Fallback)
- 现状 ： install.sh 中针对 Mac 系统使用 brew install --cask docker ，如果没有 Homebrew，脚本会报错退出并给个官网链接。
- 优化建议 ：国内很多普通 Mac 用户并没有安装 Homebrew。如果没有检测到 brew ，可以通过脚本直接调用浏览器打开 Docker 下载链接：
  - 执行 open https://desktop.docker.com/mac/main/amd64/Docker.dmg （或者直接 curl 下载），省去小白去全英文官网找下载按钮的麻烦。
### 七、 端口冲突的“静默处理” (Auto-resolve Ports)
- 现状 ：如果端口被占用，脚本会提示一个推荐的新端口，并要求用户确认。
- 优化建议 ：小白其实根本不关心后端的 API 跑在 8800 还是 8801。如果检测到端口被占用，只需要 直接分配一个可用端口 ，并打印一句 [INFO] 端口 8800 被占用，已自动为您分配新端口 8805 ，无需用户干预和按回车，进一步降低决策降级决策成本。

任务调度优化：

现在package\server\app\service\task_worker.py任务并发度是固定的，但是用户的配置不同，需要根据用户的配置来调整任务并发度。例如高性能设备使用高并发度，低性能设备使用低并发度。

package\server\app\core\system_config.py 系统设置新增一个任务并发度的配置项，有三档：低、中、高。

默认值根据用户的配置来调整。
如果用户的配置是高性能设备，就设置为高并发度，否则设置为中并发度。
配置计算使用：CPU核心数、内存大小两个维度。
- 高性能设备：CPU核心数大于等于8，内存大小大于等于16GB
- 中性能设备：CPU核心数大于等于4，内存大小大于等于8GB
- 低性能设备：CPU核心数小于4，内存大小小于8GB

现在package\server\app\service\task_worker.py任务并发度设置为中等。
用户可以在设置中调整该参数，并且在调整的时候提醒用户如果调整为高并发度比默认值高，可能会导致系统性能下降。
