# 飞牛 NAS 安装与使用

飞牛 x86 NAS 可以通过 `.fpk` 安装包使用行影集，无需手动编辑 Docker 配置。已在 fnOS V1.2.0800 上验证，当前安装包使用 CPU，不需要独立显卡。

## 下载和安装

1. 前往[下载页面的 NAS 选项](/download#nas)，下载飞牛 `.fpk` 安装包。
2. 打开飞牛「应用中心 → 手动安装 → 从电脑上传」，选择安装包。
3. 确认应用来源后，填写安装设置：

| 项目 | 怎么填写 |
| --- | --- |
| 端口 | 默认 `3180`，如已被占用，请换一个端口 |
| 照片目录（可自定义） | 预填 `trailsnap/photos`，对应「应用文件 → trailsnap → photos」；可改为已有照片文件夹的完整路径 |
| 照片目录访问权限 | 默认只读，也可选择读写；NAS 文件权限仍须允许相应操作 |
| 用户数据目录（可自定义） | 预填 `trailsnap/data`，对应「应用文件 → trailsnap → data」；可改为其他独立空文件夹的完整路径 |

默认目录由飞牛在安装存储空间中创建，例如 `/vol2/@appshare/trailsnap/data` 和 `/vol2/@appshare/trailsnap/photos`，无需手动填写卷号。安装时可以覆盖默认目录。

自定义照片目录示例：`/vol1/1000/Photos`；用户数据目录示例：`/vol1/1000/TrailSnap`。这两个目录需要分开，不能互相包含。示例路径不是所有 NAS 的默认路径，请使用飞牛文件管理中显示的实际路径。

![飞牛安装设置](/images/fnos-install.png)

4. 按向导完成安装。首次安装需要联网下载运行所需的镜像，等待应用显示可以打开。
5. 点击「打开」，创建自己的行影集管理员账号。其他设备也可以访问 `http://NAS地址:端口`，例如 `http://NAS地址:3180`。

如果最新 Release 暂时没有 `.fpk` 附件，可以使用[飞牛 Docker 部署方式](/docs/guide/docker/fnos)。不要下载其他系统的安装包代替。

## 接入已有照片

打开行影集「设置 → 照片文件夹」，点击「重新检测」，按照片文件夹名称勾选目录，然后点击「添加选中的图库并扫描」。照片会陆续出现在图库中。

照片默认按只读方式接入，不会自动移动到用户数据目录。选择读写后，可按应用功能上传、移动或删除原图；实际操作仍受 NAS 文件权限限制。

## 添加、授权和移除照片文件夹

1. 飞牛「应用中心 → 已安装 → 行影集 → 应用设置 → 运行设置 → 编辑」。
2. 在「新增照片目录」填写完整 NAS 路径，多个目录用英文分号 `;` 分隔，例如 `/vol1/1000/旅行;/vol2/1000/家庭`；在「本次新增目录权限」选择本批次的只读或读写，点击「保存并重启」。
3. 打开行影集「设置 → 照片文件夹 → 重新检测」，勾选新文件夹，点击「添加选中的图库并扫描」。

已有目录直接显示 NAS 路径和当前权限，可切换只读、读写或选择「移除」。移除只取消挂载，保留原文件；如果也要清理照片索引，请先在行影集「照片文件夹」移除对应目录。NAS 文件 ACL 仍需允许应用读写。

新增目录仅重名时添加 `(2)`、`(3)`；移除后再次接入同一路径会复用原映射。旧版「已有照片」和哈希映射继续保留，避免索引失效。原生「访问权限」授权仍可自动接入目录；通过运行设置调整后，以运行设置的选择为准。

## 查看上传的原图

行影集上传的照片可以在「照片」页面查看。在飞牛文件管理中，打开「应用文件 → trailsnap → data」（如自定义过，则打开安装时填写的用户数据目录），再进入：

```text
data/users/<用户ID>/uploads
```

原图按年月保存在其中。不要手动删除或改动用户数据目录里的数据库、配置和缩略图文件；备份时请同时备份整个用户数据目录和已有照片目录。

## 更新应用

当前通过 GitHub Release 提供安装包；应用市场上架后，可从飞牛应用中心获取已审核的更新。

手动更新时，下载新版 `.fpk`，在飞牛「应用中心 → 手动安装」上传并更新即可，**不需要先卸载**。更新会保留原端口、用户数据目录和已接入的图库，升级前会备份数据库与配置。完成后重新打开行影集，确认能登录并查看照片。

如果使用早期 `0.19.1-2` 适配包，或更新时提示备份、目录权限错误，请先保留原应用和数据，通过[反馈平台](https://feedback.trailsnap.cn/)获取迁移帮助，不要卸载重装来绕过错误。

卸载应用不会主动清理选定的用户数据目录和外部照片，但这不能替代独立备份。恢复旧版本前需要核对数据库兼容性，不要直接用旧包覆盖新数据库。
