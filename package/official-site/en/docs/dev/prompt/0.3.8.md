## Similar Photo Cleanup Feature

### Feature Description

Based on vector similarity in the `image_vectors` table, cluster by similarity — similar photos form a group. Users can view all photo groups or view photos within a specific group. They can choose to delete photos in a group (keeping one), or delete photos across all groups (keeping one per group).

### Frontend Interface

1. `package\website\src\layouts\NavBar.vue` — add a "Toolbox" sub-item under the navigation bar's "More" menu. Clicking it navigates to the Toolbox interface.
2. Move the "Low Score Cleanup" feature from `package\website\src\views\HomePage.vue` to the Toolbox interface.
3. The Toolbox interface adds a "Similar Photo Cleanup" feature. Clicking it navigates to the similar photo cleanup interface.
4. The similar photo cleanup interface displays all photos in groups. Groups are laid out vertically; photos within a group are displayed horizontally (including the photo and filename), with scroll buttons on the left and right for horizontal scrolling.
5. Clicking a photo views its details. Previous/next buttons only switch within the current group.
6. Each group has a select-all button. Clicking it selects all photos in the group (keeping the first one).
7. A "Delete All Groups" button in the top-right corner. Clicking it deletes photos in all groups (keeping the first one in each group).
8. If there are many groups, pay attention to display performance.
9. Empty state: when there are no similar photo groups, display "No similar photo groups yet" with a hint "You can adjust the similarity threshold to re-cluster"; when all photos in a group are deleted, automatically remove that group.

### Similar Photo Cleanup Feature Optimization

Currently, similarity clustering results are stored in the `tasks` table, which is inconvenient for viewing and management. The clustering results need to be stored in two new database tables: a clusters table (`image_clusters`) and a photo-cluster association table (`photo_clusters`).

Clustering results are stored in two new database tables: a clusters table (`image_clusters`) and a photo-cluster association table (`photo_clusters`).

Clusters table (`image_clusters`):
- cluster_id: Cluster ID, uniquely identifies a cluster group
- task_id: Task ID, references the task ID in the tasks table
- cluster_type: Cluster type, string type, describes the type of the cluster group (similarity clustering, md5 identical clustering)
- count: Number of photos in the cluster group, integer type
- created_at: Creation time, records when the cluster group was created

Photo-cluster association table (`photo_clusters`):
- id: Primary key, auto-increment integer
- photo_id: Photo ID
- cluster_id: Cluster ID, references the cluster ID in the image_clusters table
- created_at: Creation time, records when the photo was associated with the cluster group

When deleting a photo, delete the corresponding record in the photo-cluster association table and update the `count` field in the clusters table. When `count` is 1 or 0, delete that cluster group.

The frontend views clustering results by task ID. Multiple clustering tasks can exist, each with a unique task ID.
The progress of a specific clustering task can be viewed.
