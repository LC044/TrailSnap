## Login and Permission Management

### I. Core Objectives

- Verify user identity legitimacy; only authorized users can access the photo album application.
- After login, associate user-specific data (e.g., personal albums, favorites, permission settings) to achieve multi-user data isolation.

### II. Basic Login Module

#### 2.1 Login Entry and Form

- The application displays the login page by default after startup, with clear "Username" and "Password" input fields, as well as "Login", "Forgot Password", and "Register" (optional) buttons.
- Input fields support basic validation: username must not be empty, password length >= 6 characters. Real-time error prompts on invalid input (e.g., "Password must be at least 6 characters").
- Adapt to multi-device scenarios (web, mobile, desktop) with responsive login form layout.

#### 2.2 Login Verification Logic

- Local validation: first validate the username/password format (to reduce invalid requests), then send a verification request to the backend database.
- Identity matching: after successful verification, return the user's unique identifier, username, and user role (regular user / administrator).
- Session management: after successful login, generate a local session (e.g., Cookie, Token). The session validity period is configurable (default 7 days). If the session has not expired, the user does not need to log in again when reopening the app.
- Support "Remember Password" (optional): when checked, the username and password are encrypted and stored locally, auto-filled on next launch.
- Support "Auto Login" (optional): on top of "Remember Password", the user is automatically logged in on next app launch.

### III. User Identity Differentiation and Data Isolation

- After login, load user-specific data based on the token: each user can only view/edit their own uploaded albums, favorited photos, and custom album categories.
- Administrator role (special user): can additionally view all users' account information and storage usage, and can add/delete regular user accounts.
- Data isolation rules: photos uploaded by a user are by default visible only to themselves. Users can configure "Shared Albums" (visible to specified users) or "Public Albums" (visible without login).
- Configuration isolation: each user's configuration files (e.g., basic settings, preferences, external galleries) are by default visible only to that user.

### IV. Security

- Password security: passwords stored in the database must be encrypted with an irreversible algorithm (e.g., bcrypt, Argon2). Plaintext storage is prohibited.
- Login restriction: after 5 consecutive incorrect password attempts, lock the account for 10 minutes (configurable), and display "Account locked, please try again in 10 minutes."
- Session security: the session Token is stored locally only and is immediately destroyed on logout.
- Brute-force protection: log login IPs and attempt counts. Temporarily ban IPs with abnormal login frequency (e.g., 10+ attempts within 1 minute).

### V. Error Handling and User Prompts

- Login failure prompts: distinguish between "Account does not exist", "Incorrect password", "Account locked", "Session expired, please log in again" — avoid generic "Login failed" messages.
- Network/database errors: when the database is unavailable, display "Service temporarily unavailable, please check service status."
- Logout: provide a clear "Logout" button. After clicking, destroy the session, clear the local cache, and return to the login page.
- Forgot password: support local reset (administrators can reset regular users' passwords; regular users can reset via security questions or email).

Note: Currently only login is implemented; there is no registration or password reset functionality.
