## Login Page Design

### 1. Design Theme

A fun, interactive login interface that enhances the login experience through cartoon character interactions with user actions.

### 2. Layout

On mobile, only the right area is displayed.

1. **Left Area**:
   - Contains 4 geometric cartoon characters:
     - A tall purple rectangle character with simple eye expressions
     - A medium black rectangle character with eye expressions
     - An orange semicircle character with eye and mouth expressions
     - A yellow semicircle character with eye and mouth expressions
   - The background is light gray; characters are layered with a flat cartoon style.
2. **Right Area**:
   - White background with login form elements:
     - Title: "Login TrailSnap" — clean, modern font, large size
     - Input fields: username and password inputs with clean styling and focus state animations
     - Options: "Remember me" checkbox, "Forgot password" link
     - Action button: "Login" button (prominently displayed)

### 3. Animation Design

- When the user moves the mouse, the cartoon characters on the left look toward the mouse position.
- When the user clicks the username input, the cartoon characters shift their gaze toward the input field.
- When the user types in the password field, the cartoon characters look away to the left (not peeking at the password).
- When a button is clicked, the nearby cartoon character performs a small celebration action (e.g., a little jump).

### 4. Color Specification

- Neutral colors: light gray (#E5E7EB), white (#FFFFFF), black (#111827)
- Character colors: purple (#6366F1), black (#1E293B), orange (#F97316), yellow (#FACC15)

#### Refinements

1. The purple and black characters should be taller; the purple one should be the tallest and widest.
2. When an input field is focused, the cartoon characters on the left deform slightly, leaning forward as if peeking.
3. When an incorrect password is entered, the cartoon characters display a mocking expression.

Add an entry animation for the cartoon characters: when the login page loads, the characters drop in one by one, bounce on the ground with a springy effect, creating a dynamic entrance.

## Similar Photo Cleanup Feature

### Feature Description

Based on the vector similarity in the `image_vectors` table, cluster photos by similarity. Similar photos form a group. Users can view all photo groups or view photos within a specific group. They can choose to delete photos within a group (keeping one) or delete photos across all groups (keeping one per group).

### Frontend Interface

1. In `package/website/src/layouts/NavBar.vue`, add a "Toolbox" submenu under the "More" navigation item. Clicking it navigates to the toolbox page.
2. Move the "Low-score Cleanup" feature from `package/website/src/views/HomePage.vue` to the toolbox page.
3. Add a "Similar Photo Cleanup" feature in the toolbox page. Clicking it navigates to the similar photo cleanup page.
4. The similar photo cleanup page displays all photo groups in a vertical layout. Photos within each group are displayed horizontally (including the photo and filename) with left/right scroll buttons for horizontal scrolling.
5. Clicking a photo shows its details. The previous/next buttons only switch within the current group.
6. Each group has a "Select All" button that selects all photos in the group (keeping the first one).
7. A "Delete All Groups" button in the top-right corner deletes photos across all groups (keeping the first photo in each group).
8. If there are many groups, pay attention to display performance.
9. Empty state: when there are no similar photo groups, display "No similar photo groups" and suggest "Adjust the similarity threshold to re-cluster." When all photos in a group are deleted, automatically remove that group.
10. Loading/error state: show a loading animation during clustering (e.g., "Computing similar photo groups, please wait..."). On API failure, show an error message (e.g., "Failed to load similar photo groups, please retry") with a "Retry" button.
11. Operation feedback: after deletion, show a notification (e.g., "Successfully deleted X similar photos"). Scroll button interaction: disable the left/right scroll button when photos are scrolled to the leftmost/rightmost position (avoid invalid clicks).
12. Responsive adaptation: add mobile adaptation rules (e.g., switch group photos to vertical layout on mobile, replace scroll buttons with swipe gestures). On small screens, photo filenames should wrap or truncate (avoid overflowing the container).

### Backend API

1. Add a new API that returns all photo groups clustered by similarity. The clustering similarity threshold should be set to an appropriate value.
2. Within each group, sort photos by the score from the `image_descriptions` table (if available), with higher scores first. If no score is available, sort by time.

### Feature Optimization

1. The backend should return photos using the `export interface Photo` interface format.
2. The similarity clustering operation is time-consuming and should be handled as a background task. The frontend polls an API to get clustering results.
3. Persist clustering results to the database; update the database after each clustering completes.
4. The frontend can create a new similarity clustering task or view completed tasks.
5. The frontend can view the progress of a clustering task, cancel an in-progress task, and view grouped results after clustering completes.
6. When there are many photos (tens of thousands), the clustering operation may take a long time. The frontend should display a progress bar and prompt the user to wait.
7. Analyze whether the clustering algorithm can be optimized to reduce memory usage.

### Similar Photo Cleanup Feature Optimization

The similarity clustering results are currently stored in the `tasks` table, which is inconvenient for viewing and management. The clustering results should be stored in two new database tables: a cluster table (`image_clusters`) and a photo-cluster association table (`photo_clusters`).

**Cluster table (`image_clusters`):**
- `cluster_id`: Cluster ID, uniquely identifies a cluster group
- `task_id`: Task ID, references the task ID in the `tasks` table
- `cluster_type`: Cluster type, string, describes the type of the cluster group (similarity clustering, MD5-duplicate clustering)
- `count`: Number of photos in the cluster group (integer)
- `created_at`: Creation time

**Photo-cluster association table (`photo_clusters`):**
- `id`: Primary key, auto-increment integer
- `photo_id`: Photo ID
- `cluster_id`: Cluster ID, references `cluster_id` in the `image_clusters` table
- `created_at`: Creation time

When deleting a photo, the corresponding record in the `photo_clusters` table must be deleted, and the `count` field in the `image_clusters` table must be updated. When `count` reaches 1 or 0, the cluster group must be deleted.

The frontend can view clustering results by task ID. There can be multiple clustering tasks, each with a unique task ID. The progress of a specific clustering task can be viewed.
