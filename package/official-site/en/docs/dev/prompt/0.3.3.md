The previous logic treated a tag with an empty `owner_id` in the `photo_tags` table as a public classification shared by all users. After adding the `cover_id` field, covers would cause permission errors. Now, public tags need to be removed and a new tag created for each user.

Modify the database migration script `package\server\alembic\versions\b21a07c0b227_0023_add_cover_id_to_tag.py`:
1. Delete all tags with no associated photos and `owner_id` is null.
2. Query all tags where `owner_id` is null, find the corresponding records in the `photo_tag_relations` table, group by the photo's `owner_id`, create a new tag for each `owner_id` (with that `owner_id`, the same `tag_name`, and the first photo as `cover_id`), then update the `tag_id` field in `photo_tag_relations` to the new tag's ID.
3. Delete all tags where `owner_id` is null.
4. Commit the transaction.
