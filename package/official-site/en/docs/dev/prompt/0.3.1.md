## Scheduled Task Feature with Advanced Configuration

Implement a scheduled task feature with 3 modes:

1. **Off**: No scheduled tasks are executed.
2. **Interval Loop**: Execute tasks at a fixed interval (e.g., every N hours/days).
3. **Weekly Custom**: Select specific days of the week and times to execute tasks.

### Weekly Custom Scheduling

- Provide a day-of-week selector (multi-select: Monday through Sunday).
- Provide a time picker for selecting the execution time on each selected day.
- Multiple time slots can be configured per day.
- The schedule configuration is stored in the system configuration and persists across restarts.

### System Configuration

- Scheduled task settings are managed under System Configuration, separate from user-level settings.
- The scheduler runs as a background process and checks for due tasks at regular intervals.
- When a scheduled task triggers, it creates a new task entry in the task queue and the worker processes it normally.
- The user can view the last execution time and next scheduled execution time for each task.

## Recycle Bin Feature

Implement a soft-delete recycle bin for photos:

1. When a user deletes a photo, it is not permanently removed but moved to the recycle bin (soft delete with a `deleted_at` timestamp).
2. Photos in the recycle bin are hidden from all normal views (albums, search, timeline, etc.).
3. The user can access the recycle bin to:
   - View all deleted photos.
   - Restore individual photos or batch-restore photos back to their original location.
   - Permanently delete individual photos or batch-delete photos (hard delete, cannot be recovered).
   - "Empty Recycle Bin" to permanently delete all photos in the recycle bin.
4. Auto-cleanup: photos in the recycle bin are automatically permanently deleted after 7 days (configurable via system configuration).
5. The auto-cleanup runs as a scheduled task that checks the recycle bin periodically.
6. When restoring a photo, if the original album no longer exists, the photo is restored to the default album.

### System Configuration

- `recycle_bin_enabled`: Whether the recycle bin feature is enabled (default: `True`).
- `recycle_bin_retention_days`: Number of days to keep deleted photos before auto-cleanup (default: `7`).
- `recycle_bin_auto_cleanup`: Whether auto-cleanup is enabled (default: `True`).

## Login and Permission Management

### Core Objectives

- Verify user identity legitimacy; only authorized users can access the photo album application.
- After login, associate user-specific data (e.g., personal albums, favorites, permission settings) to achieve multi-user data isolation.

### Basic Login Module

- The application displays the login page by default after startup, with clear "Username" and "Password" input fields, as well as "Login", "Forgot Password", and "Register" (optional) buttons.
- Input fields support basic validation: username must not be empty, password length >= 6 characters. Real-time error prompts on invalid input.
- Adapt to multi-device scenarios with responsive login form layout.

### Session Management

- After successful login, generate a local session (e.g., Cookie, Token). The session validity period is configurable (default 7 days).
- Support "Remember Password" and "Auto Login" features.

### User Identity Differentiation and Data Isolation

- Each user can only view/edit their own data.
- Administrator role can view all users' information and manage accounts.
- Data isolation: photos are by default visible only to the uploading user. Shared and public albums can be configured.

### Security

- Password encryption with irreversible algorithms (bcrypt, Argon2).
- Account lockout after consecutive failed login attempts.
- Session Token destroyed on logout.
- Brute-force protection via IP-based rate limiting.
