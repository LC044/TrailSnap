# Windows 便携实例实施与验收

日期：2026-10-13。实现方案见 `desktop-portable-implementation-plan.md`。

## 已实现行为

- 独立启动器与 `instance.json`：程序存放在 `app/<build-id>`，图库、配置、模型和扩展存放在 `userdata`。每个实例独立分配端口、密钥、图库身份及 WebView 用户数据目录。
- 同一图库只允许一个启动器持有目录锁；不同图库可同时运行。磁盘、配置或版本不可用时报告错误，不创建替代空图库。
- 安装包与 ZIP 只读取安装目录内 instance.json，默认使用 userdata。旧目录必须由用户显式选择；复制先停止后台写入、逐文件校验、升级副本、核对记录与可读媒体并验证实际启动，原库始终保留。
- 托管照片使用存储根和相对路径；整体搬移保留图库身份。显式复制便携实例生成新身份与密钥。外部图库可继续引用，或选择复制进入实例；未登记的外部路径和不可用磁盘会阻止完整副本转换。
- 更新包验签后存放到独立版本目录；启动器备份数据库与配置，启动只读候选进行验证，成功后提交。验证失败或未提交事务中断时恢复快照与原版本。服务退出时等待文件句柄释放。
- 快照按图库身份支持随便携目录搬移；拒绝其他图库的快照。Windows 深层路径复制、读取、校验和暂存清理使用扩展路径。
- 在界面仍运行时转换，不复制受 WebView 占用的浏览器缓存；原缓存保留，新实例重新认证。目录发布遇到 Windows 暂时占用会在限时内重试，超时明确失败。
- Docker 的存储路径不转换。PostgreSQL 和 SQLite 迁移仅增加存储根表、可空引用列及索引，原有绝对路径和查询逻辑保持不变。

## 验收方式

所有测试使用 `tests/scripts/run-tests.ps1` 和 `tests/.env.test`。真实旧实例使用只读基线和完整副本进行验收，未启动原实例，也未切换其目录指针。

真实旧库基线：SQLite 修订 `b0b9b9a3a2c0`，1 个用户、23424 张照片、0 个相册、9346 条任务，完整目录约 18.4 GB。测试核对转换前后记录数、原库修订、SQLite 完整性与外键、搬移后的托管原图样本。

PostgreSQL 验收在测试服务器创建随机独立数据库，执行历史迁移、写入旧账号和路径，再重复升级至当前修订；检查账号散列、设置、原始路径及 ORM 查询和改名，最后删除该测试库。

二进制验收使用实际构建的 Windows ZIP，检查同时运行、端口与密钥隔离、未提交更新恢复、完整更新验证和提交、另一个实例继续可用、目录搬移及冻结后端生成副本后启动。

## 交付边界

- 本轮提供 Windows 同平台、同架构便携包。标准 ZIP 需要电脑已有 WebView2；完全离线电脑应使用构建脚本附带 Fixed Version WebView2 的完整包。
- 本次实际验收为 Windows x86_64 的目录搬移和本机多实例，未在第二台实体电脑或 ARM64 电脑上实测。
- 外部绝对路径不会自动变成可携带照片；移动硬盘需安全退出后拔出。运行中拔盘、磁盘损坏和强制断电不能保证文件系统不受损。
- 转换采用暂存、校验和保留源目录，失败后重新转换；本轮没有实现文件级断点续转。手机发现服务提供实例标识，换电脑或复制实例后可能需要重新发现、扫码和登录。
- 安装版继续使用原 NSIS 更新流程，并增加排空和备份；完整自动验证和事务回滚属于便携更新流程。
- 本机 Docker Engine 无法连接，不能声称已完成真实容器替换和挂载卷升级。实际 PostgreSQL 迁移兼容已验证；正式发布前仍应在可用 Docker 环境运行容器升级验收。
- 本地产物用于测试，未执行 GitHub 发布，也没有用发布私钥签署本地更新包。CI 已增加便携包构建、签名和独立更新清单。
