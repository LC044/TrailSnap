# 新功能建议：朋友圈九宫格智能生成器 — 一键把一次出行变成可分享的九宫格

> 对应 GitHub Issue [#45](https://github.com/LC044/TrailSnap/issues/45)「[Feature] 朋友圈九宫格生成：一键智能选图+拼图+文案」。
> 评估结论：**值得实现**。这条 issue 命中了一个真实且高频的中文用户场景，且 TrailSnap 已经攒齐了所有底层能力（AI 画质分 / 回忆值 / CLIP 嵌入 / 人脸 / 场景分类），唯独缺一个把它们"出口"成成品的入口。

## 功能描述

在工具箱里新增一个"创作"类工具——**朋友圈九宫格智能生成器**。用户选一个来源（一次出行 / 一个相册 / 一个位置 / 一段时间 / 一位人物），系统在几秒内自动挑出 9 张最值得发朋友圈的照片（兼顾画质、人脸、场景多样性、色彩协调），自动配上一句文案，再让用户微调（换图、调顺序、改文案、选拼图样式），最后导出一张 1080×1080 的正方形九宫格图，可直接保存到相册、发到微信朋友圈。

这是 TrailSnap 工具箱里**第一个"向外输出"的创作型工具**。现有 6 个工具（低分清理 / 相似清理 / 重复清理 / 图片整理 / 批量重命名 / 文件名补时间）全部是"向内整理"——把照片库收拾干净，却没有任何一个工具帮用户把整理好的照片"变成一件可以拿出去显摆的作品"。而中文用户最高频的照片输出场景，就是发朋友圈九宫格——周末郊游、节日聚会、一次出差、一场婚礼，几乎都走这条路。目前用户要从 TrailSnap 里选出 9 张、另开拼图 App 拼好、再自己憋文案，至少切三个应用；本提案把这三步压成一步。

> ⚠️ 需要与现有的 `moments` 浏览布局区分：`PhotoGallery.vue` / `UnifiedPhotoPage.vue` 里已经有一个 `layoutMode === 'moments'` 的**展示布局**（把照片按朋友圈时间线样式**展示**给自己看）。本提案是**生成器**——产出一张可对外发布的九宫格图片，方向相反，两者不冲突。

## 功能价值

**一、补上"创作出口"这块最明显的短板。** 翻一遍 `views/toolbox/`，6 个工具清一色是"清理 / 整理 / 重命名"，全部面向照片库自身。一个自托管相册产品如果只能"管理"不能"创作"，用户用一段时间后会陷入"整理得很干净，然后呢"的疲倦期。九宫格生成器是最低成本、最高频的"然后呢"——每周都能用一次，每次都用得着。

**二、把已有 AI 能力变现成用户能感知的功能。** 后端 `image_description` 表里已经存了 `quality_score`（画质分）和 `memory_score`（回忆值），CLIP 嵌入向量也跑过了，人脸聚类和场景分类也都在。但目前这些分数只在灯箱里以两个小 `el-tag` 的形式露出来（`PhotoLightbox.vue` 第 338–339 行），对普通用户而言"看不见、用不上"。九宫格生成器是这些 AI 能力第一次**集体对外输出**的出口——画质分决定"挑清晰的"、回忆值决定"挑有故事的"、CLIP 嵌入决定"挑不重复的"、人脸检测决定"挑有人的"、场景分类决定"9 张覆盖不同场景"。AI 在背后做选择，用户看到的是"它怎么比我还会挑图"。

**三、与已有提案形成完整的"分享"故事线。** 06-26 提了批量导出（原始文件出口）、06-29 提了公开链接分享（整本相册出口）、本提案补上"九宫格成品出口"——三者分别覆盖"我要原始文件"、"我要给别人看一整本"、"我要发一张图到朋友圈"三个最常见出口，构成完整的向外输出闭环。

**四、文化契合度极高。** 产品名「行影集」面向中文用户，而中文用户分享照片的第一场景就是朋友圈九宫格。这是一个"懂中国用户"的产品该有的原生能力，不是从国外相册产品照搬来的功能。

## 功能细节

### 入口与来源选择

入口放在工具箱页（`/toolbox`）现有 6 个卡片之后，作为第 7 个、也是第一个"创作"类卡片，用区别于清理工具的暖色系图标（如玫瑰金/橙色）暗示"这是产出，不是清理"。点击进入 `/toolbox/moments-grid`。

第一屏是**来源选择**，提供 5 个快捷入口，每个对应一种真实场景：

- 「一次出行」——从位置相册的 Trip 列表里选一段旅程（呼应 06-28 的旅行手记）
- 「一个相册」——从已有相册里选
- 「一个地方」——从位置相册里选一个城市/景区
- 「一段时间」——选起止日期，或快捷选项"本周/本月/本年/去年今日"
- 「一位人物」——从人物相册里选一个常出镜的家人/朋友

选完后系统从该范围内拉取候选照片（带 `quality_score` / `memory_score` / CLIP 向量 / 人脸 / 场景标签），进入智能选图。

### 智能选图（核心 AI 环节）

系统在 2–3 秒内从候选集里挑出 9 张，挑选规则对用户可见、可调：

1. **画质门槛**——先过滤 `quality_score` 低于阈值的，保证发出去不糊
2. **人脸偏好**——优先保留有人脸的（可开关：纯风景模式 / 必须有人 / 人物为主）
3. **场景多样**——用 CLIP 嵌入做聚类，保证 9 张尽量覆盖不同场景（不全是大门口、不全是一道菜）
4. **色彩协调**——9 张拼在一起色调不冲突（暖色系 / 冷色系 / 全彩 / 黑白可选）
5. **回忆加权**——`memory_score` 高的优先，让"有故事的"压过"只是好看的"
6. **时间均匀**——如果来源跨度较长（如一次 5 天出行），尽量让 9 张分布在不同天数，讲一个完整故事

选图结果以 3×3 预览呈现，每张图下方挂一个小标签说明"为什么挑它"（如"画质 92 · 含人脸 · 场景：日落"），让 AI 的选择透明可懂。

### 微调阶段

- **换图**：点任意一格，从候选池里滑动替换，候选池按"与当前格相似度"排序，方便找同类替换
- **调顺序**：长按拖拽换位，支持"按时间正序/倒序"一键排
- **换版式**：标准 3×3 / 中心留白放文案 / 1 大 + 8 小 / 时间轴式（1→9 讲故事）
- **加文案**：AI 根据来源类型自动生成 3 条候选文案（文艺风 / 直叙风 / 调侃风），用户可一键选、可手改；文案可放在九宫格外的留白区，也可叠加在中心格

### 导出

一键导出 1080×1080 正方形图（朋友圈标准尺寸），支持是否带 TrailSnap 水印（默认不带，尊重用户）。导出后直接触发浏览器下载，移动端调起"保存到相册 / 分享"系统面板。

### 页面描述

整页采用**"左候选 / 右预览"**的桌面端布局，移动端上下堆叠：

- 顶部：来源回显 + "重新选来源"按钮 + 一句文案"AI 已为你挑选 9 张"
- 左侧（约 40% 宽）：候选照片池，竖向瀑布流，每张带选择原因标签；当前已选 9 张高亮置顶
- 右侧（约 60% 宽）：1:1 正方形九宫格实时预览，所见即所得；下方一排操作按钮（换版式 / 调顺序 / AI 文案 / 导出）
- 底部固定栏：导出按钮 + 重新生成按钮

交互上强调"即时反馈"——左侧点换图、右侧预览立刻变；版式切换带 200ms 过渡动画；AI 重新选图时九宫格逐格翻牌揭晓，把"AI 在替你思考"这件事表演出来。

### 页面风格

延续 TrailSnap 整体的卡片化 + 圆角 + 柔阴影语言，但作为"创作"工具，氛围比清理类工具更暖、更轻快：

- 主色沿用主题色（`primary-*`），但辅以橙金色点缀，暗示"这是产出"
- 预览区背景用浅灰渐变（`bg-gradient-to-b from-gray-50 to-gray-100 dark:from-gray-900 dark:to-gray-800`），让九宫格本身成为视觉焦点
- 候选池卡片用 `rounded-xl` + 极轻阴影，hover 轻微上浮
- AI 文案候选用打字机效果逐字呈现，增强"AI 正在写"的体感
- 导出按钮用主色实心 + `shadow-primary-500/30`，是全页最醒目的 CTA
- 完整支持暗色模式与 5 套主题色切换；移动端单列布局，预览区吸顶固定

## 必要性评估

Issue #45 的标题已经精准概括了三个动作——"智能选图 + 拼图 + 文案"，三者缺一不可，而 TrailSnap 目前**三样全无**：没有拼图导出、没有智能选图入口、没有 AI 文案生成（虽有 LLM 但只用于照片描述）。对照仓库现状：

- `views/toolbox/` 6 个工具全是"向内整理"，零"向外创作"
- AI 画质分 / 回忆值 / CLIP 嵌入 / 人脸 / 场景分类均已就绪，但没有一个面向用户的"成品输出"消费它们
- 现有 `moments` 仅为浏览布局，不产出可分享文件

因此本提案不是"为了做而做"的功能堆砌，而是把**已有能力变现**+**补上工具箱创作缺口**的双重价值。从用户角度，这是一个每周都会用、每次发朋友圈都会想起 TrailSnap 的高频触点——比起一年才看一次的年度回忆录，它更能让产品融进用户的日常。
