# 任务通知系统：长任务完成主动告知与可追溯中心

> 对应 GitHub Issue [#74](https://github.com/LC044/TrailSnap/issues/74)「任务通知系统：长时间任务完成提醒」。
> TrailSnap 已有 13 类后台任务（人脸聚类 / OCR / 缩略图 / 重复检测 / 分类 / 嵌入向量 / 车票解析 / 元数据回填 …），并搭好了 `views/settings/TaskManagement.vue` 这套分组看板，但用户从首页或图库触发一次「全量重建人脸聚类」后，**没有任何主动告知通道**——任务在 worker 进程里跑完 30 分钟，用户不打开「设置 → 任务管理」就完全感知不到。这条 issue 跟 #70（灯箱快捷键）、#73（位置编辑）一样，是「一个原生交互位置」级别的修复。

## 功能描述

把「任务系统」从「埋得深的手动看板」升级为「可订阅的事件流」——一次 SSE 通道、一只顶栏铃铛、一套 Element Plus 站内 Toast、一组浏览器原生通知规则，串起 4 个现状里的散点：

1. **后端 SSE 事件流 `GET /api/tasks/events`**。`package/server/app/api/tasks.py` 现在只有 14 个请求-响应式端点，没有「状态变更」出口。新增一个 `text/event-stream` 路由，复用 `TaskManager.get_instance()`（`app/service/task_manager.py`）已经持有的 `SystemState` 锁；每条 `Task` 行从 `pending → running` / `running → completed` / `running → failed` 状态翻转时推一条 `{id, type, status, processed_items, total_items, error, ts}` JSON。客户端 `EventSource` 断开后 3 秒自动重连，断连期间错过的状态由前端用 `GET /api/tasks/?updated_since=<lastTs>` 一次性拉回。`agent.py` 里已经有 SSE 通道（`AgentChat.vue` 用流式响应），这次直接复用 `sse_starlette` 的同款依赖即可。
2. **顶栏铃铛 `TaskBell` + 抽屉式任务中心**。在 `layouts/NavBar.vue`（已有搜索框 / 主题切换 / 用户菜单的 PC 端 header）右侧、用户头像左侧插入一只 `Bell` 图标（lucide）+ 角标数字（`未读完成任务数`）。点击展开 `el-drawer`（direction `rtl`，width 420），drawer 内分 4 段：进行中（带进度条）、刚刚完成（带缩略图 + 跳转按钮）、失败（带错误摘要 + 重试按钮）、空状态。抽屉里点「查看全部」路由跳到 `Settings → TaskManagement.vue` 并锚定到对应 category。
3. **Element Plus `ElNotification` 站内弹窗**。任务从 `running` 切到 `completed` 时弹一条 `type=success` 的右上角通知（标题 = 任务名 + 数量，例如「人脸聚类完成 2,134 张」、副标题 = 耗时 + 入口按钮「查看结果」）。`failed` 时弹 `type=error` 并展示首条 `error` 摘要。通知通过新 store `useTaskNotifyStore` 全局去重（同 id 不重复弹），并暴露 `markAsRead(taskId)` 给铃铛联动。
4. **浏览器原生通知 + 后台标签页判断**。当 `document.visibilityState === 'hidden'` 且任务已运行超过 60 秒（防「秒级完成」噪音），调用 `new Notification('TrailSnap', {body, icon: '/pwa-192.png', tag: 'task:'+id})` 弹系统通知。点击通知时调用 `window.focus()` + 路由到对应结果页。设置项（写入 `localStorage` 的 `taskNotifyPrefs`）允许按 category 关闭：人脸 / OCR / 嵌入 / 缩略图 / 车票 / 重复 / 其他。

补充两条小尾巴，不算新功能边界：
- `TaskManagement.vue` 顶部「失败 (N)」的「重试失败任务」点击后，弹一条「已开始重试 N 条」通知闭环。
- `views/agent/AgentChat.vue` 在被用户调起 `force_rebuild` 类工具时，复用同一套 `useTaskNotifyStore` 的 `track(taskId)` 入口，把 agent 触发的任务也纳入铃铛未读计数。

## 功能价值

1. **真实痛点、覆盖面广**。13 类任务里随便一个全量跑就是 10–60 分钟量级（人脸聚类在 5 万张照片上实测约 35 分钟），用户的工作流一定是「切到别的页面干别的 → 几小时后再回来看」。当前唯一的「完成」信号是用户主动打开 TaskManagement，对 90% 的真实使用场景是失效的。一个顶栏铃铛 + 系统级通知 = 把这个 90% 的盲区补上。
2. **复用现有 `TaskManager` 状态机，零侵入**。`TaskManager.get_instance()` 已经是单例、已经在用 `SystemState` 锁、已经维护 `grouped_status` 视图；本次只新增「SSE 推送」出口，不动任务调度本身。`TaskManagement.vue` 那 1169 行代码一行不用改——`useTaskNotifyStore` 内部直接订阅 SSE，跟那个页面是平行的两条消费路径，谁也碍不着谁。
3. **与既有 5 个特性叠加成倍**：
   - AI Agent（`service/agent/service.py`）：用户说「把我 2019 年去日本的全部照片加进相册 A」，agent 在后台排队多个 task 时，铃铛未读数 = 进度条，比现有「对话气泡」更直观。
   - 工具箱（`toolbox/DuplicatePhotoCleanup.vue` / `SimilarPhotoCleanup.vue`）：这些是「触发后等结果」类页面，加载完成后能弹「清理完成 87 张重复 / 找到 23 组相似」的通知闭环。
   - 导入工作流（`MultiFileUpload.vue`）：上传完 1 万张照片触发 thumbnail + ocr + embedding 三条流水线，铃铛角标一路 +1 +1 +1 → 全部 completed 后清零，比现在的「请到任务管理看」体验好一个数量级。
   - 年度报告（`views/annual-report/index.vue`）：后台生成时不必霸屏 spinner，可以走铃铛通知，年度报告页只显示「生成中」一行字 + 铃铛角标。
   - 设备切换（手机/电脑）：自托管的 TrailSnap 在手机端用 PWA 安装后（对应 #69 昨天的提案），系统通知能直接推到手机通知中心，真正的「全家都能用」。
4. **后端 SSE 实现轻量**。FastAPI 用 `sse_starlette` 起一个 generator 路由即可，不需要 WebSocket 不需要消息队列，订阅者 1 个 vs 100 个对后端开销差别只在于「一个 `async for` 循环里多 sleep 1s」。`package/ai/app/` 里 `llm.py` 已经是 OpenAI-compatible 流式响应，这套代码风格与 SSE 几乎一致。
5. **前端零新依赖**。`Bell` 图标用 lucide-vue-next（`package.json` 已有）；抽屉用 Element Plus 自带 `el-drawer`；通知用 Element Plus 自带 `ElNotification` + 浏览器原生 `Notification` API。不增加 `node_modules` 一行。
6. **可关闭、可降级**。整套通知在用户「不想要时」可逐 category 关闭，SSE 断开自动回退到 15s 轮询 `grouped-status`，最差情况也跟今天的体验一致，不存在「做了比没做更糟」的下限。
7. **跟昨天 #69 PWA 提案完美互补**。昨天的 `2026-06-25.md` 计划做「PWA 可安装 + 缩略图离线缓存」；今天这个「系统通知」在桌面浏览器上需要标签页存活、但 PWA 安装后能直接走 Service Worker 的 `notificationclick` 事件——两条放一起，桌面 + 移动端通知体验是闭环的。

## 功能细节

### 页面描述

`TaskBell` 组件（新增文件 `package/website/src/components/TaskBell.vue`）是一个 36×36 圆形按钮，外层 `relative`，内层 lucide `Bell` 图标 (size 18)，右上角 `absolute -top-0.5 -right-0.5` 放一个 16px 圆形红点 / 数字徽章（`el-badge` 也行，但自己写 div 更可控），徽章在 0 时不渲染。`useTaskNotifyStore` 通过 `provide/inject` 在 `App.vue` 单例，全局任何地方 `const { markAllAsRead, openDrawer } = useTaskNotifyStore()` 都能调。抽屉使用 `el-drawer`（direction `rtl`，size 420，with-header=false），打开时通过 `defineExpose` 把内部 ref 暴露给外部 trigger（`NavBar.vue` 里那只铃铛）。

抽屉内部布局（自上而下）：
- **顶部固定区**（高 64px）：左侧「任务中心」标题（`text-base font-medium`），右侧两个文字按钮「全部已读」「查看全部」+ `X` 关闭。
- **进行中分组**（仅当 SSE 推来 `running` 任务时显示）：每行 56px 卡片，左侧 8×8 的 `bg-primary-500` 脉冲圆点 + 任务名 + 「1234 / 5000」进度文本 + 24px 高度 `el-progress` 条（`:percentage="(processed/total)*100"`，`status=""`，`show-text=false`，`stroke-width=4`）。点击行展开详情（payload 摘要 + 创建时间）。
- **刚刚完成分组**（默认显示最近 1 小时）：卡片左侧 36×36 缩略图（`/api/medias/{id}/thumbnail?size=128`，方形 `rounded-md`），中间任务名 + 「3 分钟前 · 2,134 张」，右侧 `→` 跳转按钮（按 task type 路由到不同终点：人脸 → `album/people`，OCR → 选 photo lightbox，车票 → `ticket`，其他 → `TaskManagement`）。整行 `hover:bg-slate-50 dark:hover:bg-slate-800/60`。
- **失败分组**（仅当存在）：卡片背景 `bg-red-50/40 dark:bg-red-900/10`，左侧 `AlertTriangle` 图标（`text-red-500`），中间任务名 + 首行错误摘要（`truncate`），右侧两个文字按钮「重试」「忽略」。忽略后该任务从失败分组移到「已忽略」二级折叠区。
- **空状态**：当进行中/完成/失败均为空时，居中显示 `Inbox` 图标（48px、`text-slate-300`）+ 副标题「暂无任务动态」+ 一行 hint「去工具箱看看？」按钮（路由到 `toolbox`）。

抽屉底部固定区（高 56px）：左侧说明文字「通知偏好可逐类关闭」，右侧 `Cog` 图标按钮 → 弹出 `el-dialog` 形式的偏好面板（12 个 category 复选框 + 「桌面通知」主开关）。

`useTaskNotifyStore` 内部（`stores/taskNotifyStore.ts`）维护：
- `unreadCount: number` —— 已完成 + 失败且未读的数量
- `unreadCompleted: Task[]` / `unreadFailed: Task[]` / `running: Task[]` —— 三组最新 50 条
- `prefs: Record<TaskCategory, boolean>` —— 通知偏好
- `connect()` / `disconnect()` —— 生命周期挂在 `App.vue` 的 `onMounted/onUnmounted`
- `markAsRead(taskId)` / `markAllAsRead()`

### 页面风格

- **顶栏按钮**：`TaskBell` 整体宽度 36px、高度 36px，`hover:bg-slate-100 dark:hover:bg-slate-800` 圆形过渡；徽章数字在 ≥100 时显示 `99+`，颜色固定 `bg-red-500 text-white`（不跟随主题，因为「未读提醒」在所有主题下都该是红色高警示）。
- **抽屉容器**：`el-drawer` 边框 `border-l border-slate-200 dark:border-slate-800`；背景 `bg-white dark:bg-slate-900`；阴影 `shadow-2xl`。抽屉内分组之间用 `divide-y divide-slate-100 dark:divide-slate-800` 切分，不画卡片边框——和 `MainLayout.vue` 的 `bg-slate-50` 整体克制风格保持一致。
- **进度条**：用 Element Plus 的 `el-progress` 但去掉外圈 padding，让它在 56px 卡片内只占 24px 高度；颜色跟随主题 `bg-primary-500`。
- **缩略图**：失败/完成卡片的 36×36 缩略图用 `object-cover rounded-md border border-slate-200 dark:border-slate-700`；失败分组里改成 lucide `FileWarning` 占位（`text-slate-400`，无边框）。
- **站内 Toast**：用 `ElNotification` 默认位置 `top-right`，title 字号 `text-sm font-medium`，duration 默认 4500ms（`completed`） / 8000ms（`failed`）；type=success 时 icon 用 lucide `CheckCircle2` 替 Element Plus 默认，type=error 时用 `XCircle`，颜色走主题 `text-primary-500` / `text-red-500`。
- **浏览器原生通知**：i18n 文案在 `zh-CN` 下：「{{taskName}}完成 {{count}} 张 · 耗时 {{duration}}」；失败时：「{{taskName}}失败 · {{errorSnippet}}」。点击通知 = 唤起对应详情。
- **空状态**：用 lucide `Inbox` 图标 + 一句话文案，不放插画。整页用 `text-slate-400 dark:text-slate-500` 灰色调，跟现有 `RecycleBinPage.vue` 的空态风格一致。
- **过渡动画**：抽屉打开用 Element Plus 默认 300ms ease；分组列表的 v-for 用 `<TransitionGroup>` 配 `name="task-list"`，进入 `opacity-0 translate-y-1` → `opacity-100 translate-y-0`（180ms ease-out），离开 `opacity-100` → `opacity-0`（120ms ease-in），保证「+1 → -1」的节奏感。
- **可访问性**：铃铛按钮加 `aria-label="任务中心，未读 ${count} 条"`；徽章数字加 `aria-live="polite"`；抽屉内卡片用 `<button>` 包裹以保证键盘可达，`focus-visible:ring-2 focus-visible:ring-primary-500 focus-visible:ring-offset-2`。

### 后端实现要点

- 新增 `app/api/tasks_sse.py`（或直接加在 `app/api/tasks.py` 末尾），端点 `GET /api/tasks/events`：
  - 用 `sse_starlette.sse.EventSourceResponse` 包裹一个 `async def event_generator()`，内层 `while True: await asyncio.sleep(1.0); ...`。
  - 内部维护一个 `asyncio.Queue`，`TaskManager` 在 `update_task_status(task_id, new_status)` 现有钩子里多推一条 `{event: 'task.updated', data: {...}}`。
  - 鉴权沿用 `Depends(get_current_user)`，跟其他端点保持一致。
- 客户端断开 = `generator.aclose()` 触发 `finally` 块里 `await queue.put(None)` 解除订阅，避免泄漏。
- 降级路径：前端 `EventSource` 不可用或连续 3 次断开 → 切到 `setInterval(() => tasksApi.getGroupedStatus(), 15000)` 轮询，对比上次 `updated_at` 决定是否触发通知。

### 文件改动清单

- 新增：`package/website/src/components/TaskBell.vue` / `package/website/src/stores/taskNotifyStore.ts` / `package/website/src/composables/useTaskSSE.ts`
- 修改：`package/website/src/layouts/NavBar.vue`（插入 TaskBell，~10 行） / `package/website/src/App.vue`（调 `useTaskNotifyStore().connect()`，~3 行）
- 新增：`package/server/app/api/tasks.py` 末尾 SSE 路由（~60 行） / `package/server/app/service/task_manager.py` 在 `update_task_status` 推 queue（~5 行）
- 文档：`package/website/src/api/tasks.ts` 加 `sseUrl` 常量 / `doc/frontend_analysis.md` 增补「任务通知」章节

### 验收标准

1. 触发任意 task，关闭「设置」页签 → 任务完成时右上角弹 `ElNotification` +（标签页隐藏时）系统通知。
2. 铃铛角标数字 = 未读完成 + 未读失败之和，点开抽屉后角标清零。
3. SSE 通道手动断开 5 秒后自动重连 + 拉回错过的状态变更。
4. 偏好面板关闭某 category 后，该 category 的任务完成不再弹任何通知。
5. `TaskManagement.vue` 现有功能零回归（既不调它的代码，也不依赖它）。
6. 暗色模式 / 5 个主题 / 移动端布局（NavBar 在 < 768px 用的是折叠菜单，需要在该菜单内也挂载 TaskBell 入口）下视觉无破图。

# 照片幻灯片与故事模式

> 增量提案，不替换上文「任务通知系统」。`views/` 下已有 `PhotoLightbox.vue`（单图查看 + 12 个圆形工具按钮）、`AlbumDetail.vue`（相册瀑布流）、`LocationMapView.vue` / `LocationTrajectoryView.vue`（位置相册）、`annual-report/index.vue`（年度报告），但**全屏沉浸式幻灯片播放器完全缺失**——用户整理完一次旅行照片后想「从头到尾翻一遍」，只能手动点开 Lightbox 再按箭头，工具栏持续占用屏幕底部 1/4 高度，沉浸感被反复打断。Google Photos / Apple Photos / Immich 都把「Slideshow / 回忆」作为核心体验，TrailSnap 在相册详情页、年度报告页、位置轨迹页都缺这条出口。

## 功能描述

新增一个全屏 `SlideshowPlayer` 页面 + 在 4 个现有入口插入「播放」按钮，覆盖「单图、相册全集、按位置/人物/时间筛选后的子集、年度报告」四种触发场景，附带背景音乐、转场、自动播放、键盘控制、导出为 MP4 / 分享链接的完整闭环。

1. **新建 `views/slideshow/SlideshowPlayer.vue`**：对应路由 `/slideshow?source=album:42&start=12&music=...`，全屏黑底 + 照片 `object-contain` 居中。
2. **Lightbox 工具栏新增 `Play` 按钮**（`PhotoLightbox.vue` L36-50 那排圆形按钮的「下载」和「编辑」之间），点击 → 跳转 `/slideshow` 并从当前照片起播。
3. **`AlbumDetail.vue` 顶部操作栏新增「播放全部」**（在「添加照片」和「批量管理」之间），传整本相册的照片 ID 列表。
4. **`LocationMapView.vue` / `LocationTrajectoryView.vue` / `ClassificationList.vue` / `PeopleList.vue`** 的右上角各加一颗 `Play` icon 入口，把当前筛选结果作为播放列表。
5. **`annual-report/index.vue` 的「生成年度报告」完成后弹一个 `el-dialog`**：「立即播放故事 / 仅下载 / 稍后再说」，点「立即播放」直接跳 `/slideshow` 并把报告里那 9 张精选图作为播放列表。
6. **背景音乐**：上传一个或多个 mp3 到 `localStorage.trailsnap_slideshow_music`（base64 持久化），或选「无」静音；播放期间用 HTMLAudioElement 后台循环。
7. **导出 / 分享**：用 `MediaRecorder` + `<canvas>` 离屏渲染（按转场 + 停留时间生成视频流），输出 webm；分享链接用现有的 `ShareToken` 机制（`/api/agent_token` 已有同类能力）临时签发一个只读 token。

## 功能价值

1. **真实场景命中、补齐主流产品差距**。Google Photos 的「回忆」、Apple Photos 的「纪念日」、Immich 的「Memories」都是首页默认 Tab，TrailSnap 这条主线完全空白。用户在相册整理流程的最后一公里——「我现在就想好好看一遍这些照片」——没有任何出口。
2. **与既有 6 个特性正向叠加**：
   - 灯箱（昨天的 #70 快捷键提案）：`Space` 播放/暂停直接复用，不冲突。
   - 相册（`AlbumDetail.vue`）：新增「播放全部」= 相册的「沉浸模式」，比现有网格浏览高一个使用频率量级。
   - 位置相册（`LocationMapView.vue`）：配合 6/24 的位置编辑提案，旅行后「按地点回忆」是天然场景。
   - 智能分类（`ClassificationList.vue`）：把 AI 分类结果直接当故事播放。
   - 人物（`PeopleList.vue`）：「这一年小明出现在 23 张照片里 → 一次性回顾」是高频情感场景。
   - 年度报告（`annual-report/index.vue`）：报告本身就是精选集合，播放 = 报告的最终交付形态。
3. **零后端改造**。所有逻辑（视频导出、播放列表、键盘控制、转场）都在前端完成；播放列表通过 query string 传 photo_ids；后端只需要一个可选的 `POST /api/share/sign`（已有 `agent_token` 同款机制，零新增表）。
4. **导出能力是「全家桶」的最后一环**。视频导出后用户可以发朋友圈、给父母电视投屏、做婚礼现场回顾——这是 Google Photos / 苹果相册用户每周至少用一次的功能，TrailSnap 之前完全没有。
5. **风险面极小**。`MediaRecorder` 在所有现代浏览器都已稳定支持（Chrome / Edge / Safari 14.1+ / Firefox），降级路径（不支持时只给「分享链接」）在 v1 就明确。照片预加载策略（前后各 2 张、IntersectionObserver 控制）保证 1000 张相册也不爆内存。
6. **可观测、可降级**。新增一个 `useSlideshowStore`（Pinia），里面只放当前播放列表、索引、播放状态、音乐 URL；任何一步崩了只影响幻灯片页，不影响 Lightbox / 相册详情。

## 功能细节

### 页面描述

#### A. `views/slideshow/SlideshowPlayer.vue`（新页面，~350 行）

路由：`/slideshow?ids=1,2,3&start=0&music=<base64>&interval=4&transition=fade`

布局（全屏 `bg-black`，无 `MainLayout`）：

- **照片主区**：`<img>` 绝对定位 + `object-contain` + `max-h-screen max-w-screen`，根据上一张/下一张方向做 24px 的位移动画过渡（避免硬切）。
- **顶部条**（高 48px，半透明 `bg-black/40 backdrop-blur`）：左侧 `ChevronLeft` 返回 + 「3 / 28」进度文字；中间 `Play` / `Pause` 切换（lucide）；右侧 `Music` 切换音乐 / `Settings` 齿轮 / `X` 退出。
- **底部条**（高 56px）：左侧当前照片元信息（拍摄时间 + 地址，`truncate` 1 行），中间进度条（整本相册的缩略图横排，64×40 圆角，当前播放高亮 `ring-2 ring-primary-500`），右侧 `Share2` 分享 / `Download` 导出。
- **自动隐藏**：3 秒内无鼠标移动 → 顶部 / 底部条 `opacity-0`，移动鼠标 `opacity-100` 渐入（`transition-opacity duration-300`）。
- **转场**：内置 `fade` / `slide-left` / `slide-right` / `zoom` 四种，用 Vue 的 `<Transition mode="default">` 包裹；默认 `fade`，可在 settings 弹窗切换。
- **自动播放**：默认 4 秒 / 张，settings 弹窗可调 2 / 4 / 6 / 8 秒；末张播完自动暂停并弹一个「再来一遍 / 退出」小卡片。
- **照片预加载**：维护 `window.__preloaded` 队列，当前 index 的前后各 2 张用 `new Image()` 提前加载；监听 `error` 事件，单张加载失败不阻塞后续，跳过并在底部条显示「1 张加载失败」。

#### H. 导出 / 分享（v1 简化版）

### 页面风格

- **全屏黑底 + 照片 `object-contain`**：所有主题下都一样（不跟随主题色），因为这是「沉浸内容」页面，不是工具页面。
- **控制条半透明黑底**：`bg-black/40 backdrop-blur-md`，文字 `text-white/90`，与现有 Lightbox 顶部条（`PhotoLightbox.vue` L7-67）保持一致的「黑底 + 白字」暗色逻辑。
- **进度条高亮**：`ring-2 ring-primary-500` 跟随 5 套主题（sky / emerald / violet / rose / amber）自动切换，零硬编码。
- **按钮焦点环**：`focus-visible:ring-2 focus-visible:ring-primary-500 focus-visible:ring-offset-2 focus-visible:ring-offset-black`，黑色 ring-offset 与全屏黑底契合。
- **转场动画**：`<Transition name="fade">` + `<Transition name="slide">` + `<Transition name="zoom">` 三套 CSS，scoped 样式里写 `@keyframes`，200-400ms 缓动，遵循 AGENTS.md「不依赖第三方动画库」的规范。
- **零新依赖**：lucide 图标、Element Plus `el-dialog` / `el-upload` / `el-slider` / `el-message-box`、原生 `MediaRecorder` / `Audio` / `Canvas`——不增加 `package.json` 一行。
- **空状态**：播放列表为空时（`ids=` 为空）居中显示 `Film` 图标（48px、`text-white/30`）+ 「没有可播放的照片」+ 「返回」按钮（跳上一级）。
