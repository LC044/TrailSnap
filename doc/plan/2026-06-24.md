# 照片位置编辑：地图拖拽标注与批量修正

> 对应 GitHub Issue [#73](https://github.com/LC044/TrailSnap/issues/73)「照片位置编辑：地图拖拽标注与批量修正」。
> 当前 `PhotoMetadataSidebar.vue` 中「拍摄时间」「基本信息」均带 `Pencil` 编辑按钮，唯独「位置」一栏是只读——这是元数据侧栏唯一缺失的编辑能力，而底层 `MapContainer.vue`（`views/album/location/components/MapContainer.vue`）已经能跑通天地图，把这套基础能力暴露到照片级别是边际成本极低的一次提升。

## 功能描述

把位置从「只读展示」升级为「可编辑」的三档交互，并补齐后端批处理能力，串起 4 个现状里的散点：

1. **元数据侧栏就地编辑**。在 `PhotoMetadataSidebar.vue`「位置」分组标题旁（参照已存在的「拍摄时间」`openBasicEditDialog` 模式）新增一个 `Pencil` 编辑按钮，点击后弹出 `el-dialog`，左侧 mini 地图（用现成的 `MapContainer.vue` 复用 + 缩到 480×360）显示当前坐标；用户搜索关键字（复用 `locationService.searchLocations` 既有端点）→ 选点 → 拖拽精修 → 反向地理编码出 `formatted_address` → 保存。保存走新增的 `PATCH /api/medias/{id}/location`。
2. **Lightbox 工具栏新增「在地图上调整」入口**。在 `PhotoLightbox.vue` 工具栏（参考 L7-67 那 12 个圆形按钮）的「添加」/「OCR」下拉里增加一项 `MapPin` 图标「调整位置」，点击后直接把灯箱切到「侧栏 + 地图模式」——复用 `PhotoMetadataSidebar` 的编辑态并把背景图换成原图，让用户能「看着照片猜位置」。这是 Issue #70（昨天的快捷键提案）里 `O` 键之外另一种「OCR 错时人工补救」的自然延展。
3. **批量修正：选 N 张 → 选一次位置 → 应用到全部**。在 `FlatPhotoGallery.vue` 批量操作栏（参考其 `add-to-album` slot 模式）新增 `MapPin` 按钮「批量调整位置」，多选后弹出一个全屏 `el-dialog`：左侧 480×360 地图、右侧多张缩略图网格（按时间倒序），用户拖一次 pin → 点「应用到全部」→ 调 `POST /api/medias/batch-location` 一次写库。这是 Issue #73 标题里「批量修正」的核心。
4. **删除/恢复时联动位置数据**。`RecycleBinPage.vue`（299 行）目前只调软删除端点；后续做「永久删除」时把 `medias.location` 外键关联记录一起清掉，避免孤儿地点坐标堆积影响 `LocationList.vue` 的统计。属于「顺手做对」的小尾巴，不是新功能边界。

## 功能价值

1. **真实痛点、零新依赖**。GPS 元数据出错是几乎所有摄影师都遇到过的——手机 GPS 漂移、相机没 GPS、导入时被照片管理工具覆盖、室内无信号……当前用户遇到这种情况只能「忍着」或「去改 EXIF」。补一个天地图级别的可视化编辑器，**复用现有 `MapContainer.vue` 与 `locationService.searchLocations`，不需要新增任何第三方服务**。
2. **侧栏编辑交互是真正的「对症下药」**。`PhotoMetadataSidebar.vue` 现在用 `Pencil` 图标可编辑「基本信息」「拍摄时间」「标签」「人物」「相册」5 个分组，**唯独「位置」是只读**——这恰好是元数据里最容易出错、改动最频繁的字段。补齐后整条编辑链路是闭合的、零空缺的。
3. **与既有 6 个特性叠加成倍**：
   - 智能相册（`AlbumList.vue`）：把「外滩夜景」相册里那些因为漂移没归到上海的 23 张照片一键纠正，下次相册自动归位。
   - 位置相册（`LocationList.vue` / `LocationMap.vue`）：现有统计按坐标聚类，纠正后会显著改善散点分布。
   - AI Agent（`service/agent/tools.py`）：新增 `update_photo_location(photo_id, lat, lng, address)` 工具，让「把我昨天拍的那张西湖照片改到断桥」这种自然语言请求真正闭环。
   - 旅行轨迹（`LocationTrajectoryView.vue`）：修正 GPS 后轨迹回放（关联 Issue #56）会立刻更准。
   - 智能行程聚合（关联 Issue #63）：行程切分的第一信号是「经纬度跳变」，坐标纠正后能少切碎几个错误 trip。
   - 朋友圈九宫格（关联 Issue #45）：选图时按位置分组，纠正后「同一天同一地点」的照片能更准地分到一组。
4. **批量是真正的杠杆**。单张编辑只能解决 5% 的场景，剩下 95% 是一次性相机/老手机整批照片没 GPS 的情况。`POST /api/medias/batch-location` 一个端点 + 一个全屏弹窗的复用，对 PhotoPrism/Immich 用户来说是非常熟悉的「标准动作」，会让 TrailSnap 在「导入即用」这条用户曲线上再上一个台阶。
5. **不依赖 AI 服务**。整个流程不调 `/api/ai/*` 任何端点，AI 容器挂了 / 没装 GPU 都不影响。`locationService.searchLocations` 已经是生产可用的反向地理编码入口（`views/album/location/AddSceneDialog.vue` L18-30 用的就是它）。
6. **可观测的依赖图小到可以放心落地**。修改集中在 3 个文件 + 2 个新端点，地图组件 0 行新增（直接复用 `MapContainer.vue` 的 `initMap` 与 `marker` 抽象），回滚容易。

## 功能细节

### 页面描述

**A. `PhotoMetadataSidebar.vue`「位置」分组的 Pencil 编辑入口**（最贴近现状的最小改动）

在 `<MapPin />` 那一行的右侧加上 `Pencil` 按钮（与「拍摄时间」的样式完全一致：`p-1 rounded-md text-gray-400 bg-transparent hover:text-primary-500 hover:bg-gray-100 dark:hover:bg-gray-800`），点击后置 `showLocationEditDialog.value = true`。新增一个 `el-dialog`：

- 左 60% 区域：mini 地图，调用 `useLocationMap` 组合式（见下）渲染一个 480×360 的天地图实例，初始中心 = 现有 `metadata.location.lat/lng`（若有）或 `selectedFromSearch`。
- 右 40% 区域：表单（`el-form label-position="top"`）。
  - 搜索框：`el-autocomplete` + `locationService.searchLocations`，与 `AddSceneDialog.vue` L18-30 完全相同的 `fetch-suggestions` 写法。
  - 「当前坐标」只读显示（`lat` / `lng`，保留 6 位小数），从地图拖拽事件回写。
  - 「地址」`el-input v-model="editForm.formatted_address"`，由反向地理编码自动填充，可手动改。
  - 底部两个按钮：「保存」→ `PATCH /api/medias/{id}/location` → `ElMessage.success` + 关闭弹窗 + emit `photo-updated` 让 `PhotosPage` / `AlbumDetail` 局部刷新；「取消」关闭弹窗不改状态。

**B. `PhotoLightbox.vue` 工具栏的「调整位置」入口**（复用 A）

在工具栏 L36-50 的下拉菜单里加一项（与「添加到人物」「移动到目录」同级）：

```vue
<el-dropdown-item @click="enterLocationEditMode">
  <MapPin class="w-4 h-4 mr-2" /> 调整位置
</el-dropdown-item>
```

`enterLocationEditMode` 做两件事：① 显示 `PhotoMetadataSidebar`（如果当前没显示就 `emit('toggle-sidebar')`）；② 把 `PhotoMetadataSidebar` 强制切到 `mode: 'location-edit'` 状态，传 `{ photo, dialogOpen: true }`。这样用户可以在「看着原图」的情况下同时调整位置。

**C. `FlatPhotoGallery.vue` 批量操作栏的「批量调整位置」入口**（最高频、最高价值）

在 `add-to-album` slot 之后插入：

```vue
<button
  @click="$emit('batch-edit-location', Array.from(localSelectedIds))"
  :disabled="localSelectedIds.size === 0"
  class="p-2 text-primary-500 hover:bg-primary-50 dark:hover:bg-primary-900/20 rounded-lg disabled:opacity-50"
  title="批量调整位置"
>
  <MapPin class="w-5 h-5" />
</button>
```

新建一个全屏 `el-dialog` `views/components/LocationBatchEditor.vue`（约 280 行）：

- 左 480×640 地图：与 A 共享 `useLocationMap`，允许拖一次 pin。
- 右滚动列表：被选中的 N 张照片缩略图（`el-image` + `lazy`），按 `timestamp` 倒序，每行显示「拍摄时间」「当前坐标」「地址」3 列 + 一个「单张移除」小叉。
- 顶部一行小字："将 {{ count }} 张照片的位置设为 [address]（{{ lat }}, {{ lng }}）"。
- 底部按钮：「应用到全部」→ 调 `POST /api/medias/batch-location` → 成功后 `ElMessage.success` + 关闭弹窗 + emit `photos-updated` 让画廊静默刷新 + 清空 `selectionStore`。
- 安全护栏：当 `count > 50` 时弹一个二次确认（`ElMessageBox.confirm`），避免「误点 500 张」。

**D. 后端两个新端点**（与 A/B/C 配套，1 个文件 / 50 行内）

- `PATCH /api/medias/{id}/location` body `{lat, lng, formatted_address?, force_regeocode?: bool}`，调用现成的反向地理编码补全 `province/city/district/scene`（`LocationList` 统计依赖的字段），写 `medias.location` 与 `medias.gps`。
- `POST /api/medias/batch-location` body `{photo_ids: string[], lat, lng, formatted_address?}`，事务内更新，写一条 `audit_log`。
- **不要新增表**，不要动 Alembic；`medias.location` 已经是 JSON 字段（`LocationList.vue` 已经在读它）。

### 页面风格

- **沿用 AGENTS.md 的主题色规范**。所有 MapPin 图标与按钮 active 态用 `text-primary-500` / `bg-primary-50` / `hover:bg-primary-600`，在 5 套主题（sky / emerald / violet / rose / amber）下自动切换。`useTheme.ts` 里的 `injectTheme()` 注入到天地图实例后，地图上的「当前位置」marker 用 `currentTheme.value.primary` 渲染，pin 拖动时主题色跟着变。
- **暗色适配**。mini 地图容器 `bg-gray-100 dark:bg-gray-800`，对话框 `bg-white dark:bg-gray-900`，与 `AddSceneDialog.vue` 现有 `el-dialog` 模式一致。**特别注意**：天地图底图是亮色的，需要加 `mix-blend-mode: lighten` 或 `filter: invert(0.92) hue-rotate(180deg)` 让暗色模式不刺眼——参考主流地图（百度/高德）的实现，封装到 `composables/useLocationMap.ts` 里复用。
- **焦点环**。`Pencil` 按钮、批量栏按钮、地图上的可点击 marker 全用 `focus-visible:ring-2 focus-visible:ring-primary-500 focus-visible:ring-offset-2 focus-visible:outline-none`。
- **单灰色族**。`PhotoMetadataSidebar` 主体已经是 `bg-white dark:bg-gray-900`，新增弹窗维持同色族，不要混入 `slate-*`。
- **零硬编码品牌色**。禁止 `text-blue-500/600/700`（现 `AddSceneDialog.vue` L32-43 的 `focus:ring-blue-500` 顺手一起改成 `focus:ring-primary-500`）。
- **拖拽光标**。地图上可拖区域 `cursor: grab` → `cursor: grabbing`；marker 悬浮显示小气泡「拖动修正位置」。

### 验收与回归

- **E2E**：`tests/e2e/` 新增 `location-edit.spec.ts`，用 Playwright 触发：① 单张编辑 → 拖 marker → 保存 → 重新打开侧栏验证地址已更新；② 批量 5 张编辑 → 全部应用 → 跳回画廊看每张位置都改了。
- **手动回归**：5 个灯箱入口（PhotosPage / AlbumDetail / PeopleDetail / Search / RecycleBin）逐一确认「调整位置」下拉可点；批量按钮在 `selectionStore` 为空时 disabled。
- **可观测性**：批量端点响应时间应 < 500ms（100 张以内），超过 1s 给出「后台处理中」提示（v1 可暂用同步，v2 接入 task 队列）。
- **回归保护**：新增后不要破坏「从文件名修改拍摄信息」(`TimeFromFilenamePage.vue`) 与「清理相册」(`CleanupPage.vue`) 的 EXIF 流程——它们不读 `medias.location`，但要确保不会因为共享 model 字段而误改。
