# TrailSnap PWA 化：移动端可安装 + 离线浏览照片缩略图

> 对应 GitHub Issue [#69](https://github.com/LC044/TrailSnap/issues/69)「PWA 离线支持：移动端可安装与离线浏览缓存」。
> 当前 `package/website` **完全没有任何 PWA 基建**：`package.json` 没有 `vite-plugin-pwa`，`vite.config.js` 只装了 `@vitejs/plugin-vue`，`public/` 里只有 `favicon.ico` / `logo.svg` / 几张装饰图，`index.html` 没有 `<link rel="manifest">`、没有 `theme-color` meta、没有 `apple-touch-icon`、没有 `mask-icon`。这意味着 Chrome / Safari 移动端无法把 TrailSnap「加到主屏幕」，离线时整站直接挂掉；而 TrailSnap 是一个**读多写少**的照片浏览产品（相册详情、Lightbox、位置地图这些高频路径全都是 GET 资源），把这条主路径缓存下来边际成本极低、用户收益极大。

## 评估结论（TL;DR）

强烈建议做，且**第一版严格限定为「只读可安装 + 缩略图离线缓存」**，把"可写同步""推送""iOS 后台同步"这些边界推到 v2。理由如下：

1. **现状完全是白纸**。没有 service worker 冲突需要清理，没有缓存策略需要重写，没有 manifest 字段需要迁移——属于**最舒服的 PWA 接入时点**。
2. **产品域适配度极高**。一个用户的 TrailSnap 会话里，**80% 以上的请求是缩略图/原图 GET**（`/api/medias/file/{id}/thumbnail` 这种），剩下 15% 是相册/标签/位置元数据，**只有 5% 是写操作**。先覆盖前 95% 的读路径，离线体验就已经成立。
3. **主题色天然兼容**。`src/composables/useTheme.ts` 已经维护了 5 套主题（sky / emerald / violet / rose / amber），每套都有 `primary`（hex）+ `rgb` —— PWA 的 `theme_color` 和 `background_color` meta 完全可以**响应式跟随当前主题**，不用新增设计系统。这是 TrailSnap 相对其他 PWA 改造的隐藏优势。
4. **和 5 个已有特性正向叠加**（详见后文「功能价值」第 4 条）。
5. **风险面小**。`vite-plugin-pwa` 已经被 Vite 官方推荐（`VitePWA` plugin），Workbox 缓存策略文档完备，主流 AI agent（Codex / OpenClaw）都已内置 PWA 知识。整个 P0 工作量预计 **2 个新组件 + 1 个 composable + 1 个页面 + 1 个 manifest + 1 个 vite plugin 配置**。

不建议在第一版同时做：桌面端安装、推送通知、后台同步、AI 推理结果缓存（AI 服务是独立容器，缓存命中收益低且容易导致过期模型结果误导用户）、**离线写入队列**（TrailSnap 的写操作集中在"上传""编辑元数据"——这些放在线做更安全）。

## 功能描述

把 TrailSnap 升级为可安装的渐进式 Web 应用，重点解决三件事：

1. **移动端「添加到主屏幕」开箱可用**。iOS Safari / Android Chrome / 鸿蒙浏览器都能识别 TrailSnap 为可安装应用，桌面 Chrome 也会显示地址栏右侧的安装按钮。安装后**独立窗口启动、隐藏浏览器 UI、启动画面和应用图标跟当前主题色一致**。
2. **离线/弱网下的照片浏览闭环**。当用户处于地铁、飞机、地下停车场、山区等弱网场景时，已访问过的相册/智能分类/位置相册**保留 30 天内可继续翻阅**（按缩略图缓存策略），原图按需懒加载。导航、Lightbox、OnThisDay、统计图这些纯读视图全部能跑通。
3. **优雅的更新与降级**。当后端发布新版本时，**不强制刷新打断用户**，而是在右下角弹一个 toast「TrailSnap 已更新，点击刷新」，点一下再切到新版。离线时右上角小指示器低调提示"离线浏览中"，不打断操作。

### 技术选型

- **`vite-plugin-pwa` 1.x**（Vite 7 兼容版）：自带 Workbox 集成、自动生成 manifest、autoUpdate 策略、`@vite-pwa/assets-generator` 可从 `logo.svg` 一键产出全套尺寸的 PWA 图标。
- **Workbox 缓存策略矩阵**：

| 资源类型 | 策略 | 容量上限 | 过期时间 | 理由 |
| --- | --- | --- | --- | --- |
| 应用 shell（HTML/JS/CSS） | `precacheAndRoute` | Workbox 默认 | v1 | 离线启动 |
| 字体（Mingcute icon font 等） | `CacheFirst` | 30 | 90 天 | 不变 |
| 缩略图 `/api/medias/file/{id}/thumbnail` | `CacheFirst` | 1000 | 30 天 | 高频读、相对稳定 |
| 原图 `/api/medias/file/{id}/original` | `StaleWhileRevalidate` | 200 | 7 天 | 大文件，避免双倍缓存 |
| API GET（`/api/albums`、`/api/locations`、`/api/photos` 等） | `NetworkFirst` | 200 | 24h（兜底） | 元数据要新，但离线可读 |
| API 写（POST/PUT/PATCH/DELETE） | `NetworkOnly` | 0 | — | 写入绝不能离线误以为成功 |
| 地图瓦片（天地图） | `StaleWhileRevalidate` | 500 | 30 天 | 离线时位置相册仍能定位 |
| 用户头像、装饰图 | `CacheFirst` | 50 | 30 天 | 不变 |

- **版本控制**：`self.__WB_MANIFEST` 注入 + `skipWaiting()` 关闭、`clientsClaim()` 立刻接管。autoUpdate 模式 + 用户点 toast 才 reload（避免半截渲染）。
- **iOS 兼容**：补 `apple-touch-icon`（180×180，**不能带 alpha**，iOS 不支持透明图标）、`apple-mobile-web-app-capable=yes`、`apple-mobile-web-app-status-bar-style=black-translucent`。iOS 不支持 `theme-color` 动态跟随，但启动画面用 `background_color` 静态填一个中性灰即可（避免与主题色割裂）。
- **HTTPS 要求**：生产部署本身就走 nginx + 自签名/Let's Encrypt（参考 `docker-compose.yml` 的 frontend 容器），本地开发 vite dev server 不会触发 SW（`devOptions.enabled = false`）。

## 功能价值

1. **真实场景命中**。TrailSnap 的目标用户是「自部署相册玩家」，他们**手机端的使用强度远高于桌面**——通勤地铁翻相册、回老家飞机上看老照片、给朋友/家人展示收藏。把"离线 / 弱网"这个真实场景从"打不开"升级为"翻得动"，对核心使用频率的提升是数量级。
2. **降低主屏心智成本**。当前要进 TrailSnap 需要"打开浏览器 → 翻书签或输域名 → 等首屏"，**平均 8-15 秒**。PWA 安装后是 1 秒启动、全屏沉浸、图标在主屏显眼位置——这跟原生 App 的差距会非常小。
3. **为 Issue #45/#44/#48 等 AI/canvas 重型特性做基础**。朋友圈九宫格、自动旅行日志、智能相册推荐都涉及**先离线展示已渲染过的图、再在线拉 AI 结果**。PWA 的缓存层是这些特性的"地面"，先把地面修好再盖楼。
4. **与既有 5 个特性正向叠加**：
   - **HomePage OnThisDay / HeatmapSection**（`HomePage.vue`）：离线时直接出今天往年的旧照片——这是 PWA 最具"惊喜感"的场景之一。
   - **位置相册 `LocationList.vue` / `LocationMap.vue`**（合计 ~60KB 重组件）：地图瓦片缓存后，旅行中没信号也能展示上次到过的城市。
   - **AI Agent `AgentChat.vue`**：对话历史走 PWA 缓存，重新打开 App 不丢上下文（注意：仅 UI 历史，AI 推理结果走 NetworkFirst 不缓存）。
   - **智能相册 `AlbumList.vue`**：相册封面缩略图全部缓存，离线时整页秒开。
   - **Lightbox `PhotoLightbox.vue`**（关联昨天的 Issue #70 提案）：用户翻过的照片原图按 SWR 策略本地化，离线点开不转圈。
5. **可观测、可回滚**。SW 升级策略出问题只需要在 `vite.config.js` 把 `registerType: 'autoUpdate'` 改成 `'prompt'`，用户全部走旧版不影响。`workbox.runtimeCaching` 的每条规则都能在 DevTools 的 Application/Service Workers 面板里直接看到命中数和过期时间。
6. **零后端改造**。整个改动纯前端 + 一个 `public/` 图标资源，**不调一次后端 API**。`/api/medias/file/...` 的 Cache-Control 头由 nginx 控制即可（`location ~ ^/api/medias/file/` 段加 `Cache-Control: public, max-age=604800`，参考已有的 frontend nginx 配置）。
7. **和主题系统天然兼容**。`useTheme` 已经覆盖了 5 套主题，PWA 的 `theme_color` meta 通过一行 watcher 跟随，比从零设计"深色/浅色启动屏"省一周工作量。

## 功能细节

### 页面描述

#### A. `InstallPrompt.vue`（新增，~80 行）—— 顶部安装横幅

`src/components/InstallPrompt.vue` 用 `useInstallPrompt` composable 监听浏览器的 `beforeinstallprompt` 事件。组件渲染条件：

- 用户在桌面端（视宽 ≥ 768px）：**不展示**——桌面用户走地址栏安装按钮更合适。
- 用户在移动端 / 平板：展示条件 = `beforeinstallprompt` 已触发 + 用户**未在 localStorage 标记过「已关闭」** + 上次关闭距今 ≥ 30 天（避免反复打扰）+ 不是 PWA 模式启动（`display-mode: standalone` 媒体查询）。
- 触发时机：首屏加载完成 + 用户至少滚动过 200px（证明不是误触进入）。

UI 形态：**顶部 56px 横条**，背景 `bg-primary-500`（跟随当前主题色），文字白色，关闭按钮右上角。布局：

```
┌─────────────────────────────────────────────────┐
│ [icon]  把 TrailSnap 添加到主屏幕     [添加] [×]│
└─────────────────────────────────────────────────┘
```

文案不出现"安装"二字（避免诱导），用"添加到主屏幕"——**遵循系统原生 iOS Safari 的同款措辞**。"添加"按钮触发 `prompt.prompt()`，根据 `userChoice` 写 localStorage 标记（`pwa-install-dismissed-at`），不再展示。`flex items-center gap-3 px-4 py-2`，进入动画 `transition-transform translate-y-0` ← `translate-y-[-100%]`。

#### B. `PwaUpdateToast.vue`（新增，~50 行）—— 右下角更新提示

`src/components/PwaUpdateToast.vue` 用 `usePwaUpdate` composable 监听 `vite-plugin-pwa` 提供的 `onNeedRefresh()` 回调。组件固定在右下角（`fixed bottom-6 right-6 z-50`），卡片样式：

- 背景 `bg-white dark:bg-gray-800`（**不**用 `bg-primary-*`——避免与 FAB 助手按钮抢色）。
- 左边图标：`Mingcute refresh-line`。
- 主文案："新版本已就绪"
- 副文案："点击刷新以体验新功能"（暗色下用 `text-gray-400 dark:text-gray-500`）
- 按钮：`bg-primary-500 hover:bg-primary-600 text-white` 的"刷新"，右侧文本按钮"稍后"。

点击"刷新"调 `updateServiceWorker(true)` 触发 `skipWaiting + clientsClaim`，整页 reload。点击"稍后"或 30 秒不动：自动收起。**注意**：与已有的"Agent 助手 FAB"（`MainLayout.vue` L28-37）位置不冲突——FAB 在 `right-6 bottom-6`，更新 toast 临时出现时 FAB 自动 `v-show="false"` 200ms，互相避让。

#### C. `OfflineIndicator.vue`（新增，~30 行）—— NavBar 离线状态点

`src/components/OfflineIndicator.vue` 用 `useOnline()` 监听 `online/offline` 事件。组件挂在 `NavBar.vue` 右侧用户菜单之前：

- 在线：渲染一个 `w-2 h-2 rounded-full bg-emerald-500` 绿点 + hover tooltip "已连接到 TrailSnap 服务"（绿点是 `tailwind.config.js` 里独立 token，**不**走 `bg-primary-*`——状态色按设计规范就该是固定的语义色）。
- 离线：换成 `bg-amber-500` 橙点 + tooltip "离线浏览中（仅显示已缓存照片）"，并把 `aria-live="polite"` 给屏幕阅读器播报。

不弹模态、不打断用户。`transition-opacity duration-200`，点消失/出现。

#### D. `OfflinePage.vue`（新增，~120 行）—— 路由兜底

`src/views/OfflinePage.vue` 对应 `router/index.ts` 里新加的 `{ path: '/offline', name: 'Offline', component: OfflinePage, meta: { layout: 'blank' } }`。这个页面的作用是 SW 在 `navigateFallback` 时回退的占位页——**不是给用户主动访问的**，而是 SW 拦截到未知路由 + 离线时回退的目标。内容：

- 顶部 `Mingcute wifi-off-line` 大图标（`text-6xl text-gray-400 dark:text-gray-500`）。
- 标题 "您当前处于离线状态"（`text-2xl font-semibold text-gray-700 dark:text-gray-200`）。
- 副标题 "已缓存的照片仍可继续浏览"（`text-sm text-gray-500 dark:text-gray-400`）。
- 主按钮 "返回首页"（`bg-primary-500 hover:bg-primary-600`）→ `router.push('/')`。
- 底部小字 "TrailSnap 会在网络恢复后自动同步"。

`vite.config.js` 里 `workbox.navigateFallback: '/offline'` 指向这个页面。**注意**：`navigateFallbackDenylist` 必须显式加上 `/api/`、`/medias/`、`/tokens/`，否则 API 404 也会被错误地回退到 `/offline`。

#### E. `useInstallPrompt.ts` / `usePwaUpdate.ts`（新增 composable，合计 ~100 行）

- `useInstallPrompt()`：在 `main.ts` 里统一 `window.addEventListener('beforeinstallprompt', ...)` 缓存到 `ref<BeforeInstallPromptEvent | null>`，提供 `canInstall` / `prompt()` / `dismiss()`。**不要每个组件单独监听事件**——Chrome 一个会话只触发一次，多个 listener 会导致"用户点关闭后又出现"的诡异 bug。
- `usePwaUpdate()`：封装 `vite-plugin-pwa` 暴露的 `useRegisterSW({ onNeedRefresh, onOfflineReady })`，暴露 `needRefresh`（ref boolean）和 `update()`（action）。这样 `PwaUpdateToast.vue` 只关心 UI，composable 处理 SW 通信。

#### F. `main.ts` 里的主题色同步（新增 ~10 行）

```ts
import { provideTheme, themeColors } from '@/composables/useTheme';

const theme = provideTheme();

// 同步 theme-color meta 到当前主题
const updateThemeColor = () => {
  const meta = document.getElementById('theme-color-meta') as HTMLMetaElement | null;
  if (meta) meta.content = theme.currentTheme.value.primary;
};
watch(() => theme.currentTheme.value.primary, updateThemeColor, { immediate: true });
```

`index.html` 加：

### 页面风格

**与现有 5 套主题完全打通**。本提案没有引入任何新的设计 token：

- 安装横幅：背景 `bg-primary-500`、文字白色。`primary-500` 在 `useTheme.ts` 里随当前主题切换（sky=蓝、emerald=绿、violet=紫、rose=红、amber=橘），同一份代码 5 套主题下都自洽。
- 更新 toast：背景 `bg-white dark:bg-gray-800`、按钮 `bg-primary-500`——这与 `MainLayout.vue` 的 FAB `bg-primary-600` 形成层级（toast 用 500、FAB 用 600）。
- 离线指示点：用 **emerald-500**（在线）和 **amber-500**（离线）——这是语义色，**不**走主题色，与 `StatsPage.vue` 等数据面板里的"成功/警告"色完全一致。
- 离线兜底页：图标 `text-gray-400`、标题 `text-gray-700`、副标题 `text-gray-500`——遵守 AGENTS.md 里"**一个组件只用一套灰色族**"的规则，全用 `gray-*`。
- 焦点环：所有按钮加 `focus-visible:ring-2 focus-visible:ring-primary-500 focus-visible:ring-offset-2 focus-visible:outline-none`——和项目规范一致，环颜色自动跟随主题。

**字体/排版**：

- 横幅与 toast 用项目全局的 `font-sans`（`MainLayout.vue` 根 div 已是 `font-sans`），不引入新字体。

### 落地节奏（建议拆 3 个 PR）

1. **PR1: PWA 基线**（预计 1-2 天）

   - 不挂任何 UI 组件，只验证 `chrome://flags/#installable-apps` 能识别、`localhost:5176` 离线模式能看到缓存命中。
2. **PR2: 安装提示 + 更新 toast + 离线指示器**（预计 1 天）
   - `InstallPrompt.vue` / `PwaUpdateToast.vue` / `OfflineIndicator.vue` + 2 个 composable + `main.ts` 主题色同步。

3. **PR3: 离线兜底页 + Workbox 缓存矩阵**（预计 1 天）
   - `OfflinePage.vue` + 路由 + `workbox.runtimeCaching` 完整规则 + `navigateFallbackDenylist`。
   - Playwright e2e 加一条 `test:e2e` 用例：访问首页 → 关闭网络 → 刷新 → 断言显示离线兜底页 + 已访问过的相册仍可点开。
