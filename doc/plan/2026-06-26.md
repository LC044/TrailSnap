# 批量导出照片：自定义命名模板 + ZIP 打包

> 对应 GitHub Issue [#72](https://github.com/LC044/TrailSnap/issues/72)「批量导出照片：支持自定义命名模板」。
> 现状是「零批量导出能力」：`PhotoLightbox.vue` 的 `downloadImage` 只支持单张（`/api/medias/{id}/file`），工具箱 6 个工具全是「在原位上做文章」（重命名 / 整理 / 清理 / 相似 / 重复 / 时间戳），**没有任何工具把「选中的 N 张照片导出到任意目录 / 打成 ZIP」**这件事包起来。而这恰恰是任何自托管照片库的标配出口——用户买 NAS 装 TrailSnap 跑了一年，年终想把 1,200 张精选照片发给打印店、放进礼物 U 盘、做家庭分享，**全靠单张点击**。这条 issue 跟 #70（灯箱快捷键）、#73（位置编辑）、#74（任务通知）同级别，是「一个原生交互位置」级别的修复。

## 功能描述

把「选 → 配 → 跑 → 取」4 步串成一个新工具 `toolbox/ExportPage.vue`，复用既有的「多选 + 后台任务 + 进度条 + 通知」骨架，让用户能把任意筛选条件下的照片集合（相册详情 / 位置详情 / 人物详情 / 搜索结果 / 全部照片）一键导出为带规则命名的 ZIP 或目录树。

1. **统一的「导出」入口**。在以下 5 个高频多选位置（`selectionStore` 已有 `selectedPhotos` 数组）底部加一个 `el-affix` 工具条，里面 3 个按钮「批量打标签」「批量加入相册」「**批量导出**」（新增第三个，绿色 `Download` 图标 + 主题色 `bg-primary-500`）。
   - `views/PhotosPage.vue`（全部照片）
   - `views/album/AlbumDetail.vue` / `views/album/location/LocationDetail.vue` / `views/album/people/PeopleDetail.vue`（各类详情页）
   - `views/search/SearchResult.vue`（搜索结果）
   - `components/PhotoGallery.vue` / `components/FlatPhotoGallery.vue`（被复用的瀑布流 / 网格视图容器，工具条作为 slot 子组件插进去）
   工具条在 `selectionStore.selectedPhotos.length > 0` 时 `el-affix` 钉在视口底部中央（`position: fixed; bottom: 24px; left: 50%; transform: translateX(-50%)`），显示「已选 N 张 · 总大小 X MB」+ 三个按钮 + 关闭清空按钮。点「批量导出」→ 路由跳 `/toolbox/export?ids=...&from=albumDetail` 并把选中的 id 列表 + 来源 route name 写进 Pinia。
2. **导出配置页 `views/toolbox/ExportPage.vue`**（与 `RenamePage.vue` / `OrganizePage.vue` 同模板），左右两栏：
   - 左栏 560px：模板编辑器 + 实时预览。
     - `命名模板` 输入框（默认 `{date}_{city}_{index}`），下方一行小标签展示可用变量（`{date}` `{time}` `{year}` `{month}` `{day}` `{city}` `{location}` `{album}` `{tag}` `{original}` `{index}` `{sequence3}` `{sequence4}`），点击变量 chip 自动插入到模板末尾。
     - `起始序号` 数字输入框（默认 1）+ `序号位数` 单选（2 / 3 / 4 / 不补零）。
     - `日期格式` 下拉：`YYYYMMDD` / `YYYY-MM-DD` / `YYYY年MM月DD日` / 留空使用 EXIF 拍摄日期（无则回落到文件 mtime）。
     - `导出范围` 单选：仅导出当前选中 N 张 / 当前筛选条件下全部（额外弹一次确认，显示「额外加载 1,234 张到任务，预计耗时 X 秒」）。
     - `输出格式` 单选：原始质量（直接打包源文件）/ 压缩（统一 1920px 长边、JPEG quality 85，新增「宽度」滑块 1280–3840）。
     - `EXIF 保留` 开关：默认开，关闭时连同 orientation 一并去除（适合朋友圈发布）。
     - `输出方式` 单选：**ZIP 压缩包**（默认 streaming 下载）/ **解压到指定目录**（填绝对路径，调用新的 `POST /api/photos/export/directory`，需要 server 进程对目标路径有写权限）。
     - `ZIP 体积上限` 数字输入（默认 2048 MB，超出自动分包为 `TrailSnap_export_part1.zip` `part2.zip` …）。
   - 右栏 `flex-1`：实时预览面板。前 12 张选中照片的「原文件名 → 导出名」映射表（两列等宽字体显示，超长 truncate + title 悬浮），底部「总计 1,200 张 · 预计 ZIP 体积 ≈ 856 MB（按平均每张 700 KB 估算）」。
   - 顶部固定条：返回 + 标题「批量导出」+ 副标题「将 1,200 张照片按 `…` 模板打包」+ 右侧「开始导出」主按钮。
3. **后台任务 `TaskType.EXPORT`**。新增 `app/service/tasks/export.py` handler，行为：
   - 启动：校验 id 列表 → 解析模板（正则 `{(\w+)(?::(\d+))?}` 支持 `{sequence:3}` 这种带位数的简写）→ 异步打开 `zipfile.ZipFile`（`mode='w'`, `compression=ZIP_DEFLATED`, `compresslevel=6`）写到 `data/cache/exports/{task_id}.zip`。
   - 循环：每张照片 `await asyncio.to_thread(process_one_photo, photo_id, template_ctx)`，`processed_items += 1` 推 SSE（接昨天 #74 提的任务通知 SSE 通道，自动免费拿到顶栏铃铛 + 系统通知）。
   - 失败处理：单张读不到 / 模板变量解析失败 → 不阻塞整批，记入 `task.error` 数组「`[failed] photo_123.jpg: city 字段为空`」；批次整体 5% 失败阈值时中止并 rollback。
   - 结束：`status=completed` + `output_path=...zip` + `download_url=/api/photos/export/{task_id}/download`（一次性签名 token，30 分钟有效）。
4. **下载闭环**。任务完成后：
   - 站内 `ElNotification` 弹「导出完成 · 1,200 张 · 856 MB」，按钮「立即下载」/「在文件夹中显示」（后者用浏览器 `navigator.userAgent` 解析后展示对应说明，因为 web 没 API 真的打开资源管理器）。
   - 工具箱首页 `ToolboxPage.vue` 的「最近导出」卡片（新增 60px 小区块，显示最近 5 次 completed export 的文件名 + 大小 + 倒计时「剩余 28 分钟」+ 下载按钮），过期后变灰「已过期」并提供「重新导出」一键重跑（参数模板全部回填）。
   - 铃铛未读通知（接 #74 任务通知系统）：`export` category 完成时弹系统级通知（移动端 PWA 用户 `#69` 直接进手机通知中心）。
5. **小细节**：
   - 模板编辑器旁加「保存为预设」/「加载预设」按钮，预存取 `localStorage` 的 `exportTemplatePresets[]`，最多 10 条。
   - 后端在 `export_photos` 开头加一道 `dry_run=true` 路径：返回「将导出 1,200 张 · 预计 856 MB · 前 5 张样例名」JSON 供前端实时预览用，前端在用户每次改模板时 `debounce(300ms)` 触发，无需真正打包。
   - `TaskManagement.vue` 顶部加一个「导出」tab 分类筛选，复用 `grouped_status` 视图，不动现有代码。

## 功能价值

1. **填补零能力空缺，闭环核心使用场景**。TrailSnap 已经是「AI 人脸 / OCR / 车票 / 位置 / 智能分类」一应俱全的完整照片库，但「怎么把照片拿出来」只有 `PhotoLightbox` 顶上的「下载单张」一个按钮——这等于一个冰箱能装能冻能显示温度，但没有门让你拿东西。批量导出是这个冰箱的**门**。
2. **复用 4 套已有基建，零新依赖**。
   - 后台任务：`TaskManager.get_instance()` + `app/service/tasks/` handler 注册（`export.py` 加一个文件 + `__init__.py` 加一行注册，跟 `rename.py` `metadata.py` 完全同构）。
   - 进度 / 通知：直接接昨天 `#74` 提的 SSE 通道 + 顶栏铃铛，免费拿到「用户不用守着看」的体验。
   - 多选：`stores/selectionStore.ts` 已有 `selectedPhotos` / `clearSelection()`。
   - 压缩：`zipfile` 是 Python 标准库；图片压缩用 `Pillow`（`package/server/pyproject.toml` 已有，PaddleOCR / InsightFace 依赖链带入）。
3. **模板化命名是真痛点**。Issue #72 的 issue 描述里点名了 `{date}_{city}_{index}` 模式，这是把「2024-03-15_京都_001.jpg」直接交给打印店 / 朋友圈的关键——TrailSnap 数据库里既有 `taken_at` 又有 `location_id → location.name`（`MapContainer.vue` 已能反查），把这俩 join 一下出文件名是边际成本极低的活儿。
4. **「解压到指定目录」是自托管杀手锏**。本地 NAS 用户最烦的就是「先下载 2 GB ZIP 到浏览器默认下载目录 → 再右键解压到 NAS」的两步操作；如果支持直接解压到 NAS 上挂载的 `/Photos/Exports/2024/`，等于「在 TrailSnap 里点一个按钮、文件就出现在 NAS 文件管理器里」。这是把 TrailSnap 从「网页应用」拉向「原生 NAS 工具」的一步。
5. **不增加「AI 黑盒」复杂度**。本提案 100% 是 IO + 模板渲染 + 打包，跟 PaddleOCR / InsightFace / CLIP 没有任何耦合，GPU 不需要，CI 资源占用几乎为零（不触碰 `构建后端` / `构建前端` 触发关键词即可绕过 Docker build），适合作为「中优先级实用工具类功能」独立发版。
6. **导出可作为「年度回忆录」的数据出口**。`views/annual-report/index.vue` 现在是「在网页里看」，导出后用户可以 PDF 打印做成实体相册，闭环又一项付费意愿。
7. **CLI 联动**。`package/trailsnap-cli/` 现有 `export` 子命令只导「元数据 + 缩略图」，本提案可以新增 `trailsnap-cli export-photos --template '{date}_{city}_{index}'` 子命令（直接复调后端 `POST /api/photos/export`），让自动化脚本 / 第三方 agent 也能触发导出。CLI 跟 Web 是同一个能力池。

## 功能细节

### 页面描述

`/toolbox/export` 页面（新增 `views/toolbox/ExportPage.vue`）是一个 **左 560 / 右 flex-1 的双栏布局**，顶部 64px 固定 header（`bg-white dark:bg-slate-900 border-b border-slate-200 dark:border-slate-800`），左下是模板配置卡，右下是实时预览列表，最底部 80px 固定 footer（`bg-white dark:bg-slate-900` + 边框 + 「开始导出」主按钮）。

**左栏（模板配置）** 560px 宽，`bg-white dark:bg-slate-900` 圆角 `rounded-xl shadow-sm border border-slate-200 dark:border-slate-800`：

- **模板输入区**（顶部 96px 高）：左上是 `el-input` 标签「命名模板（不含后缀）」+ 提示文字「支持变量，可拖入下方标签」；右上是「预设」下拉（`el-select` filterable），含「+ 保存当前为预设」按钮。
- **可用变量 chips 区**（横向滚动条，48px 高）：每个变量是 `el-tag` 圆角胶囊（size small，type info），点击插入到模板光标处。变量：`{date}` `{time}` `{year}` `{month}` `{day}` `{hour}` `{minute}` `{city}` `{location}` `{album}` `{tag}` `{original}` `{index}` `{sequence3}` `{sequence4}` `{camera}` `{lens}` `{iso}`。
- **配置区**（剩余高度，`el-form` label-position=top）：
  - 起始序号 + 序号位数（2 个 el-input-number 横排）
  - 日期格式（el-select，4 个选项 + 自定义 strftime）
  - 导出范围（el-radio-group，2 个选项 + 提示气泡）
  - 输出格式（el-radio-group，原始 / 压缩，压缩展开 width 滑块 1280–3840）
  - EXIF 保留（el-switch，默认 true，关闭弹「将去除所有元数据」确认）
  - 输出方式（el-radio-group，ZIP / 解压到目录，后者展开 el-input 绝对路径 + 「浏览」按钮调 `FolderSelectionDialog`）
  - ZIP 体积上限（el-input-number，单位 MB，默认 2048，超出说明「将自动分包」）

**右栏（实时预览）** flex-1，`bg-white dark:bg-slate-900` 圆角同左栏，padding 16px：

- 顶部 56px 固定条：左侧「前 12 张预览（共 1,200 张 · 预计 856 MB）」+ 右侧「展开全部」开关（开 → 全 1,200 张 virtual scroll 列表）。
- 列表项 40px 高，左右两列等宽：左列等宽字体显示原文件名（`text-slate-500 dark:text-slate-400 truncate`），中间 `→` icon，右列等宽字体显示导出名（`text-slate-800 dark:text-slate-200 truncate`）。hover 整行高亮 `bg-slate-50 dark:bg-slate-800/60`。
- 底部 32px 提示行：`text-xs text-slate-400`，例如「`{city}` 在 87 张照片中无值，将使用 'unknown'」。

**底部 footer** 80px 高，flex 布局：左侧「取消」次按钮（`el-button` plain），右侧「开始导出」主按钮（`el-button` type=primary，size large，左侧 `Download` icon）。按钮在模板为空 / 选中 0 张时 disabled。

**`PhotoGallery.vue` 工具条组件**（新增 `components/SelectionActionBar.vue`）是一个 `el-affix` 包裹的浮岛，position fixed bottom-6 left-1/2 transform -translate-x-1/2，宽度 auto、padding 12px 16px，圆角 `rounded-full shadow-2xl`，背景 `bg-white/95 dark:bg-slate-800/95 backdrop-blur`，内含 `已选 N 张 · 总大小 X MB` + 「批量打标签」+「批量加入相册」+「批量导出」三个按钮 + `X` 关闭按钮。仅在 `selectionStore.selectedPhotos.length > 0` 时渲染（用 `<Transition>` 做出现 / 消失动画）。

**`ToolboxPage.vue` 新增卡片**「最近导出」（与现有 6 个工具卡片同 grid 布局，1×1 大小，绿色 `Download` 图标背景 `bg-green-100 dark:bg-green-900/30 text-green-500`），hover 展开 60px 子区块显示最近 5 次导出条目。

### 页面风格

- **整体配色**：跟随主题（`useTheme` 的 5 套主色）。主按钮「开始导出」用 `bg-primary-500 hover:bg-primary-600 text-white`，强调绿色仅用于「最近导出」卡片的图标背景（突出「下载完成」的语义信号，与主操作色区分）。
- **变量 chip 样式**：`el-tag` type=info，size=small，圆角 `rounded-full`，hover 时变 `bg-primary-500/10 text-primary-600 dark:text-primary-400 border-primary-500/30`，点击时给 100ms scale-95 反馈。
- **变量渲染失败的兜底**：模板里出现未定义变量时，编辑器边框变 `border-amber-400`，下方提示「变量 `{foo}` 不支持，可选：…」；预览对应行导出名显示为 `error_unknown.jpg`（红色高亮 + tooltip 解释）。
- **预览区字体**：导出名 / 原文件名都用 `font-mono text-sm`，等宽对齐；`{index}` 序号 0 补齐到 3 位时显示为 `001` `002`（与相机 DCF 命名习惯一致）。
- **进度反馈**：任务跑起来后，左栏整体 opacity-50 + 顶部叠一层半透明 `el-skeleton`，footer 按钮变成「导出中 · 234/1200 · 取消」三段式。
- **任务完成后**：「开始导出」按钮位置弹出 `el-result`（status=success，title=「导出完成 1,200 张 · 856 MB」），下方两个按钮「立即下载」+「再导一次」。
- **空状态**：未选中任何照片直接进入 `/toolbox/export`（可能由收藏夹 → 批量导出按钮进来），右栏居中显示 `PackageOpen` 图标（48px、`text-slate-300`）+ 「请先在照片列表里选择要导出的照片」+ 「去全部照片」按钮（路由 `/photos`）。
- **过渡动画**：变量 chip 插入用 `<TransitionGroup>` name=chip，duration 150ms；预览列表项用 `<TransitionGroup>` name=preview，新增时 `opacity-0 translate-x-2` → `opacity-100 translate-x-0`（180ms），删除时反向。
- **可访问性**：所有 el-form-item 必填项 label 前加红 `*`；「开始导出」按钮 `aria-label="开始批量导出 1200 张照片"`；预览列表用 `role="list"` + 每行 `role="listitem"`；变量 chip 按钮加 `aria-label="插入变量 date 到模板末尾"`。
- **响应式**：< 1024px 时左 / 右两栏自动堆叠为单列（顺序：模板配置 → 预览），footer 按钮全宽。

### 后端实现要点

- 新增 `app/api/photo.py` 末尾端点：
  - `POST /api/photos/export` body `{ photo_ids: [int], template: str, options: { output: 'zip'|'dir', target_path?: str, start_index: int, sequence_digits: int, date_format: str, quality: 'original'|'compressed', width?: int, keep_exif: bool, zip_max_mb: number, dry_run: bool } }` → 返回 `{ task_id: int, estimated_count, estimated_size_mb, samples: [{original, exported}] }`（dry_run 模式）或 `{ task_id, status: 'pending' }`。
  - `GET /api/photos/export/{task_id}/download?token=...` → `FileResponse` 流式返回 ZIP，`Content-Disposition: attachment; filename=TrailSnap_export_{date}.zip`，token 是后端 `secrets.token_urlsafe(16)` + 30 分钟 TTL（写 `data/cache/export_tokens.json`，过期清理）。
  - `GET /api/photos/export/recent` → 返回最近 5 次 `completed` export 摘要。
- 新增 `app/service/tasks/export.py` handler，注册到 `TaskType.EXPORT`，调用链路：`TaskManager.update_task_status` → 现有 SSE 推送钩子（接 #74）→ 顶栏铃铛免费消费。
- 模板解析：正则 `r'\{(\w+)(?::(\d+))?\}'`，未知变量抛 `TemplateError`，handler 捕获后写 `task.error`。
- 图片压缩：`Pillow` `Image.thumbnail((width, width*10), Image.LANCZOS)` + `save(buffer, 'JPEG', quality=85, optimize=True)`，exif 透传用 `piexif`（已依赖）。
- 大文件流式：`zipfile.ZipFile` 配合 `StreamingZipGenerator`（自写 generator，`yield` 4 MB chunk），FastAPI 用 `StreamingResponse(generator, media_type='application/zip')`。
- 权限：解压到目录模式要求 `target_path` 必须在 `data/.env` 的 `ALLOWED_EXPORT_DIRS` 白名单内（防任意写盘），用户配置里新增 `Settings → 存储` 子页。
- 性能：1,200 张 4 MB 照片 ≈ 4.8 GB，压缩到 856 MB 约 5 分钟；用 `asyncio.to_thread` 把 CPU 重活（压缩 / 写入）丢到默认 executor，主循环只 await。
- 限速：每个用户同时只能跑 1 个 `EXPORT` 任务（`TaskManager` 现有 per-user 并发检查已够用）。

### 验收标准

1. 在 `PhotosPage` 选中 5 张照片 → 点击「批量导出」→ 跳到 `/toolbox/export` → 模板输入 `{date}_{city}_{index}` → 实时预览显示 5 个「原名 → 导出名」映射 → 「开始导出」→ 进度条 5/5 → 完成后弹「立即下载」+ 「最近导出」卡显示这条记录。
2. 选中 1,200 张照片（mock 测）→ 「ZIP 体积上限」= 100 → 任务结束后下载得到 12 个分卷 zip。
