# 可编辑 CLIP 分类（首版）

入口为「智能分类 → 分类规则」。原 YOLO 分类继续运行；CLIP 根据描述独立追加标签，一张照片可以属于多个分类，也可以不命中任何分类。

## 目录和使用

默认目录 v2 包含 11 个一级分组、173 个独立二级分类，每个默认类别只归属一个分组。「机场」「车站」「站台」归入交通出行，「聚餐」归入活动 / 事件。预设首次创建时全部启用，可按组或单独关闭。新建并启用、从停用改为启用时自动扫描全库。全部类别可通过「更新历史照片」执行，编辑已有类别时可直接点击「重新分类此类别」，或保存时勾选更新历史照片。

默认目录用于初始化缺少的预设。已经初始化的名称、分组、描述和阈值保存在用户数据库中，需要通过分类规则编辑入口更新已有规则。目录升级保留继续使用类别的 preset key，新类别分配新的 key，移除的 key 留空。

每个分类包含名称、展示分组、1～5 条短描述、严格程度、各模型阈值和自动分类开关。描述各自表达同一个类别的典型画面。预览展示命中照片和阈值附近的照片，不写入照片标签。预览默认检查按照片 ID 排序的前 1,000 张兼容照片，API 上限 5,000 张，也可传入最多 50 个照片 ID；这不是随机抽样或全图库统计。

编辑描述、严格程度或阈值后生成不可变规则版本；改名和分组维持原标签 ID。关闭规则停止后续自动分类，已有结果仍保留；删除规则移除该 CLIP 类别的全部可见关联（含人工保留），保留独立的 YOLO 和自定义标签。首次使用支持本功能的服务时需要运行数据库迁移，并同时升级 AI 服务。

## 计算和任务

分别归一化每条描述的向量，取平均后再次归一化，形成一个类别原型。归一化图片向量与原型的点积为余弦相似度。各类别独立与自身阈值比较，不做跨类别 softmax；相似度不作为概率展示。标准使用默认阈值，宽松减 0.025，严格加 0.025。

使用当前选择的 embedding 模型，仅复用 `ImageVector.model_name` 一致的图片向量。历史回算开始时读取一次所选模型的 runtimeName，并随分页与照片任务传递。单张照片任务直接复用任务指定模型，旧任务使用图片向量记录的模型名。文本请求指定相同模型并复用按模型名缓存的描述向量。逐张分类不查询 AI 模型目录。AI 服务在文本编码时使用同一模型，拒绝模型不匹配与超出模型 token 上限的描述。预览与分类优先使用当前模型专用阈值，缺少时统一采用基础阈值 0.42，再叠加严格程度调整。

`CLASSIFY_IMAGE_CLIP` 是独立、可追踪的 AI 任务，在后台任务列表紧随图片特征提取，优先级依次为 YOLO 10、embedding 9、CLIP 8、人脸 7。分类拥有独立资源槽（并发 1），调度每批 256 张、预取上限 512 张；历史回算按 1,024 张分页生成任务。同一照片的待执行任务合并当前规则版本，embedding 批次结束后一次读取规则及待处理任务，再为每张成功照片创建分类任务。缺少兼容图片向量时提交提取任务并立即释放 worker，图片向量完成后接续分类。每次任务重新计算其指定的有效规则，命中时写入照片分类关联，未命中时清理旧关联，人工保留/排除优先；不保存逐照片逐类别的正负结果，也不在照片 JSON 中记录各类别完成情况。重试可重复计算，关联更新保持幂等，执行状态由任务系统记录。CLIP 不触发票据识别，YOLO 原有流程保留。

文本原型缓存在服务进程内，键包含 AI 服务、模型名称、描述和聚合算法。冷缓存批量编码描述。同一用户批量读取图片向量和规则，以矩阵乘法计算图文相似度；统一读取人工决定与关联，按批新增、更新、删除结果。发布时先按顺序锁照片，再锁分类并重读版本，拒绝已删除、停用或版本过期的任务。SQLite 在计算后结束读取事务，再以 BEGIN IMMEDIATE 进入短写事务；临时表使用内存以避免依赖系统临时目录。

## 数据与接口

预设初始化完成状态按数据库引擎实例、用户 ID 和目录版本在进程内缓存，每个引擎最多保留 4,096 个最近使用项。事务成功提交后才发布完成状态，回滚或关闭会话时清除待发布状态，保存点提交继续等待外层提交。缓存命中时跳过预设 key 查询，进程重启、缓存淘汰或目录版本变化后重新检查数据库。

用户注册和应用启动时延迟初始化预设。首次图片向量完成、分类历史总任务执行或用户主动打开规则管理时，批量补齐缺失预设。PostgreSQL 锁定用户行，SQLite 通过事务内无操作更新预留写锁，获得锁后重新检查预设。已有关闭、删除和编辑状态保留。初始化事务结束后再执行文本推理。同服务地址和模型的文本原型冷缓存生成使用进程内互斥，其他线程复用完成的结果，失败后释放锁并允许重试。

首次 CLIP 数据库迁移为存在非视频照片的每个用户创建一条历史分类总任务，任务 UUID 由固定命名空间和用户 ID 派生，重复入队保留已有任务状态。迁移仅写任务，运行期加载规则。升级任务等待已有待处理或执行中的图片特征任务结束，再分页生成分类任务并合并待执行照片任务。AI 服务暂不可达、模型准备中或服务返回 502/503/504 时进入自动等待，恢复后继续，等待不消耗推理重试次数。离线迁移 SQL 输出仅包含结构变更，升级任务入队由在线迁移执行。

新增三张表：`clip_categories` 保存用户分类与当前版本；`clip_rule_revisions` 保存不可变规则；`photo_tag_decisions` 保存人工保留或排除。现有 `photo_tag_relations` 继续提供照片查询的可见分类。

CLIP、YOLO 和自定义标签分别使用独立的 `photo_tags.id`，通过现有 `type` 字段区分；同名标签可在不同类型下存在。自动分类仅查找本类型标签，重算只更新自身类别 ID 对应的关联，无需 `photo_tag_evidence`，也不使用 JSON 保存来源。每个默认类别归属一个分组，并拥有独立规则和标签。人工决定优先于自动匹配；新建人工标签使用独立 custom ID；既有人工保留/排除按原类别 ID 生效。

分类列表跳转及详情中的查询、移除、封面设置均传递 `tag_id`，避免同名类别混淆；接口保留未携带 ID 的旧名称入口供旧客户端兼容。删除 CLIP 类别会清理其全部关联并隐藏其标签；再次创建同名类别分配新 ID。规则分组、描述和模型阈值仍用现有 JSON 配置字段，它们不承担来源记录。

切换图片特征模型时，界面提醒重新执行全部照片的 embedding 任务，确保图片与分类描述使用同一个模型。现有切换流程自动创建图片特征重建任务，新向量生成后接续 CLIP 分类。

## 开发图库首轮校准

2026-11-11 对开发库中 30,129 张兼容 `chinese-clip-ViT-B-16` 的图片/实况照片向量计算全部类别分数。每类检查前两名和四个候选阈值附近样本，共 1,044 个类别与图片的检查位置，同一图片可能重复出现。视觉判断分为匹配、不匹配和无法确定，不使用模型分数自动充当真值。

阈值按 0.005 网格搜索，试验目标函数为 `4 × 误收数 + 漏收数`；并列时接近原候选阈值。109 类的已检查正负样本支持分离，标记 `reviewed`；65 类正例不足或正负交错，标记 `limited`。两者均仅代表六个选定样本的首轮结果，不代表独立测试集精度、召回率或全图库最优阈值。

「自拍」「体育比赛」「蛋糕」等存在高分误收与低分正例交错，单靠调阈值无法完全解决。「工作中的人」「食材」「短信记录」「银行卡」的当前样本尤其不足。对于此类规则，需要补充代表性标注、改写描述后重新校准。样本覆盖限制保留在校准记录中，界面提示先预览。

预设描述、阈值和逐类校准摘要保存在 `app/service/clip_catalog.json`。个人照片、照片 ID、向量、联系表与逐样本判断仅保留在仓库外的私有验收目录，不进入 Git。

开发者可从 `package/server` 运行 `scripts/calibrate_clip.py`，指定 `--output`、`--data-dir` 生成联系表，`--review-labels` 接收逐类 T/F/U 视觉标注，更新目录并生成汇总。初轮每类 12 张，编号 1～8 用于拟合、9～12 用于验证。完成初轮后，`--refine` 在当前阈值附近追加 6 张拟合样本，标签顺序对应编号 13～18。`--boundary` 保留边界联系表的文件名前缀。个人样本和逐图证据保存在仓库外，`CLIP_DEV_ENV` 指向开发数据库配置。

更换描述或模型后，需要重新计算相似度并生成对应描述的评分清单。类别定义相同时，既有图像的视觉标注可以保留；类别定义变化后需要重新审核。脚本检查类别 key 和描述是否与评分清单一致，拒绝把旧分数直接应用于新描述。
