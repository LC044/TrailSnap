# 上传与手机备份优化验证（2026-10-10）

## 结论与改动

确认存在两个问题：后台任务完成后频繁清空照片缓存再加载，导致整页骨架闪烁；上传请求同步生成缩略图、读取尺寸和 EXIF，后台基本处理又重复执行这些工作，延迟了下一批传输。

- 照片页保留旧列表，统计和已加载月份请求全部成功后一次替换；失败保留当前画面，丢弃过期筛选请求。后台事件合并为约 3 秒一次检查，滚动、选图、查看大图和编辑期间延后更新。
- 上传响应表示原文件已保存并完成完整性校验；缩略图、尺寸、拍摄时间和其他元数据交给后台任务。后台处理完成后补齐照片显示。
- 手动上传在 Worker 内逐块计算 SHA-256，计算完成的块立即上传，用确认额度限制并行分块数量，避免整文件校验形成屏障。
- 手机备份改为有界准备队列：哈希、去重和传输重叠，空闲上传槽立即接收下一文件；公网非计费网络使用双路起步，失败降级，保留在途字节限制。
- Android 文件导出与 MD5 计算移到四线程 I/O 池，避免桥接线程串行执行。
- 分块备份保存上传会话，恢复时查询已提交分块，仅补传缺块；最终检查尺寸、分块数量和文件哈希。单个失败文件不阻塞后续文件和后续分页；失败页之前的检查点保留，下一次备份可以重试。
- 上传队列挂载到应用层，收起窗口或站内切换页面继续上传；提供明确停止操作、全局队列入口和原文件保存/后台整理状态。手机备份保留失败项和失败数量。
- 文件夹扫描消除重复根目录，并避免对子目录重复递归。

## 速度对比

样本来自用户指定的开发环境“手机备份”目录：按完整路径排序选取前 24 张 JPG，加前 6 个大小在 10–35 MB 之间的 MP4，共 30 个文件、142,648,241 字节（142.65 MB）。每组测三轮，每轮上传全部样本，随后逐文件下载原文件检查 SHA-256；共 180 次完整性校验全部通过，下载校验耗时不计入上传时间。

采用同机回环 HTTP、相同数据库和磁盘、4 个文件并发、每文件 2 个分块并发、8 MiB 分块。测试接口使用真实登录、分块上传、合并、完整性校验及数据库保存代码，停止后台调度以隔离 AI 和缩略图任务竞争。客户端使用同一 Python/httpx 脚本，包含读文件与 SHA-256 计算，双方均关闭 HTTP 连接复用并使用相同重试配置。

“优化前”在隔离接口中复现修改前 `save_and_create_photo` 的同步缩略图、尺寸、EXIF 和照片记录保存流程；“优化后”使用当前实现。双方分块路由使用同一版本。因此这项对比主要衡量服务端上传确认路径的改善，不是旧版本完整客户端与新版本完整客户端的端到端对比。

| 指标（三轮中位数） | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 全部原文件保存确认时间 | 11.468 秒 | 1.356 秒 | 缩短 88.2% |
| 有效原文件吞吐量 | 12.44 MB/s | 105.21 MB/s | 8.46 倍 |
| 每轮单文件完成请求耗时的中位数，再取三轮中位数 | 380.23 ms | 41.95 ms | 缩短 89.0% |

| 轮次 | 优化前耗时 / 吞吐 | 优化后耗时 / 吞吐 |
| --- | --- | --- |
| 1 | 12.014 秒 / 11.87 MB/s | 1.935 秒 / 73.73 MB/s |
| 2 | 11.468 秒 / 12.44 MB/s | 1.354 秒 / 105.34 MB/s |
| 3 | 11.009 秒 / 12.96 MB/s | 1.356 秒 / 105.21 MB/s |

MB/s 按十进制计算。结果只覆盖原文件上传、校验、合并和保存确认，后台整理时间不包含在内。手机 Wi-Fi、公网链路、Android 导出和浏览器 Worker 的综合吞吐仍需真机实测，不能把回环 HTTP 数值直接视为手机备份速度。

## 功能验证

以下本地结果来自原开发工作区。提交 PR 时另建工作树提取上传与备份改动，保留其他尚未提交的大图解码、查看器和桌面数据目录工作；独立提交的回归结果以 PR CI 为准。

- 前端单元冒烟：65 项通过；后端照片域单元冒烟：500 项通过。覆盖流式哈希额度、并行队列、失败排空、断点续传缺块恢复、失败文件跨页继续、原文件完整性、扫描去重、无空列表刷新、过期响应丢弃和刷新期间新增月份缓存。
- 前端生产构建通过，保留已有大包警告。
- 手机备份自适应传输 P0 回归：8 项通过；测试服务已按统一脚本关闭。
- 真实浏览器上传 30 个文件：采样 1,112 帧，空照片列表帧 0，整页骨架帧 0。该轮与其他工作争用资源，耗时未用于速度对比。
- 阻塞一个上传分块后收起窗口、切换首页、重新打开队列：上传状态保留，解除阻塞后正常完成。
- 手机视口 390×844：队列可见，无横向溢出；检查浅色和暗色显示。
- 恢复开发环境后台任务后，保留的 30 个优化后样本全部补齐尺寸并生成缩略图。随后清理 `_upload_benchmark` 范围内测试副本与任务；清理前后源目录文件数量和总字节数一致。
- 修改的 Android 插件通过直接 javac 编译。完整 Gradle APK 构建受本机 Java 的 `Unable to establish loopback connection` 错误阻断，尚未验证新 APK 的真机传输。
- 全项目 TypeScript 检查仍有原有 Vue 声明和其他组件错误，不能将生产打包通过等同于全项目类型检查通过。

## 后续验证重点

Android 仍先导出临时文件再构造 Blob；原生直接流式传输可以进一步减少大视频的复制和内存占用。断点会话还可以补充服务端过期清理。应在真实手机上分别测试局域网、公网 Wi-Fi、低带宽和中途断网，确认并发调节、后台整理负载和功耗之间的取舍。
