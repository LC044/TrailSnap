# 猜城市游戏 · 玩法设计文档

> TrailSnap 新增小游戏 —— 「猜照片拍摄城市」
> 状态：**玩法已定稿，尚未进入实现**

## 一、概述

一个类似 Wordle / GeoGuessr 的回忆向小游戏：系统随机选一张用户的旧照片，用户根据照片画面（辅以渐进式拍摄时间提示）猜测照片的拍摄**城市**。

游戏复用 TrailSnap 已有的照片经纬度元数据、城市字段，以及前端的天地图（Tianditu）组件，实现成本低，且与 OnThisDay、年度报告的「回忆杀」调性一致。

## 二、核心玩法

| 维度 | 规则 |
| --- | --- |
| 单局结构 | 单张速答——**一局只考一张照片** |
| 猜测次数 | 最多 **5 次** |
| 判定目标 | 猜**城市**，完全猜中才算成功（非距离分制） |
| 输入方式 | 输入框输入城市名，由**后端处理判定** |
| 提示 | 渐进式拍摄时间提示 + 每次猜错给出「方位 + 距离」反馈 |

## 三、游戏流程

1. **抽题**：后端随机抽取一张符合条件的照片（见「照片筛选规则」）。
2. **展示**：显示照片 + 第 1 级时间提示（**年**）。
3. **用户输入城市名** → 后端判定：
   - **无法识别**（库内、天地图都查不到该城市）→ 提示用户**重新输入**，**不消耗**猜测次数。
   - **识别成功但猜错** → 消耗 1 次机会：
     - 解锁更细的时间提示；
     - 给出「照片实际位置相对用户所猜城市的**方位 + 距离**」反馈（如：实际在你猜测城市的**西北方向约 320km**）。
   - **猜中** → 游戏成功，结束。
4. **次数用尽**：5 次仍未猜中 → 游戏失败，揭晓答案。

## 四、渐进式时间提示节奏

共 5 次猜测，3 级时间提示：

| 猜测轮次 | 时间提示精度 |
| --- | --- |
| 第 1 次猜前 | 年 |
| 第 2 次猜前 | 年-月 |
| 第 3 次起 | 完整日期 |
| 第 4、5 次 | 时间提示已到顶，靠累积的「方位 + 距离」反馈收敛 |

**设计意图**：时间提示帮助玩家锁定**大致年代**，方位 + 距离反馈帮助锁定**地理方向**，两者配合逐步逼近答案。

## 五、照片筛选规则

候选照片需满足：

1. **必须有位置信息**（经纬度），否则无答案。
2. **排除照片数最多的 Top1 城市**——大概率是常住地，没有猜的意义。
3. **优先选拍摄时间在一年以前的照片**（如果有，否则放宽限制），增强回忆感。

> 其他「可猜性」过滤（如排除室内特写、纯人脸合影、票据 OCR 图等难猜照片）后续再优化。

## 六、关键实现要点

- **城市判定**：照片库已有城市字段，答案直接取该字段；判定即「用户输入城市 == 照片城市字段」。
- **城市坐标**：每个城市的坐标提前给定，或调用天地图转换，用于猜错后计算方位 + 距离。
- **后端归一化**：用户手输城市名由后端统一处理识别，识别不了引导用户重输（不扣次数）。

## 七、隐私注意

- 分享 / 未登录场景不要泄露照片的精确地点。
- 注意常住地（Top1 城市）已被排除，降低暴露住址风险。

## 八、前端页面交互设计

### 8.1 页面定位与入口
- 新增独立游戏页，路由 `/game`（或 `/guess`），`meta.layout: 'main'`（保留侧边栏布局）。
- **入口放在首页**：复用 `HomePage.vue` 现成的「年度报告 Banner」范式（`HomePage.vue` L25-42）——一张渐变色卡片（左图标 + 标题 + 副文案，右箭头），放在「那年今日」下方、年度报告 Banner 旁边并列。点击 `router.push('/game')`。
- 主题色统一用 `primary-*` 工具类（跟随用户主题），不硬编码品牌色。

### 8.2 单局界面布局
桌面端左右两栏，移动端上下堆叠：

```
┌──────────────────────┬─────────────────────┐
│                      │  剩余次数 ●●●●●        │
│      照片展示区        │  📅 时间提示：2021年    │
│   (大图，可点开看大图)  │  [ 输入城市名…  ] 猜 │  ← el-autocomplete
│                      │  ─────────────────   │
│                      │  历史猜测反馈列表↓      │
└──────────────────────┴─────────────────────┘
```

### 8.3 关键交互组件

1. **照片展示区**：大图展示，可点开看大图。出图须走脱敏接口，**不暴露 EXIF / 地点**，防作弊。
2. **时间提示条**：渐进式，初始只显示「年」。每次有效猜错后动画展开到更细粒度（年 → 年-月 → 完整日期），给「解锁」正反馈。
3. **城市输入框**：用 Element Plus `el-autocomplete` **自动补全**，候选来自库里出现过的城市；回车提交。判定仍由后端处理；后端返回「无法识别」→ 输入框下方红字提示重新输入，**不消耗次数**（次数圆点不变）。
4. **猜测反馈列表（核心体验）**：每次有效猜错追加一条**纯文字**反馈，含方向 + 距离，可视化「越来越近」：
   ```
   ✗ 你猜：成都   实际在 西北方向 · 约 320km
   ✗ 你猜：西安   实际在 正北方向 · 约 90km   ← 越来越近
   ```
   不配地图 / 罗盘，保持克制、不剧透。
5. **剩余次数指示**：5 个圆点，猜错熄灭一个，直观有压力感。

### 8.4 结算态（成功 / 失败）
- **复用「那年今日」(`OnThisDay.vue`) 的全屏相框样式**（L56-108）：白底相框 + 灰色卡纸边框 + 模糊背景，照片下方信息区展示：
  - **拍摄日期**（对应 `formatDate`）
  - **地点**（省 + 市，对应 `getLocation`）
  - **叙事文案**（对应 `getNarrative`，取 `photo.image_description.narrative`）
- 显示本局用了几次猜中 / 失败结果。
- 「再来一张」按钮，直接抽下一局。
- 实现建议：把相框抽成可复用组件，或直接照搬 `OnThisDay.vue` 全屏态模板。

## 九、待办 / 后续优化

- 照片「可猜性」过滤（结合 CLIP 向量 / 图像分类，优先有风景或地标的户外照片）。
- 是否引入多轮赛制、累计总分、排行榜（当前为单张速答，暂不做）。
- 备选玩法方向（暂未采用）：猜时间、猜人物、渐进提示猜照片。
