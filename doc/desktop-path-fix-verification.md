## 路径规则

Windows 安装包与 ZIP 共用布局生成器：根目录 `TrailSnap.exe`、`instance.json`、`userdata/`、`app/<build-id>/`。默认数据库、模型、照片、日志和配置保存在该实例的 `userdata/` 中。配置发现只依据实际可执行文件所在目录，不读取 AppData 中的旧目录指针，也不接受环境变量指定另一实例根目录。后端进程的路径变量由启动器根据本地配置设置；Docker 服务仍使用原部署配置。

安装包的卸载项、快捷方式和进程清理按安装目录隔离。覆盖安装保留 `instance.json` 和图库；卸载删除程序版本，保留数据、配置和快照。ZIP 与安装包使用同一版本内容计算方式，排除 Cargo 产生的非运行时 DLL。

## 旧版本使用与失败恢复

旧用户先退出旧程序，在新客户端设置中明确选择旧数据目录，预检后复制至独立空文件夹。原库保留，复制不会写入禁用原库的转移标记。移动整个实例目录可保留图库身份；复制为独立实例则生成新身份和密钥。

复制已便携化的图库时，先按源实例解析存储根，再重建目标引用。外部照片选择复制后指向副本内文件；预检正确解码相对路径配置。发布目标前核对记录、文件以及原先可读媒体的抽样内容，并启动实际候选程序验证。

复制后的启动交接由原启动器在销毁旧 Windows Job 后完成，避免新实例随旧实例退出而被终止。候选程序失败会及时返回错误，保留原库。配置缺失且已有图库、数据库丢失、不可用数据盘均拒绝创建替代空库。

升级候选以只读模式验证；失败或未提交事务中断恢复程序与数据库快照。前端显示回滚原因和备份位置，失败版本暂停自动重复下载，后续修复版本仍可自动更新。启动失败界面提供打开数据/日志目录和重启入口；恢复失败则停止启动并显示备份位置。
