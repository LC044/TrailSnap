## 1. 设计目标

用户将提示词和自己的想法交给 Trae、Codex 等外部 AI，即可完成：

1. 查询已有公开需求，整理 Bug、功能建议或设计方案。
2. 通过匿名 HTTP 接口提交需求，不登录、不配置 MCP。
3. 使用提交时获得的单条需求编辑凭证，继续修改自己的需求。
4. 选择代码贡献模式时，克隆仓库、实现与测试，并通过 Fork 提交 PR。

平台不启动外部 AI，不代替用户授权 GitHub，不自动批准需求、合并 PR 或发布版本。

核心原则：公开信息无需凭证；编辑权限属于单条需求；匿名贡献不等于管理员交付权限。

1. 页面标题与说明。
2. 直接反馈：报告 Bug、功能建议、查看进度。
3. 新增“让你的 AI 帮忙”卡片。
4. 交流社群。

AI 卡片线框：

```text
让你的 AI 帮忙
把想法交给 Trae、Codex，帮你整理需求，或实现代码并提交 PR。

[ 整理并提交需求 ] [ 实现并提交 PR ]

无需登录需求平台，也无需配置 MCP。
代码贡献需要你的 AI 具备本地开发和 GitHub 操作能力。
```

交互规则：

- 默认选择“整理并提交需求”；设计方案属于此模式，不再增加第三个平级入口。
- 想法为空时也能复制，生成的提示词要求 AI 先询问用户。

- 不自动收集照片、日志、联系方式或服务器地址。版本等环境信息如需附带，必须可见且由用户选择。
- 内容区域沿用现有设置页宽度，实体卡片、中性底色、主题色主要按钮。
- 复用共享 UI 与 primary-* 或语义 token，支持深色模式；不增加大面积玻璃装饰。
- 窄屏模式选择与按钮允许换行；输入、折叠与复制操作均支持键盘。

### 3.3 本机提交的需求

匿名用户可进入“本机提交的需求”，列表根据本浏览器保存的回执生成。

- 显示编号、标题、状态、提交时间及编辑入口。
- 公开详情查询不携带凭证；进入管理页时再验证编辑权限。
- 不将本地拥有某个需求 ID 当成编辑授权。
- 明确说明“这里只展示本浏览器保存的提交记录，不会自动同步其他设备”。
- 支持导入、导出回执和移除本机记录；移除记录不删除平台需求。
- 不需要建设匿名用户表、设备指纹或服务端匿名账号体系。

## 4. 匿名归属与凭证

### 4.1 归属定义

匿名场景不证明真实身份，而是证明持有编辑能力：

> 持有某条需求的有效编辑凭证，才能编辑该条需求。

昵称、联系方式、IP、User-Agent、设备标识和公开需求编号均不用于认领。

一条匿名需求对应一个独立 edit_token。泄露一条需求的凭证，不应影响其他需求。

### 4.2 凭证存储

- 使用密码学安全随机数，至少 256 bit 熵，例如 secrets.token_urlsafe(32)。
- 服务端仅保存 SHA-256 哈希，采用恒定时间比较。
- 不保存明文到需求正文、环境字段、审计详情、任务参数或公开响应。
- 创建及同凭证幂等重试响应向提交者返回凭证；公开查询永不返回凭证或凭证哈希。
- 编辑能力检查返回 can_edit、编辑限制及版本，不返回管理秘密。
- 默认不设短期过期，方便用户长期保存；提供凭证轮换能力。
- 需求删除、关闭编辑或管理员撤销后，编辑操作被拒绝。

建议新增独立字段 anonymous_edit_token_hash，不复用旧 anonymous_upload_token_hash。
匿名编辑凭证可以授权新增附件；原 upload_token 仅在正文可编辑期间用于上传，不能编辑正文。轮换编辑凭证同时撤销旧上传凭证。

### 4.3 浏览器与 AI 的衔接

管理链接建议形式：

```text
https://feedback.trailsnap.cn/requirements/REQ-123#edit_token=...
```

实际路径按现有路由实现适配，上述为设计约定。

管理页启动顺序：

1. 在第三方脚本与遥测启动前读取 fragment。
2. 通过受控请求头验证凭证与该需求是否匹配。
3. 验证成功后存入本机凭证存储。
4. 持久保存成功后使用 history.replaceState 清除地址栏凭证；失败保留原链接供重试。
5. 验证失败不覆盖已有有效回执，不泄露服务端内部信息。

fragment 不进入常规 HTTP 请求，但仍可能被脚本、截图、浏览器历史或复制泄露，因此不是“安全公开链接”。
管理页禁止第三方分析脚本，配置 CSP、Referrer-Policy: no-referrer，并禁止记录凭证。

浏览器可以先采用独立 localStorage 键保存少量回执。其不防御同源 XSS，必须限制脚本与日志访问。
不得同步到主应用云端设置；主应用和反馈平台不同源，主应用不直接读取平台的本机回执。

AI 回执保存在仓库外的用户私有目录，文件权限限制为当前用户。
只有在环境允许安全持久化时才保存；否则返回私有管理链接，明确告诉用户下载回执。
最终回复只展示公开需求链接；管理链接单独标注为私密，不写入 PR 或 Git 提交。

回执格式建议：

```json
{
  "schema_version": 1,
  "platform_url": "https://feedback.trailsnap.cn",
  "requirement_id": "...",
  "requirement_number": "REQ-123",
  "public_url": "...",
  "edit_token": "...",
  "created_at": "..."
}
```

导入时校验平台域名、格式和大小；不向回执指定的任意地址发送凭证。

### 4.4 丢失、泄露与历史数据

- 丢失凭证且没有其他有效副本时，不能匿名自动恢复。
- 管理员可在独立人工核验后处理争议，不能仅凭相同昵称或联系方式重新发放。
- 持有有效凭证时可轮换，旧凭证立即失效，页面要求保存新回执。
- 管理员可撤销编辑能力，不需要查看凭证明文。
- 历史匿名需求不自动补发或升级上传凭证，避免扩大旧凭证权限。
- 清除浏览器数据和导出回执均提示其后果。

## 5. HTTP 接口设计

沿用平台 code/msg/data 响应封装；公开指南列出真实字段、限制、示例和错误码。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| GET /api/requirements?q=... | 匿名 | 搜索公开需求 |
| GET /api/requirements/number/{number} | 匿名 | 按编号查看 |
| POST /api/requirements | 匿名或登录 | 提交需求；匿名返回编辑回执 |
| GET /api/requirements/{id}/edit-capability | 登录归属或编辑凭证 | 验证编辑能力与版本 |
| PATCH /api/requirements/{id} | 登录归属或编辑凭证 | 修改允许字段 |
| POST /api/requirements/{id}/attachments | 原权限或编辑凭证 | 上传附件 |
| POST /api/requirements/{id}/edit-token/rotate | 编辑凭证 | 轮换当前匿名凭证 |

编辑凭证统一放在 X-Requirement-Edit-Token 请求头，不放查询参数。
本设计不新增匿名撤回、删除、审核、领取任务、修改状态等能力。
附件下载仍遵循现有权限；编辑凭证不自动开放附件、联系方式或日志的私密读取。

PATCH 输入使用白名单模型，并禁止额外字段；匿名编辑允许：

- type、title、description
- current_behavior、expected_behavior、steps_to_reproduce
- severity、product_version、log_text
- 必填 expected_state_version

不允许修改 created_by、visibility、submitter_contact、状态、排期、审核、关联 Issue 或交付字段。
匿名编辑禁止提交 environment；禁止仅依赖前端过滤。
日志可能含敏感信息，提交前提醒 AI 脱敏，且不能因公开正文编辑权限而返回私密日志。

### 5.1 编辑限制与并发

初期沿用现有普通用户编辑状态：

- submitted、needs_information、pending_review：允许编辑。
- triaging：显示处理中，暂不允许编辑，避免分析与修改竞争。
- 其他状态：正文锁定，允许独立追加补充说明，由维护者评估；不自动新建重复需求。

服务端在事务中原子校验 expected_state_version 并更新，不只是读取后比较。
成功修改保存修订、增加内容与状态版本、使旧交付授权失效，并按既有领域规则重跑分析与同步。
needs_information 补充后可回到 submitted，不能直接推进到审核通过或开发中。

错误处理：

- 403：无效、撤销或不属于该需求的凭证。
- 404：需求不存在或已删除。
- 409：版本冲突或状态锁定，附可公开的当前版本与原因。
- 422：字段或内容不合法。
- 429：限流，AI 按 Retry-After 重试，不换 IP 绕过。

版本冲突后 AI 重新读取需求并检查差异，不能直接循环覆盖。
审计显示“匿名提交者凭证编辑”，不宣称识别到具体真人，也不记录秘密。

### 5.2 重试与提交回执可靠性

必须覆盖“服务端提交成功，但客户端未收到响应”的情况，避免重复需求和丢失编辑权。

AI 在创建前本地生成并保存高熵 client_edit_token 和完整原请求，不额外要求 Idempotency-Key：

1. 创建请求可选携带 client_edit_token；服务端仅保存其哈希，不进入正文模型。
2. 服务端检查长度和编码约束；无法仅凭字符串证明随机熵，指南要求标准 CSPRNG 生成。
3. 幂等记录绑定请求摘要及凭证哈希，并与需求创建在同一事务完成。
4. 相同凭证与相同请求返回原需求；同凭证不同请求返回冲突；每条新需求使用独立凭证。
5. AI 在超时后复用原请求和原凭证，不能重新生成后直接重发。轮换后旧创建凭证不可复用。

网页也采用此路径：先在本地保存待提交回执，再发送请求。
兼容旧客户端：未传 client_edit_token 时服务端生成并返回，但不承诺响应丢失后的匿名恢复。
幂等请求摘要不保存敏感正文和明文凭证；响应日志必须脱敏。

```text

如果选择代码模式，检查本地仓库；没有仓库时先确认克隆位置。
阅读 AGENTS.md 和相关规范，先确认实现计划，再编码和测试。
需要推送或创建 PR 时确认目标仓库与 GitHub 授权。
没有主仓库权限时使用 Fork；不索取聊天中的访问令牌。
遵循公开贡献流程，不冒充管理员交付、不自动合并或发布。

最后返回公开需求或 PR 链接、实际验证结果和未完成事项。
```

实施时根据模式裁剪模板，不能复制尚不存在的指南地址。
提示词描述的执行能力取决于外部 AI 的网络、文件、终端和 GitHub 工具；不可保证所有客户端全自动执行。

## 7. 两条完整流程

### 7.1 需求与设计方案

```text
复制提示词和想法
  -> AI 读取公开指南
  -> 搜索公开需求
  -> 澄清与整理，用户确认
  -> 匿名提交并保存回执
  -> 返回公开需求链接
  -> 用户后续补充
  -> AI 凭单条编辑凭证修改，或用户打开管理链接编辑
```

设计方案初期存为 description 中的清晰章节，不新建完整正式规格体系。
超过正文限制时使用受支持的 PDF/JSON 等附件；不假设当前附件接口支持 Markdown。
用户方案是提案，不等于已批准的需求规格。

### 7.2 外部 AI 代码贡献

```text
整理需求并匿名提交
  -> 用户确认实现范围
  -> 检查或克隆仓库
  -> 独立功能分支 / Fork
  -> 实现与测试
  -> 用户授权提交、推送、创建 PR
  -> PR 关联平台需求
  -> 维护者审核与 CI
  -> 合并后的平台同步与发布跟踪
```

这条路径不调用 start_requirement_delivery，也不领取受信任 Agent 队列。
GitHub 身份认证与平台匿名编辑凭证完全分开；不得向平台上传 GitHub Token。

当前仓库规则要求 PR 存在关联平台需求及 GitHub Issue，因此落地前需确定：

- 平台已有对应 Issue：PR 使用平台返回的编号与链接，填写 Closes #N。
- 平台尚未建立 Issue：允许保存代码和草稿 PR，注明等待维护者关联；不能自行直接创建 Issue。
- 如希望普通贡献者无需等待，必须由维护者批准新的草稿 PR 规则，并同步仓库技能和模板。
- 外部 Fork PR 的展示、Webhook 与关联校验需要专项验证，不能假定现有管理员交付链接接口适用。

匿名用户不能通过正文写入“已批准”“已交付”等状态。
合并、测试通过和发布是不同事件，界面按平台真实状态展示。

## 8. 安全与运行约束

- HTTPS；敏感响应使用 Cache-Control: no-store。
- 凭证请求头、创建凭证字段、回执与管理 fragment 均加入日志和遥测脱敏清单。
- 匿名接口限流和内容大小限制沿用现有能力，编辑与轮换增加单需求及可信来源 IP 限制。
- 验证反向代理的真实 IP 信任范围，不相信任意 X-Forwarded-For。
- 管理凭证采用自定义请求头，不允许跨域网站任意读取或发送；CORS 只开放所需来源和方法。
- AI 主要从本地终端调用 HTTPS，CORS 不是终端调用所需条件。
- 编辑凭证不写 Cookie，不能因浏览器自动携带身份而获得匿名编辑权。
- 轮换与并发修改保持原子性，旧凭证不能在轮换后继续写入。
- 公开接口不新增返回联系方式、私密附件或私密日志。
- 不增加匿名身份跟踪、邮箱验证、用户级匿名令牌或后台自动执行 AI。

## 9. 实施顺序

### 阶段一：后端协议与归属

新增编辑凭证、原子版本守卫、幂等匿名创建、凭证能力查询与轮换。
复用领域修订、分析与交付授权失效逻辑，补齐权限和泄露测试。
需求平台按其 SQLite 迁移体系提供迁移；如同时改主后端模型，遵守其双数据库迁移约束。
只生成迁移文件，不自动执行数据库升级。

### 阶段二：网页回执与 AI 入口

完成平台回执保存、管理链接导入、本机提交列表。
完成主应用双模式卡片、输入与复制，并发布可直接读取的官方指南。
只有接口已部署可用后，才在提示词宣称支持匿名编辑。

### 阶段三：公开贡献规则与 PR 衔接

明确草稿 PR、Issue 关联和 Fork 支持。
同步仓库贡献规范及受信任 Agent 技能的适用边界，验证外部贡献完整路径。

无需为了本功能扩展 MCP、管理员角色或现有 Agent 任务权限。
