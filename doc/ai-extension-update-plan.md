# 桌面 AI 扩展包更新与手动下载实施计划

关联需求：REQ-153（需求 ID：`a9e1dd46-816f-4bed-8d2c-ff7b62819f1f`）。

## 用户体验

- 保留启动时自动获取扩展清单；页面提供“检查更新”，检查中禁用重复点击，失败显示原因。兼容的已安装扩展不因客户端升级而自动下载；只有清单明确判定不兼容或要求强制更新时才自动下载兼容目标版本。
- 当前版本旁显示兼容状态与可选更新版本；兼容旧版继续使用，并保留“下载更新”供用户主动选择。没有新的扩展发布时无需重新打包或下载。同版本不重复下载，已安装更高版本时不按版本号简单降级。
- 更新下载支持进度、暂停与重试；已安装状态不再隐藏更新任务的进度或错误。下载、校验和安装过程中禁止卸载、重复安装及离线导入。
- 页面显示当前操作系统与架构，提供“官方下载页”；有当前平台附件时，各扩展提供“手动下载”直链及文件名。明确提示“下载后无需解压，点击离线导入”。
- 没有平台附件或清单不可用时保留官方下载页和离线导入说明，不把失败显示成“已是最新”。

## 任务安全与自动恢复（用户已确认）

- 更新包先下载并校验；替换阶段设置独立的扩展维护状态，停止派发依赖该扩展的新任务，等待在途推理与结果提交结束，再停止 AI Sidecar 并替换文件。下载期间可继续使用旧扩展。
- 卸载同样先停止新任务派发并等待在途任务结束，再关闭服务并删除运行时；照片、独立模型目录与分析结果保留。
- 扩展不存在时，依赖它的任务保留为待执行，并显示“等待安装 AI 扩展”；维护中显示“等待 AI 扩展更新”。等待不计入失败次数，不消耗连接错误的自动重试额度。
- 更新成功或重新安装后清除维护/缺失状态，唤醒任务调度；下一次 AI 请求按需启动服务，继续未完成的任务。更新失败保留旧扩展，清除维护状态并恢复旧运行时的任务处理。
- 扩展维护暂停与用户主动暂停分别存储；自动恢复只能解除维护状态，不能调用全量恢复而覆盖用户的暂停选择，包括交互高优先级任务。
- 下载、校验、替换、导入和卸载互斥；界面禁用与后端校验同时落实。维护状态覆盖程序异常退出与重启，启动时按实际安装和活动任务重建可用状态，避免永久暂停。
- AI 模型下载也要纳入关闭服务前的等待条件；不能仅检查照片推理任务，否则停止 Sidecar 仍会打断模型下载。

任务调度实现涉及 `package/server/app/service/task_manager.py`、`task_worker.py` 和相应桌面维护接口；复用持久化系统状态，优先避免新增 ORM 字段。桌面 Gateway 阻止维护阶段按需重启 Sidecar，并与 Server 的任务派发/排空状态协调。

## 兼容性与实现范围

1. 扩展发布清单新增兼容规则：每个已发布扩展版本声明支持的客户端语义版本范围；每个客户端范围可声明最低必需扩展版本或明确的强制更新规则与原因。客户端和扩展版本独立，不要求每次客户端发布都构建扩展包。规则引用实际已发布的、匹配当前平台且带 SHA-256 的附件，可复用历史 Release 资产。
2. `package/desktop/src-tauri/src/ai_extension.rs`：根据当前客户端版本、已安装扩展版本及平台选择兼容目标；向响应增加兼容/可选更新/必须更新/未知状态、原因、附件地址与文件名、官方发布页地址。采用可靠的语义版本比较；不能把版本不相等直接判为不兼容，也不能从 latest 随意选择不支持当前客户端的扩展。
3. 清单缺失、请求失败或旧清单未声明兼容关系时，状态为未知，保留当前运行能力且不强制更新。明确不兼容但找不到可安装的兼容附件时，显示原因并保留待执行任务，不重复下载、不循环重启、不启动明确不兼容的运行时。没有安装扩展时仍由用户选择在线安装或手动下载，不把未安装当作强制安装授权。
4. 强制更新复用任务安全维护流程：先下载校验，再排空并替换；明确不兼容的旧扩展在下载期间暂停新推理，兼容但需要强制升级的扩展仅在规则允许时继续处理至替换阶段。更新失败保留旧文件；只有旧扩展仍兼容且规则允许时才恢复执行，否则保持等待更新并提供重试与手动下载。自动更新对同一目标失败后不形成无限重试循环，重复清单检查不创建并发下载。
5. 在线更新复用现有下载、SHA-256 校验和替换安装流程；断点文件按扩展、平台及附件内容哈希隔离，防止旧版本残留参与新版本续传。校验失败清理坏文件，重试重新下载；安装前核对归档版本与清单版本。失败保留原扩展。
6. `package/desktop/src-tauri/src/lib.rs` 与 `ai_gateway.rs`：核对安装、重试、导入期间的 Sidecar 启停与互斥；防止更新开始后 AI 请求重新启动正在被替换的可执行文件。检查清单接口将失败状态返回页面。
7. `package/website/src/api/desktopAIExtensions.ts`：封装扩展管理请求和类型，组件不新增直接 HTTP 请求；Tauri 命令与既有桌面接口沿用相同返回数据。
8. `package/website/src/views/settings/DesktopAIExtensions.vue`：补充兼容性结果、必须更新原因、可选更新操作、检查状态、升级进度、平台提示和下载入口；复用共享按钮、主题色及全局外部链接打开机制，兼顾暗色及窄屏。
9. 同步桌面 README、中英文扩展指南以及发布流水线的清单生成流程，说明兼容规则、强制更新、在线更新和手动下载导入流程。

## 验收对应

| 验收项 | 主要证据 |
| --- | --- |
| AC1：旧版本可更新，同版/高版本不降级 | Rust 版本比较和清单响应测试；前端更新按钮与版本显示回归 |
| AC2：进度、暂停、重试、失败及旧安装保留 | Rust 本地归档/下载回归；前端已安装扩展的升级任务状态回归 |
| AC3：明确的平台下载来源与导入说明 | 前端附件链接、发布页回退、文件名及说明回归 |
| AC4：清单失败可恢复，兼容旧版不自动下载 | 清单失败 UI 与刷新回归；启动调用链检查 |
| AC5：适当回归与主题兼容 | 统一测试入口执行桌面/前端单元测试；可用浏览器环境下检查明暗、窄屏与桌面 |
| AC6：更新与卸载等待在途任务结束 | 模拟在途推理/结果提交，验证维护期间不新增任务且文件替换/删除发生在排空之后 |
| AC7：安装后自动继续，用户暂停保留 | 缺失扩展期间任务保持待执行、失败次数不增加；安装唤醒后继续，主动暂停任务仍暂停 |
| AC8：更新失败与异常退出可恢复 | 替换失败恢复旧安装；维护状态与实际安装一致；并发更新/卸载/导入被拒绝 |
| AC9：模型下载期间安全等待 | 模型下载中不停止 Sidecar，下载结束后进入替换阶段 |
| AC10：兼容清单独立于客户端发布 | 客户端升级仍允许旧扩展；历史 Release 附件复用；语义版本范围及预发布版本回归 |
| AC11：仅不兼容或强制规则触发自动更新 | 可选更新不自动下载；强制更新按兼容目标下载且只启动一次；缺兼容附件与网络失败不无限重试 |

执行测试入口：`pwsh tests/scripts/run-tests.ps1 -Layer unit -Component desktop -Level smoke`、`pwsh tests/scripts/run-tests.ps1 -Layer unit -Component website -Level smoke`。必要的 E2E 使用同一入口按相关文件缩小范围。

任务调度回归另使用 `pwsh tests/scripts/run-tests.ps1 -Layer unit -Component server -Level smoke -Scope task`；执行前确认测试入口的业务域过滤与相应测试标记一致。
