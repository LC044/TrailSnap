# 行影集工具箱重构需求设计

版本：v1.0 设计提案
日期：2026-11-06
状态：待产品评审，未实现
适用范围：TrailSnap Web、移动 Web/PWA 与共用界面的桌面客户端

## 1. 设计结论

将工具箱从“几个直接执行的批量表单”升级为“有范围、有预览、能复用的影像处理工具”。

统一操作流程：

**选择处理范围 → 设置处理规则 → 查看真实变化 → 确认执行 → 查看结果。**

最重要的三个改动：

1. 处理范围独立于整理规则。无论按时间、位置、人物还是分类，都能只处理某个相册、文件夹、年份或手动选择的影像。
2. 重命名自动记住最近使用的有效模板，并支持保存多套自定义模板。普通用户可以选预设、点变量，不必先学习占位符语法。
3. 执行之前必须展示真实影像的前后变化、影响数量和风险。不能用一个固定示例代替批量操作预览。

不建议第一版加入复杂自动化流水线、定时整理或自然语言执行。先把用户主动操作做清楚，再逐步扩展能力。

本文示例中的影像数量、文件名和地点为设计示例，不代表当前图库的实际数据。

## 2. 背景与现状

### 2.1 用户问题

场景一：已按日期整理照片，现在只想把 2026 年的照片再按城市细分，其他年份应保持不变。

场景二：经常使用自己的命名模板，但每次进入批量重命名都要重新输入；希望系统记住模板，或能保存“日常照片”“旅行照片”“相机导出”等几套规则。

底层问题不只是缺少一个筛选框，而是当前页面把“哪些影像”和“怎样处理”混在一起，缺少可复用配置与明确的执行边界。

### 2.2 当前源码确认

| 现有能力 | 当前限制 | 设计影响 |
| --- | --- | --- |
| 首页已有清理、整理、重命名、元数据修复等六个入口 | 最近活动是静态空白，占位没有接入真实记录 | 保留工具能力，重新组织入口，接入真实任务 |
| 整理支持时间、分类、人物、位置，支持移动/复制 | 日期范围仅在时间策略中展示和生效；基础查询面向用户全部未删除影像 | 所有策略共用范围解析 |
| 整理支持平铺与嵌套目录 | 不支持明确保留原目录层级后再细分 | 二次整理增加独立目录生成模式 |
| 地点、分类、人物有可用选项 | 选项从整个图库生成，切换时自动全选 | 选项随范围生成，不能自动扩大选择 |
| 重命名支持日期、时间、城市、原名、序号、相机等变量 | 每次初始化为 `IMG_{date}_{time}`；仅固定示例预览 | 保留变量，增加模板记忆及真实预览 |
| 元数据修复已有目录或相册选择 | 工具之间范围能力不一致 | 可以复用已有选择组件，但统一业务规则 |
| 用户模型有 `settings` JSON 字段 | 尚未确认存在工具箱偏好接口 | 优先扩展已有偏好存储，不为模板引入独立复杂体系 |

### 2.3 必须明确的概念

| 概念 | 面向用户的解释 |
| --- | --- |
| 相册 | 应用内的影像集合，可能包含来自多个文件夹的内容 |
| 文件夹 | 影像在服务器、NAS 或桌面电脑上的实际存储目录 |
| 按相册选择范围 | 只选中相册成员，不等于移动或重建相册 |
| 文件归档 | 会移动或复制实际文件，可能改变原文件路径 |
| 相册归类 | 只改变应用内分组，不移动文件，属于后续独立能力 |

第一版保留现有实体文件整理能力，页面统一叫“影像整理”，说明明确写“按规则整理实际文件”。不暗示它会自动创建应用内相册。

浏览器操作的是服务端可访问的存储，不是手机本地相册。目录选择器显示存储名称与相对路径，完整服务端路径放在展开详情中。

## 3. 目标与边界

### 3.1 产品目标

- 从工具箱直接进入时，不预选全部影像。
- 从相册、文件夹、搜索结果或批量选择进入时，带入当前范围，不扩展到整个图库。
- 日期条件对所有整理策略有效。
- 用户能看懂二次整理后目录究竟长什么样。
- 重命名再次打开时不必重复输入常用模板。
- 用户能在执行前知道“处理多少、跳过多少、会不会移动原文件”。
- 任务执行不要求用户一直停留在页面，完成后可查看结果。

### 3.2 第一阶段 P0

- 工具箱首页重构，保留现有六项工具及旧路由。
- 整理、重命名共用范围选择：相册、文件夹、条件筛选、手动选取、明确选择全部。
- 日期、媒体类型等范围条件与整理策略解耦。
- 二次整理支持保留原目录层级；支持显式重新归档。
- 最近有效重命名模板记忆、自定义模板、默认模板。
- 服务端真实预览、执行确认、结果明细与失败重试。
- 整理/重命名的基础操作日志与保守的撤销能力。
- 清理与元数据页面保持原有能力，首页名称和样式统一；未迁移的范围行为明确提示。

### 3.3 第二阶段 P1

- 清理、元数据修复接入统一范围与预览流程。
- 保存完整整理方案；支持一次组合“年份 → 城市”等最多三级规则。
- 按规则创建应用内相册，与文件整理分开进入。
- 模板导入/导出、更多命名变量、结果清单导出。
- 清理可选“仅范围内比较”或“与整个图库比较”，禁止默认删除范围外内容。

### 3.4 暂不纳入

- 自动定时整理、规则触发器、无人确认的 AI 文件操作。
- 任意读取或处理未入库的磁盘文件。
- 跨用户模板共享与团队级规则权限。
- 对元数据原文件写入承诺通用撤销。
- 对跨磁盘批量文件操作承诺整体原子成功或无限期恢复。

## 4. 工具箱首页

### 4.1 信息架构

按普通用户的目标分组，首先展示本次重构的核心能力：

| 区域 | 展示内容 | 用户动作 |
| --- | --- | --- |
| 页头 | 工具箱；“整理、命名与修复，先选范围再操作” | 查看操作记录 |
| 正在进行 | 当前任务、范围摘要、进度、状态 | 查看详情；请求停止 |
| 整理与命名 | 影像整理、批量重命名 | 进入向导 |
| 照片清理 | 重复照片、相似照片、低质量照片 | 扫描后手动核对 |
| 信息修复 | 修正拍摄信息 | 进入现有修复能力 |
| 我的模板 | 最近使用和用户保存的命名模板，最多露出三项 | 用此模板重命名；管理模板 |
| 最近操作 | 最近三条真实记录，移动端也显示 | 查看结果；再次使用规则；符合条件时撤销 |

不展示整库空间统计，不自动请求 `/api/storage/latest`。没有任务时隐藏“正在进行”；没有自定义模板时显示一行“保存常用命名方式，下次直接使用”，而不是空白大卡片。

### 4.2 工具卡片内容

每张卡片显示图标、名称、一句用途。涉及原文件变更的工具补充短标签，例如“移动或复制文件”“修改原文件名”。

推荐文案：

- 影像整理：把选中的影像按日期、地点、人物或分类归档。
- 批量重命名：统一文件名，记住你常用的命名方式。
- 重复照片：找出内容完全相同的照片，由你确认保留。
- 相似照片：比较相近画面，挑选值得留下的照片。
- 低质量照片：查看模糊或低分候选，不自动替你删除。
- 修正拍摄信息：根据文件名或指定值修正时间、设备信息。

### 4.3 入口与上下文

- 相册详情“更多 → 整理这些影像 / 批量重命名”带入相册 ID。
- 文件夹“更多”带入存储 ID、相对路径和子目录选项。
- 影像多选工具栏带入明确选中 ID。
- 搜索结果支持“处理当前结果”，必须区分全部匹配结果与当前页已选项目。
- 首页“我的模板”只带模板，不带上次影像范围，不直接执行。
- 最近操作的“再次使用规则”只复用规则；另设“使用原范围”，用户确认后重新解析范围、重新预览。
- 查询条件与模板不在 URL 中携带任意原始路径或长 ID 列表；大范围通过受权限保护的上下文引用传递。

## 5. 共用范围选择

### 5.1 初始状态

工具箱直接进入：展示“先选择要处理的影像”，下一步禁用。

不允许把范围缺失、空数组、筛选无结果解释成全部。全部图库必须是用户明确选中的范围类型。

### 5.2 选择方式

| 方式 | 界面展示 | 规则 |
| --- | --- | --- |
| 选择相册 | 搜索、封面、名称、项目数量 | P0 支持一个或多个普通相册；不支持的动态相册不展示或明确禁用 |
| 选择文件夹 | 存储名称、目录树、影像数 | 可选择多个目录；“包含子文件夹”默认开启且可见；选中父目录时折叠重复子范围 |
| 按条件筛选 | 年份快捷项、日期区间、媒体类型；更多条件展开 | 点击年份只修改日期条件，不修改整理策略 |
| 手动选择 | 复用已有影像网格及多选 | 显示选择数；支持从现有批量选择带入 |
| 全部影像 | 单独的次要入口、整库数量 | 必须主动点选，执行前再次强调整库影响 |

相册与文件夹选择器显示已有缩略图，不加载原图。无法读取封面时显示语义图标，不生成装饰性假照片。

### 5.3 筛选逻辑

- 同一类别多个值取并集，如相册 A 或相册 B。
- 基础来源与附加条件取交集，如“2026 文件夹”且“拍摄于 2026 年”且“照片”。
- P0 一次选择一种基础来源，不把文件夹与相册的复杂混合表达式暴露给普通用户。
- “按条件筛选”来源是当前用户有权限的已入库影像，必须至少填写一个实际限制条件；全部媒体不算限制条件。
- 重复命中的影像按 ID 去重。
- 清空条件后要求重新选择范围，不能悄悄切成全部图库。
- 日期默认按拍摄时间筛选。缺少拍摄时间默认排除，并告知数量；可明确开启“缺少拍摄时间时按上传时间判断”。
- 日期区间按应用确定的统一时区解释，使用开始日包含、结束日次日不包含；范围筛选和目录生成采用相同时间口径。
- 切换整理策略、位置粒度、平铺/嵌套不改变范围。
- 切换基础来源时保存各来源的会话草稿，但新来源需确认选择；不跨账号复用范围。

更多筛选可逐步加入地点、人物、分类、收藏、设备；P0 必须支持日期与媒体类型，其他条件依据现有筛选能力复用，不为本次重构重写搜索系统。

### 5.4 范围摘要与影像核对

始终可见的摘要示例：

> 2026 年相册 · 拍摄时间 2026-01-01 至 2026-12-31 · 仅照片 · 1,248 项
> 查看影像　更改范围

“查看影像”打开分页/虚拟网格，可以排除个别项目；排除计入摘要。大范围由后端解析，不一次下载整库 ID、元数据和缩略图。

当范围读取失败显示错误与重试，不显示“0 项”掩盖错误。空结果显示条件调整入口。所有数量在执行前重新校验。

### 5.5 影像支持规则

使用“影像”作为整体术语，但逐工具展示支持类型：

- 整理、重命名：P0 照片必须可用；视频只有完成对应文件与元数据验证后才开放选择，否则显示“不支持的视频 N 项”。
- 清理：沿用当前图片能力，不暗示可评价视频质量。
- 修复：只处理支持写入的图片格式，明确写入原文件。
- Live Photo、RAW+JPEG 等关联文件不能拆散处理。未完成成组识别的类型默认跳过并提示；后续支持后按一个影像组选择、成组变更、逐文件记录。

## 6. 影像整理

### 6.1 页面步骤

1. 选择范围。
2. 设置归档规则和目录布局。
3. 查看真实预览，确认移动/复制。
4. 进入任务详情，不再留在可误提交的表单中。

桌面可以显示完整步骤条，手机显示“第 2 步，共 3 步”和当前步骤名。用户可以返回修改，修改后旧预览失效。

### 6.2 规则界面

四张可选规则卡：按日期、按地点、按人物、按分类。选中后仅展开相应参数。

| 规则 | 普通设置 | 展开的高级设置 |
| --- | --- | --- |
| 日期 | 年、月、日；实时目录例子 | 平铺/嵌套；缺少日期处理 |
| 地点 | 省、市、区县；省市、市区、省市区 | 平铺/嵌套；缺失行政层级处理 |
| 人物 | 搜索人物、头像、范围内数量 | 同图多人归属方式 |
| 分类 | 选择类别、范围内数量 | 同图多类别归属方式 |

日期筛选放在“处理范围”，日期粒度放在“归档规则”，两者绝不共用一个控件。

地点、人物、分类的选项与数量仅来自当前范围。默认“范围内全部分组”是明确选项，不通过空数组表达；切换为“指定分组”后至少选一个，取消全部时禁用继续。异步刷新不得重新全选。

地点选择使用内部标识和行政层级，不把最终目录字符串当筛选标识，避免“平铺切嵌套”使地点选择失效。

缺少规则所需信息默认跳过并显示数量；用户可改为归到“未知时间/未知位置/未分类/未命名”目录。不得在日期筛选中偷偷纳入未知年份。

多人/多分类不能靠隐含算法决定移动目的地。复制可明确选择“每个匹配分组各复制一份”，预览显示额外副本数；移动默认跳过有歧义的项目，可选择一个目标或显式开启“按识别结果优先级归入一个分组”，并展示每个项目的目标目录。命名/排序相同时以稳定 ID 决胜。

### 6.3 目录布局：二次整理的关键

提供两个清晰选项，不预设用户愿意丢弃原层级：

**保留原文件夹层级，再按新规则细分**

- 仅当范围具有明确的共同源目录时提供。
- 源文件父目录相对共同源目录的路径先保留，再追加新归档路径。
- 在原目录内整理时，新目标为“预览冻结的原父目录 / 新规则目录 / 文件名”。
- 不以任务进行中的新路径反复计算，避免 `城市/城市/城市` 的嵌套。

**重新归档到目标目录**

- 仅使用新规则生成层级，原文件夹层级不进入目标路径。
- 跨文件夹相册默认要求选择目标目录，不自动推断原日期结构。
- 页面提示“原有月份/日期目录不会保留在新结构中”。

默认行为：文件夹范围建议保留层级，但仍要求确认模式；相册或条件范围不自动猜测目录布局。选择“移动”或“复制”也必须明确确认，不沿用当前默认移动。

复制与移动说明：

- 复制：“原文件保留；目标生成新副本，并按图库规则入库。可能增加存储占用。”
- 移动：“原文件将从原位置移走；应用中的文件引用同步更新。外部软件依赖原路径时可能受影响。”
- 显示复制预计新增字节；未知大小说明“无法准确估算”，不伪装为零。
- 目录不可访问、只读、剩余空间不足时显示具体原因。空间检查属于主动操作预检，不调用首页存储统计接口。

### 6.4 用户完整场景：只整理 2026 年

假设已存在：

```text
照片库/
  2025/12/31/a.jpg
  2026/01/01/b.jpg
  2026/05/02/c.jpg
```

操作流程：

1. 在工具箱选择“影像整理”。
2. 选“文件夹”，选择 `照片库/2026`，确认包含子文件夹。
3. 若要严格按拍摄年份限制，再添加“拍摄时间：2026 年”。目录名与拍摄年份可能不一致，系统不自行等同。
4. 规则选“按地点”，粒度选“省/市”，目录结构选“嵌套”。
5. 选择“保留原文件夹层级，再按新规则细分”。
6. 明确选择“移动”，查看完整路径预览。
7. 确认范围内变更，后台执行，2025 目录不变。

预览后结果：

```text
照片库/
  2025/12/31/a.jpg               # 不在范围内，不变
  2026/01/01/浙江省/杭州市/b.jpg
  2026/05/02/江苏省/南京市/c.jpg
```

如果用户想按“2026 年 → 城市”而不要保留月/日：

选择“重新归档到目标目录”，目标选 `照片库/2026`，粒度选“城市”，结果为：

```text
照片库/2026/杭州市/b.jpg
照片库/2026/南京市/c.jpg
```

如果“2026 年”是应用内相册：从该相册进入，范围为其成员；即使成员在多个实体目录，也只处理成员。用户需选择目标及目录模式，不能据相册名称推断年份或源路径。

### 6.5 重复执行保护

- 路径已经符合同一规则的项目显示“已符合，无需处理”。
- 保留层级模式通过操作记录识别相同规则已处理的影像，不能只看目录名称猜测是否已整理。
- 同源影像、规则和目标已有成功复制记录且副本仍有效时，默认跳过；用户可明确选择再生成副本。
- 不设置泛化“整理过就永久跳过”：按 A 整理过的影像仍允许按 B 整理。
- 不同规则或参数变化要求重新预览。
- 同名文件不覆盖，预览展示最终避让名称；磁盘执行时再校验，发生竞争则标记冲突等待重试，不悄悄采用另一名称。
- 不默认删除整理后留下的空文件夹；作为后续独立清理操作。

## 7. 批量重命名

### 7.1 页面结构

选择范围后，模板区按以下顺序显示：

1. 当前模板选择：上次使用、我的模板、内置模板。
2. 模板编辑：可编辑文字和变量按钮。
3. 简洁即时示例，标注“示例，最终以真实预览为准”。
4. 排序与编号设置。
5. “预览重命名”，展示真实影像旧名与新名。

无需保存模板就能执行，保存只是方便复用。

### 7.2 模板记忆规则

区分三种数据，避免“记忆”含义模糊：

| 类型 | 何时保存 | 下次如何使用 |
| --- | --- | --- |
| 临时草稿 | 输入停止约 500ms 后保存当前账号的本地草稿 | 返回/刷新恢复；下次重新打开时提示“有未使用草稿，恢复/丢弃”，不静默当默认 |
| 最近使用模板 | 服务端校验并接受执行计划后 | 无默认预设时自动选中，页面显示“上次使用” |
| 自定义模板 | 点击“保存为模板”或显式更新模板 | 在“我的模板”选择；可设为默认 |

自动初始化优先级：本次入口明确指定模板 > 用户设定默认模板 > 最近有效模板 > 内置默认。

草稿恢复由用户明确选择，覆盖当前模板前提示；已恢复会话在刷新时继续保持。

任务提交失败或被拒绝不更新最近使用。任务接受后因文件异常部分失败，模板仍保留，模板的有效性不依赖每个文件都成功。

只记住模板和命名参数，不自动记住上次待处理影像、移动操作或执行确认。退出登录清理当前可见草稿与状态；本地持久化按账号隔离。

最近使用列表最多 5 项，按模板内容与命名参数去重；自动历史不等于用户收藏，不挤满“我的模板”。设置默认后，上次临时使用别的模板不会覆盖默认。

### 7.3 自定义模板管理

保存弹窗：

- 模板名称，必填，建议上限 30 字。
- 命名内容，必填，服务端校验。
- 排序方式、编号起点、连续/按目录重置等参数。
- 设为默认，默认不勾选。
- 保存与取消。

用户模板建议最多 20 套；达到上限时说明并提供管理入口。

支持使用、复制、重命名、更新、设默认、删除。内置模板只能复制，不能编辑原件。编辑已保存模板形成工作副本，不因输入实时覆盖预设；点击“更新模板”才保存。

同名保存提示“替换原模板 / 另起名称”；删除默认模板后按最近有效模板回退，不清空正在编辑的会话副本。同步冲突以版本校验提示重新载入或另存，不无声覆盖其他设备修改。

### 7.4 内置模板

| 名称 | 模板 | 示例 |
| --- | --- | --- |
| 标准日期时间 | `IMG_{date}_{time}` | `IMG_2026-05-02_093015.jpg` |
| 紧凑日期时间 | `IMG_{year}{month}{day}_{time}` | `IMG_20260502_093015.jpg` |
| 日期与城市 | `{date}_{city}_{sequence3}` | `2026-05-02_杭州市_001.jpg` |
| 保留原名加日期 | `{date}_{original}` | `2026-05-02_DSC00123.jpg` |
| 自定义主题编号 | `旅行_{year}_{sequence4}` | `旅行_2026_0001.jpg` |

“保留原名加日期”标明不适合重复套用，否则可能连续追加日期；执行日志记录本次原名，但不凭空承诺能追溯未记录的历史原名。

### 7.5 变量交互

常用变量默认露出：日期、时间、城市、原名、序号。设备、镜头、ISO 等放到“更多变量”。

变量按钮插入当前光标位置，而不是模板末尾；点击后焦点返回输入框。按钮支持键盘，移动端点击可查看含义和例子。

保持现有变量语义：

- `{date}` 为 `YYYY-MM-DD`；紧凑日期由年、月、日组合。
- `{location}` 对应地址，不误标为区县。
- `{original}` 为本次执行前不含扩展名的原文件名。
- `{sequence3}` 至少三位，超过 999 不截断；`{sequence4}` 同理。
- 扩展名保留，输入框不要求用户写 `.jpg`；检测到疑似扩展名时提示，不直接猜测删除文字。

未知变量显示具体错误，如“变量 `{dat}` 不存在”，不再默默丢弃。支持重复变量，每次出现都正常替换。

### 7.6 编号、缺失字段与冲突

- 默认按拍摄时间升序，缺失时间置后，以稳定 ID 排序兜底。
- 编号默认从 1 开始、整个范围连续编号；可展开设置起点、按目录重置。
- 重试使用原计划编号，不对失败项目重新从 1 编号。
- 时间缺失默认跳过依赖时间的模板；可以明确选择上传时间兜底，不能用运行时“现在”生成不可重复的命名。
- 地点、设备等缺失默认使用清晰占位词并显示数量；用户可改为跳过，预览必须一致。
- 无效字符、保留名称、尾部空格、过长路径提前校验；任何自动替换都在预览中标注。
- 同目录重名默认追加 `(1)`、`(2)`，预览包含最终名称；不同目录可以有相同文件名。
- 已符合目标名称的项目跳过。
- 含 `{original}`、变化编号或变化范围的模板不保证重复运行结果不变，预览明确展示，不能以“智能去重”概括。
- 重命名只修改文件名，默认不改文件夹、不改 EXIF 内容；关联引用同步更新。

## 8. 真实预览与确认

### 8.1 预览展示

主指标只有一个：“将变更 1,200 项”。辅助信息为“范围内 1,248 项 · 无需变更 20 项 · 缺失信息 18 项 · 冲突 10 项”。

各状态互斥，数量之和等于范围内项目数；复制到多个分组另外显示“预计生成 1,430 个文件”，不将副本数混作影像数。

整理展示目录树与前后路径；重命名展示旧名、新名、原目录。均有已有缩略图、原因标签、分页/筛选。

| 原文件 | 处理后 | 状态 |
| --- | --- | --- |
| `2026/05/02/DSC00123.jpg` | `2026/05/02/杭州市/DSC00123.jpg` | 将移动 |
| `DSC00124.jpg` | `2026-05-02_杭州市_002.jpg` | 将重命名 |
| `DSC00125.jpg` | 不变 | 缺少拍摄时间 |

默认展示前 20 项，但统计及冲突检查覆盖整个计划，不把抽样预览称为全部检查。支持“只看异常”“只看变更”。目录树显示各分组数量，可折叠。

预览阶段不得创建归档文件夹、移动/复制文件或修改图库记录。大规模计划可异步生成，显示可取消的“正在准备预览”；这不是执行任务。

### 8.2 确认区

摘要必须明确：

> 仅处理：2026 年相册，共 1,248 项。
> 规则：省/市，保留原目录层级。
> 操作：移动原文件，1,200 项将改变位置。
> 其他影像不会被处理。

主按钮按实际动作命名：“确认移动 1,200 项”“确认复制 1,430 个文件”“确认重命名 1,200 项”，而非笼统“确定”。

移动、重命名需确认“我已查看变更预览，了解原文件将被修改”；全部图库操作进一步强调全库数量。普通复制不叠加多层弹窗，但保留最终确认步骤。

有阻塞冲突时不可执行；允许跳过的异常必须已计入计划与确认摘要。没有可执行变更时不创建空任务。

### 8.3 预览有效性

- 修改范围、规则、目标、模板、排序或缺失字段策略后，旧预览立即失效。
- 服务端返回用户绑定的计划 ID、版本、摘要和有效期，建议确认窗口 30 分钟。
- 确认后只执行被冻结的候选集合与目的地；执行中新增影像不加入本次计划。
- 源文件消失、权限失效、元数据变化或目标被占用时，不静默扩大范围或改名，跳过并记录，允许刷新计划再处理。
- 仅客户端按钮禁用不构成保护；服务端校验归属、版本、幂等键和计划状态。

## 9. 任务记录、停止与撤销

### 9.1 任务界面

状态区分：准备预览、等待确认、排队、执行中、请求停止、成功、部分失败、失败、已停止。

进度显示已处理/总项目数，成功、跳过、失败分别计数。失败原因可读，例如“文件夹只读”“源文件已不存在”“目标名称被其他程序占用”，详细技术信息可展开。

完成后展示：

- 查看结果影像/目标目录。
- 查看异常并重试。
- 再次使用规则。
- 在条件允许时撤销。

退出页面不取消执行。移动端顶部简洁任务提示，通知跳转对应任务详情；首页最近活动是真实记录，不是固定“暂无”。

“停止”表示停止后续项目，不恢复已经完成的项目；点击后说明语义并进入请求停止状态，不直接删除任务记录。

### 9.2 并发与恢复

- 相同请求幂等创建，重复点击返回同一任务。
- 不同任务命中相同影像/关联文件时排队或提示冲突，不能仅按任务类型分别互斥。
- 重试只处理原计划失败且仍安全的项目，不重跑整个范围。
- 服务重启依据执行日志恢复状态，先核实文件与数据库，不把“任务未完成”当“全部没做过”。
- 文件操作与数据库不是一个原子事务；单项目变更要有补偿和明确的恢复失败记录。

### 9.3 撤销设计

P0 为新版本记录完整日志的移动、重命名提供有条件撤销，建议窗口 24 小时；不能支持时隐藏动作并说明原因，不提供失效按钮。

操作日志至少包含影像 ID、关联文件 ID、原路径、目标路径、原名称、规则摘要、执行顺序、结果和校验信息。

- 撤销也是一次先预览再确认的后台任务。
- 当前文件仍是本次操作产物、未被后续操作覆盖、原位置未被占用时，才允许恢复。
- 遇到冲突允许逐项跳过，不覆盖其他文件，不宣称整批必定恢复。
- 复制的撤销仅删除确认仍属于本次生成、未被修改或继续使用的副本，不触碰原文件；条件不满足则阻止。
- 后续元数据修复仍沿用原文件写入风险提示，未实现备份前不承诺撤销。
- 超过撤销窗口只保留结果历史；日志保留期建议 90 天，可作为产品配置，过期会明确提示。

## 10. 页面布局与视觉

### 10.1 桌面布局

首页采用现有主布局及 `AppPage wide`，核心工具优先，避免一屏铺满等权统计卡。两张主工具卡更突出，清理与修复为次级紧凑入口。

向导内容宽度约 1,280px：

```text
工具箱 / 影像整理                         操作记录
选择范围  >  设置规则  >  预览并执行

主内容区约 2/3                 摘要区约 1/3
范围选择 / 规则表单             当前范围与数量
                               当前规则
                               操作与目标

上一步                         下一步：查看预览
```

表单控件宽度受限，避免全屏拉伸。摘要区在宽屏可粘性定位；中等宽度放到表单上方。第三步以预览为主，确认摘要与操作按钮固定在内容尾部。

### 10.2 移动布局

```text
返回    影像整理                    更多
第 2 步，共 3 步 · 设置规则

2026 年相册 · 1,248 项        更改
归档方式：按地点
粒度：省 / 市
布局：保留原文件夹层级
操作：移动 / 复制

底部：上一步              查看预览
```

- 核心工具使用紧凑单列条目，减少卡片大面积空白。
- 范围选择、模板编辑、预览详情使用全屏弹层，短动作使用底部菜单。
- 真实预览用逐项卡片，不强行压缩桌面宽表格；原名与新名可换行，路径详情点击展开。
- 向导活动时仅保留一个底部操作层，可按现有选择模式隐藏全局底栏；离开向导恢复五栏导航。不能让确认按钮与 56px 导航胶囊重叠。
- 软键盘打开时当前输入与必要操作可见，安全区只计算一次。
- 输入字体不小于 16px，核心触控区不小于 44px。

### 10.3 视觉语言

- 内容区采用中性实体卡片，圆角、细边框、适度留白，不铺满玻璃或高饱和渐变。
- 玻璃用于 sticky 页头、浮动操作条、菜单和弹层，与现有导航保持一致。
- 选中规则用主题色边框与浅色底；危险操作使用危险语义色，不跟随主题色改变含义。
- 页面标题、步骤标题、字段、辅助说明形成清晰层级；警告只在相关选项附近展示。
- 使用真实已有影像缩略图表达范围与结果，首次选择前不展示假照片。
- 兼容浅色/深色与现有五种主题色；所有弹层继承全局主题。
- 骨架、空态、错误态与有效零结果分开。减少动效偏好下保留所有功能。

### 10.4 空态和错误文案

| 场景 | 提示与动作 |
| --- | --- |
| 未选范围 | “先选择要处理的影像”；选择相册/文件夹/筛选 |
| 条件无结果 | “这些条件下没有可处理影像”；修改条件 |
| 相册不存在或无权限 | “该相册已不可用，请重新选择”；不回退全库 |
| 模板为空 | “请输入命名方式，或选择一个模板” |
| 模板未保存 | “当前为临时修改”；保存为模板/继续使用 |
| 计划过期 | “预览已过期，需要重新检查文件状态”；重新预览 |
| 服务端目录离线 | “存储暂不可访问，请检查挂载或连接”；重试 |
| 大部分缺失位置 | “选中范围中有 860 项缺少地点，默认跳过”；查看/返回调整 |
| 部分失败 | “已完成 1,180 项，20 项未完成”；查看原因/重试安全项目 |

## 11. 工程落地建议

本节是实现方向，不表示接口或组件已经存在。实现前需要复核实际 props、权限和数据模型。

### 11.1 共享模块

建议新增业务组件：

- `MediaScopeSelector`：范围来源、附加条件、排除项。
- `MediaScopeSummary`：一致的自然语言摘要与数量。
- `ToolWorkflowShell`：步骤、返回、草稿、底部操作。
- `OrganizeRuleEditor`：分组规则与目录布局。
- `RenameTemplateEditor`：变量、预设、保存和校验。
- `ToolPlanPreview`：统计、分页明细、异常过滤。
- `ToolExecutionResult`：结果、停止、重试、撤销。

基础布局复用 `AppPage`、`PageHeader`、`SurfaceCard`；菜单复用 `AdaptiveMenu`，长表单复用 `ResponsiveDialog`；目录树、相册选择与 `UnifiedPhotoPage` 按实际接口复用。不重写独立的画廊、主题或弹层系统。

### 11.2 范围模型

建议抽象：

```text
scope:
  source: albums | folders | filter | selected | all
  album_ids / folder_refs / selection_ref
  filters: captured_date_range, media_types, missing_time_policy
  excluded_ids
```

每种来源的必要参数显式校验；`all` 是明确枚举，不用缺少参数表示。服务端统一注入 owner 和权限条件，默认排除回收站项目。

文件夹引用优先采用 `storage_root_id + relative_path`。目录范围必须按规范化路径边界判断，不能用字符串 `startswith`，防止选 `2026` 时误命中 `2026-backup`。同时核验符号链接、路径穿越、驱动器/UNC、大小写及移动后存储引用。

预览选项、统计、计划和执行都使用同一范围解析器；不在四个策略中各写一套条件。

### 11.3 计划与执行

建议新增统一预览计划接口与分页明细接口，执行接口接受计划引用而不是重新全库扫描：

| 能力 | 概念接口 |
| --- | --- |
| 范围数量和抽样 | `POST /api/toolbox/scopes/preview` |
| 当前范围的规则选项 | `POST /api/toolbox/organize/options` |
| 生成真实操作计划 | `POST /api/toolbox/plans` |
| 读取计划与分页明细 | `GET /api/toolbox/plans/{id}`、`/{id}/items` |
| 确认执行 | `POST /api/toolbox/plans/{id}/execute` |
| 请求停止/安全重试 | 按 task ID 的独立动作接口 |
| 撤销预览 | 从 task ID 生成恢复计划 |
| 模板与偏好 | 当前用户范围的工具箱偏好读写接口 |

新增接口统一 `BaseResponse[T]`，成功/失败使用项目规定封装；字段使用明确枚举、类型和版本，避免继续扩大 `any`。

大范围计划分批计算并持久化明细，磁盘可变性在执行时再次核验。业务筛选与数量仍按需实时查询；这里的持久化用于执行清单、去重和恢复，不引入整库统计快照表。

对旧 API 和 CLI 制定兼容期：保留旧路由，但新界面不走无范围执行。旧客户端无范围请求不能悄悄执行全部，可返回明确的升级提示；需要旧行为的兼容调用必须显式指定全部并经过相同安全校验。

### 11.4 偏好与日志

- 用户模板、默认模板、最近有效模板优先存于 `User.settings.toolbox`，数量有限，版本化读写，按字段合并不覆盖其他设置。
- 本地草稿仅作当前用户输入恢复；跨设备长期偏好以服务端为准。
- 任务 payload 保存模板内容及规则快照，不只保存模板 ID，防止执行中预设修改影响任务。
- 操作日志与计划明细复用现有任务机制可承载的能力；需要大量逐文件记录时使用任务明细表，不把海量日志塞进用户偏好或单个巨大 JSON。
- 模型变化按仓库约定提供 PostgreSQL 与 SQLite 迁移，不自动执行 `alembic upgrade head`，由用户手动迁移。

## 13. 验证与交付次序

建议分四个可独立验证的迭代：

1. 统一范围与模板记忆：先补齐两项直接诉求，包含后端范围校验，不仅新增前端控件。
2. 整理目录模式与真实预览：验证 2026 年二次整理、重名、缺失字段、计划变更。
3. 新首页、任务明细与恢复：接入真实最近活动、异常重试、有条件撤销。
4. 扩展到其他工具及组合方案：清理比较边界、元数据写入策略、应用内相册归类。

前两步也必须保留明确最终确认；不能在真实预览未上线时放开大范围直接执行。

验证重点：

- 后端单元：范围交并集、日期边界、路径边界、模板优先级、编号稳定、计划幂等。
- 文件/数据库集成：真实临时文件移动与复制、重名竞争、数据库失败补偿、重启恢复、撤销冲突。
- 前端交互：步骤回退、范围不丢失、草稿、预设显式更新、过期预览、错误与空态。
- E2E：以 2025/2026 混合图库验证范围外文件字节、名称、路径和数据库引用均未变化。
- 跨端：窄屏与桌面、明暗主题、弹层滚动、软键盘、无障碍、关联文件支持状态。
- 性能：千项与万项范围，避免整库前端下载；预览只读且可分页，计算可取消。

代码实施时按 `tests/README.md` 选择测试范围，统一通过 `tests/scripts/run-tests.ps1` 执行。本文只有需求设计，未运行应用测试或浏览器视觉验收，不将线框视为完成的 UI。

## 14. 评审时需确认的取舍

以下采用本文建议默认值，进入开发前可以逐项调整：

| 决策 | 本文建议 | 影响 |
| --- | --- | --- |
| 整理对象 | 第一版仍整理实体文件，相册归类作为独立后续能力 | 避免把两类操作混为一谈 |
| 全库处理 | 保留但必须主动选择 | 兼顾整库管理与默认安全 |
| 二次整理 | 保留原层级/重新归档两种模式明确确认 | 直接覆盖用户的重复整理场景 |
| 移动或复制 | 不默认选移动，用户明确选择 | 增加一步确认，减少误移动 |
| 模板初始化 | 默认预设优先，其次上次有效模板 | 兼顾固定习惯与临时使用 |
| 模板容量 | 20 套自定义，5 项最近使用 | 保持管理简洁 |
| 执行计划有效期 | 30 分钟 | 过期重新核验，而非长期保存过时路径 |
| 撤销窗口 | 新操作有条件支持 24 小时 | 需要逐文件日志与冲突处理 |
| 完整组合规则 | P1，最多三级 | P0 先以保留目录解决二次整理，控制复杂度 |

最终体验应当是：用户先看清“这次只处理谁”，再选“怎样整理”，看到真实结果后才确认；下次命名时，自己的习惯已经在那里。
