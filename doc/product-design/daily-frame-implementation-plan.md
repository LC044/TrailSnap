## 实现目标与范围

实现 PRD 首版全部范围：每日唯一代表素材、月历与年度总览、照片及一秒动态选帧、当月确认式批量填充、制作预览、持久后台 MP4 生成、作品管理及下载。覆盖 A01—A20。

暂不包含多项目、提醒、音乐、多人协作、直接拍摄或公共分享。

## 现有能力与实施选择

- 图库已存在 image、video、live_photo 三种类型，照片有 duration、photo_time、owner_id 和回收站状态。
- Photo.photo_time 当前采用无时区 DateTime；服务层按原有本地时间语义分日，不用 upload_time 补齐缺失拍摄时间。固定日历 IANA 时区用于今天和未来日期判断。
- Live Photo 可通过现有 storage.get_live_photo_vide 定位动态文件；动态模式需同时验证动态文件可读取。
- 已有 Task、TaskManager、TaskStrategyFactory 与独立任务工作进程；影片生成使用新增任务策略，不使用进程内临时线程作为持久任务替代品。
- 前端已有 Pinia、统一请求封装、桌面和移动导航配置。新增页面与入口沿用这些约定。
- 现有媒体访问、用户存储布局和下载鉴权必须复用并核实，不通过公共文件地址规避权限检查。

## 模块划分

### 数据与迁移

新增日历设置、每日选帧、影片作品模型。每日选帧以 owner_id 与 date 唯一约束，保存素材引用、静态或动态模式、起点、文字和递增版本；移除保留版本记录，防止移除重建导致旧请求覆盖新状态。

影片作品保存不可变素材快照、输出设置、内容指纹、任务关联、输出文件信息和状态。成品独立于原素材删除；生成过程中仍检查源素材权限与可用性。

使用 Alembic 自动生成迁移，检查生成内容；PostgreSQL 与 SQLite 各提交一个迁移，包含约束、索引和必要默认值。核实当前两套迁移 head 后确定 down_revision。

### 后端

新增 daily-frame API、schema 与 service，统一返回 BaseResponse。

- 日历初始化、设置读取与首次保存后时区锁定。
- 月份与年度范围查询、状态汇总、分页候选查询。
- 版本校验保存、移除与撤销，素材所有权和日期校验。
- 候选批量填充预览与确认保存，逐项成功、冲突和失败结果。
- 制作快照预览、范围校验、失效素材显式跳过、指纹去重。
- 持久生成任务、取消、重试、作品读取删除及鉴权下载。

### 媒体生成

先核实各部署形态的编码器可用性。能力不可用时提前返回能力状态，并在页面展示原因。

每个日期统一输出一秒、30 fps、静音片段。照片按画幅 contain/cover 适配；动态片段精确截取并使用末帧补足。日期与文字使用一致的安全区域和可用中文字体。先生成临时文件，完整校验全部素材和任务状态后发布结果；取消或失败清理临时输出。通过真实生成样本核对最终帧数、时长、画幅和文字。

### 前端

新增统一 API、类型、Pinia store，以及月历/年度页、选帧编辑器、批量填充页、制作页和作品详情。

制作预览与导出共用内容快照、适配和文字排版规则；范围或设置变化使旧预览失效。选帧支持短动态素材、Live 静态模式、起点调整、未保存退出提醒和冲突反馈。

记忆页面顶部加入“一日一帧”按钮，侧栏及移动端“更多”不单独列出此功能；进入一日一帧后保持记忆导航高亮。首页加入今日卡片，照片查看器加入带日期校验的快捷设置入口。保持暗色、主题色、移动端触控和键盘操作要求。

## 运行要求

- 已新增 PostgreSQL `d1f139000001` 和 SQLite `sqlite_0017` 迁移；由原有数据库初始化流程执行。后续开发环境联调已在用户指定的开发库执行 PostgreSQL 迁移。
- 生成影片需 FFmpeg、FFprobe、H.264/libx264 编码器和中文字体。Docker 镜像已包含 FFmpeg 和 Noto CJK；原生部署可通过 `TS_FFMPEG_PATH` 指向 FFmpeg 可执行文件（FFprobe 放在同目录），通过 `TS_VIDEO_FONT` 指向中文 TTF/TTC/OTF 字体文件，配置后重启服务。
- 能力不足时可继续日历选帧，制作页显示明确原因，禁止提交生成任务。
- 作品保存在应用数据目录 `users/<user-id>/daily-frame/`；预览为 360×640/640×360，成片为 1080×1920/1920×1080，30 fps、静音、每个有效日期一秒。
- JSON 和下载使用现有认证；播放器使用独立签名密钥、30 分钟有效期、绑定单个素材路径与模式的凭证。
