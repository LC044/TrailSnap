## 1. 产品结论

在现有记忆、人物、地点和照片能力之上增加“关联探索”功能。用户从一个对象出发，查看有证据支持的直接关联，点击关联对象继续探索，也可以选择两个对象查看共同记忆。

桌面采用可逐层展开的关系画布：从一个中心开始，点击任意节点将下一层追加到同一张图上，已有节点和真实连线保持可见；支持全屏漫游、平移和缩放。移动端提供分组卡片，二者共用查询结果和筛选条件。首版复用关系型数据库，不引入图数据库或新的大模型推断链路。

关键产品原则：每条关系都能解释依据；“同一记忆中有关联”“出现在同一张照片”和“在该地点拍到这个人物”分别表达。不能仅凭同一记忆包含某人物和某地点，就宣称该人物到访过该地点。

## 2. 背景、目标与范围

### 2.1 原始问题

人物、地点、相册和记忆分散在不同页面。用户想回答“和这个人有哪些共同经历”“这个地方有哪些熟悉的人”“这段旅行还关联哪些照片”，需要反复切换入口。

### 2.2 用户故事

| 用户场景 | 操作路径 | 用户获得的结果 |
| --- | --- | --- |
| 从人物回忆旅行 | 人物详情 → 关联 → 某地点 → 某记忆 | 沿着人物和地点找到相关经历及照片 |
| 回顾某个地点 | 地点详情 → 关联 → 相关人物 | 看到在当地照片中出现的人，以及仅在同一记忆中关联的人 |
| 查看两个人的经历 | 选择人物 A、B → 共同记忆 | 找到同时关联两人的已确认记忆；合影作为独立证据 |
| 继续探索一次事件 | 记忆详情 → 关联 → 人物/地点/照片 | 看到事件组成，并能返回探索起点 |
| 手机随手回忆 | 关联卡片 → 下一层 → 返回 | 无须操作密集的小尺寸关系图 |

### 2.3 首版交付范围

必须覆盖原需求全部六项验收标准：人物/地点/记忆入口、一级探索和返回、双对象共同记忆、详情跳转、有界呈现、移动卡片。

首版包含四类节点：人物、地点、记忆、照片。“事件”统一指现有已确认记忆，不再创建平行的 Event 业务实体。照片可从关系结果进入浏览器，也支持成为探索中心。

首版不包含全库全景图、跨用户或共享相册关系网络、自动推测家庭/朋友关系、任意多跳路径搜索、图谱编辑器、图谱分享导出，以及票据/标签/相册作为独立节点。用户纠错通过现有详情页完成。

### 2.4 成功衡量

上线前以第 11 节验收为准。上线后在已有统计能力和用户设置允许的范围内观察：入口点击率、成功展开率、探索两层及以上的会话占比、共同记忆结果打开率、详情跳转率、空结果比例、接口错误率和 P95 延迟。

首轮先建立基线，不预设缺乏依据的转化率目标。统计只记录节点类型、操作和耗时，不上传人物名、地名、照片地址或记忆正文；尚无统计基础设施时，功能交付不以新增第三方埋点为前提。

## 4. 数据与关系规则

### 4.1 可见数据范围

1. 默认仅当前用户自己的有效数据；共享相册里的他人照片不进入首版关系网络。
2. 记忆仅纳入 confirmed。候选、忽略、归档、被合并/拆分替代、删除状态均不进入关系和计数。候选详情提示“确认后可探索关联”。
3. 人物必须属于当前用户，且未隐藏、未删除；照片必须属于当前用户且不在回收站；Face 本身也必须有效。
4. 全局公共 Scene 可以作为地点定义，但只能由当前用户可访问的照片或记忆提供关联证据。不能从公共地点反向发现其他用户的数据。
5. 隐藏/删除数据不得泄漏到节点名称、头像、封面、数量、证据摘要或双对象结果中。不存在与无权访问统一返回不可用，不暴露对象存在性。

### 4.2 节点身份

| 类型 | 稳定标识建议 | 展示内容 |
| --- | --- | --- |
| 人物 | `person:<identity_id>` | 名称、当前可见头像；未命名人物显示“未命名人物” |
| 地点：场景 | `place:scene:<scene_id>` | 场景名和所属行政区；保留 UUID，不依赖名称 |
| 地点：行政区 | `place:region:<结构化路径的稳定编码>` | 层级 + 国家/省/市/区路径；空值有明确标记 |
| 地点：未解析文本 | `place:unresolved:<memory_place_id>` | 原名称、“未关联标准地点”标签、来源记忆 |
| 记忆 | `memory:<memory_id>` | 标题、时间、有效封面 |
| 照片 | `photo:<photo_id>` | 缩略图、拍摄日期；视频等媒体沿用现有浏览器能力 |

节点 ID 是身份标识，不是授权凭据。后端仍需检查用户范围。

地点规则：优先使用有效 scene_id；行政区使用完整已知路径。名称只做空白等确定性规范化，不做模糊同义合并。历史 MemoryPlace 只有名称时，可依据该记忆有效照片解析；仅当同层级同名地点得到唯一一致路径时关联，多个候选或证据不足则保留独立文本节点。

“朝阳区”等同名异地必须分开；父级缺失的城市不自动并入某个完整路径。用户编辑地点后重新解析。未解析节点允许查看来源记忆和其地点说明，不伪造可以打开的地理地点详情；此情形应在 UI 中明确标注。

### 4.3 直接关系及解释

| 两端 | 依据 | 展示文案示例 |
| --- | --- | --- |
| 人物—照片 | 有效 Face 关联 | “照片中识别到” |
| 地点—照片 | PhotoMetadata 的行政区路径或 scene_id | “拍摄地点” |
| 记忆—照片 | 有效 MemoryPhoto | “包含于记忆” |
| 记忆—人物 | 用户显式关联，或记忆中有效照片的人脸证据 | “你关联的人物” / “记忆照片中识别到” |
| 记忆—地点 | 用户显式地点关联，或记忆中有效照片的地点证据 | “你关联的地点” / “记忆照片的地点” |
| 人物—人物 | 同照，或同一已确认记忆分别关联两人 | “12 张共同照片” / “3 段共同记忆” |
| 人物—地点 | 此人物实际出现的照片有该地点；或仅同记忆关联 | “在此地的 8 张照片” / “2 段相关记忆” |
| 地点—地点 | 两个地点关联同一已确认记忆 | “同属 2 段记忆” |

后面三类是由证据聚合得到的业务关联，用户点击仍只加载一级结果；接口须标明来源，不能伪装成原始事实。首版不额外展示记忆—记忆或照片—照片推荐边，避免语义和密度失控。

自动 MemoryPerson/MemoryPlace 不能仅凭历史缓存关系继续展示：查询时应验证当前照片证据，避免移除照片、修正人脸后出现过期关系。用户显式关联可以独立存在，保留“你关联的”说明。用户删除手工关联后，如仍有照片识别证据，可展示为自动识别关系，并引导到照片/人物页纠正，不能重新标为用户确认。

同一端点对聚合为一条边，附带多个 evidence kind；数量按不同 memory_id/photo_id 去重，不能将一张照片的多个人脸检测框重复计数，也不能把照片数和记忆数相加作为一个“关联次数”。未确认的自动识别只表达识别结果，不推断亲疏或身份关系。

### 4.4 “共同记忆”的严格定义

令 M(x) 为在当前用户范围内与对象 x 关联的已确认记忆集合：

- 人物：显式关联此人物，或包含此人物有效照片的记忆。
- 地点：显式关联此标准地点，或包含此地点有效照片的记忆；未解析文本节点仅关联其来源记忆。
- 照片：包含该照片的记忆。
- 记忆：该记忆自身，即单元素集合。

两个不同对象 A、B 的共同记忆为 `M(A) ∩ M(B)`，按记忆 ID 去重。相同对象不能重复选择。

例如两个人在同一旅行的不同照片中出现，旅行仍是共同记忆，但不是合影；两人只有共同照片且照片尚未关联已确认记忆时，显示“暂无共同记忆”，另列“共同照片”，不自动生成记忆。

所有类型组合遵循同一规则：人物+记忆用于验证该人物是否关联这段记忆；两个不同记忆的结果为空，提示“请选择人物、地点或照片查找共同记忆”，不擅自返回相似记忆。产品默认推荐人物+人物、人物+地点、地点+地点，照片也允许参与。

记忆结果按 start_time 倒序、ID 稳定排序；时间缺失排最后。首版不增加日期筛选，避免照片拍摄时间和事件跨度产生两个筛选口径。

## 5. 页面与交互

### 5.1 入口与导航

- 人物详情、标准地点详情、已确认记忆详情增加“关联”入口，携带节点标识进入同一探索页。
- 建议新路由 `/explore/relations`，通过受校验的 query 携带 root 和可选 compare 对象。刷新后可恢复中心及比较对象。
- 记忆列表可增加“关联探索”入口；没有 root 时展示起点选择器，不自动加载全库关系。
- 起点/比较对象选择器按类型搜索当前用户的有效对象，服务端分页；未命名人物支持头像辨认，照片支持缩略图选择，不强制依赖名称。
- 从聚合名称地点页进入时，若名称对应多个行政路径，先选择具体地点；不得随机选一个或合并计算。

### 5.2 桌面端

首屏以当前人物、地点、记忆或照片的封面图和名称为主，探索路径、返回、换起点与寻找交集在封面内。封面下方是“故事从这里延伸”，类型筛选作为轻量圆角选项；宽屏桌面将关系图放在独立的沉浸式探索区，中等宽度及手机使用完整卡片列表，避免压缩节点。桌面图右侧显示当前聚焦线索的照片、名称、关联摘要及下一步操作；下方缩略图可点选其他线索。宽屏用户可随时切换到完整卡片列表。

1. 默认显示一个中心和其一级关联，人物、地点、记忆、照片在环形空间中混合分布，不按类型分区。人物裁为圆形头像、照片为方形缩略图、地点用较轻的菱形标记；缺图时回退到类型形状。
2. 点击普通节点：在原图中以该节点为锚点加载并追加下一层；重复节点合并，已展示节点之间存在真实依据时补画连线。已有节点的位置保持稳定，视口移向新展开区域。点击已展开且有后续结果的节点继续加载；没有更多结果时保留预览，不重复请求。
3. 中心摘要与“查看详情”位于封面；悬停其他节点可更新线索预览，侧栏缩略图可点击选择同一预览，并可继续探索或查看关联依据。完整列表是键盘可用的替代入口。
4. 支持缩放、拖动画布、适应画布和全屏沉浸查看；全屏切换保留当前节点、视口与缩放，Esc 退出。节点可键盘聚焦并展开。
5. 面包屑、页内返回和浏览器返回均恢复前一探索状态。回到历史中的节点时回退到该层，避免 A→B→A 不断堆积重复路径。
6. 每个节点的下一层按服务端游标逐页读取，画布可以持续向外延伸；下方分页及完整卡片列表仍用于浏览起点的一级关联。
7. 实线代表直接照片依据、虚线代表仅有记忆关联；线宽和亮度随有效依据数增加。聚焦节点时保留中心与对应连线，其余线索减弱但仍可见。不能绘制没有证据的邻居间连线。

### 5.3 移动端

窄屏（建议小于 768px）默认用卡片，不加载图形画布；桌面也可主动切换到同一列表视图。

页面依次呈现：带照片的当前对象封面、简短引导、类型选项、按人物/地点/记忆/照片分组的线索卡片。卡片以照片、名称和关系摘要为主，主区域轻触进入下一层；“如何相连”与“查看详情”置于卡片底部。比较时主区域改为勾选，固定选择条避开底部导航。

普通模式点击卡片进入下一层，卡片上的“详情”按钮直接打开详情。双对象模式点击卡片变为勾选；底部固定显示已选对象及“查看共同记忆”。每次仅展示当前层，系统返回/应用返回恢复上一层滚动位置；返回照片浏览器后保留中心、筛选和比较状态。

### 5.4 类型筛选与规模

| 项目 | 建议规则 |
| --- | --- |
| 默认类型 | 人物、地点、记忆；照片可显式打开，也会在详情侧栏提供入口 |
| 默认邻居数量 | 20；按启用类型公平分配配额，剩余配额按排序补齐 |
| 单页最大邻居 | 40，含中心的图中最多 41 个节点 |
| 图中边 | 仅中心到邻居的边，同一端点对合并；最多 40 条，不绘制邻居之间的交叉关系 |
| 移动列表 | 每类初始 6 项，“查看更多”后以 20 项分页 |
| 照片详情列表/共同记忆 | 每页 20，服务端最大 50 |
| 展开深度 | 单次请求固定一级，无递归查询；历史最多保留 20 个状态 |

类型筛选仅控制可见邻居，不改变中心，也不修改共同记忆定义。全部取消时提示选择至少一种类型。比较对象固定显示在选择栏，即使其类型暂时被隐藏。

人物、地点、记忆类默认按共同记忆数降序、有效证据照片数降序、最近相关时间降序、节点 ID 排序。照片类先按拍摄日和具体地点分桶，优先展示尚未出现过的日期或地点，再按相关时间和 ID 稳定排序；连续拍摄的一组照片不会占满首屏。缺失时间或地点归入各自的未知桶。排序仅帮助浏览，不称为“最亲密”。

分类型返回已展示数量和 has_more，截断时显示“当前展示部分关联”；不能把已加载 20 项当作总数。精确总数仅在可控查询成本下提供，未知时不编造。

### 5.5 双对象流程

进入选择模式 → 选择第一个对象 → 从当前结果或搜索选择第二个对象 → 点击“查看共同记忆” → 展示分页结果。

最多选择两个对象；再次点击可取消，选择第三个提示先移除一个。结果页保留两个对象的卡片、共同记忆列表和关系依据，支持替换/移除对象。仅人物+人物等具有直接照片交集的组合展示独立“共同照片”区域，不与记忆混合计数。退出比较回到原探索中心和视图状态。

### 5.6 详情跳转

人物复用 `/album/people/:id`；记忆复用 `/memories/:id`；标准地点复用 `/album/location/:name` 并携带精确地点路径或 sceneId；照片调用现有完整媒体浏览器。

必须同步扩展地点详情查询的精确范围，保证从“辽宁省朝阳市”进入后不会展示其他同名城市照片。未解析文本节点的按钮为“查看来源记忆”，其摘要本身承担文本地点说明，不显示无效的“地点详情”按钮。

## 6. 异常与边界状态

| 情况 | 产品行为 |
| --- | --- |
| 没有直接关联 | 保留中心，提示“暂未找到相关内容”，提供详情入口 |
| 没有共同记忆 | 展示空状态和更换对象入口；有共同照片则独立展示 |
| 无人脸结果/无 GPS | 对应类型为空，其他关系正常；不要求开启 AI 才能探索已有数据 |
| 对象已删除、隐藏或不可访问 | 清除失效选择和本地结果，提示“内容已不可用”，允许返回上一层 |
| 请求失败 | 保留上一个成功状态，显示重试；失败不写入探索历史 |
| 快速切换中心 | 取消或忽略旧请求，迟到响应不能覆盖新中心 |
| 照片删除/移出记忆 | 下次请求不再用它计数或提供证据；用户显式人物/地点关联仍按其来源显示 |
| 记忆合并/拆分 | 原记忆退出结果，新的 confirmed 记忆按新关联参与；不通过溯源边重复计数 |
| 缩略图加载失败 | 类型占位图，保留可访问的文字和详情入口 |
| 超大关联或查询超时 | 保持分页上限；超时明确提示并允许重试，不能静默伪装成无关联 |
| 退出登录/切换账号或服务器 | 清除探索历史和缓存，防止跨账号显示残留内容 |

提供可键盘操作的列表替代图形；按钮建议不小于 44px 的触控区域。主题色遵循 `primary-*`；图形从 `injectTheme()` 读取强调色并在主题变化时重绘，文字/背景配套暗色变体。

## 7. 技术实现建议

### 7.1 后端：关系查询服务

建议新增 `app/api/relations.py`、`app/schemas/relations.py`、`app/service/relations.py`。将权限过滤、节点解析、地点标准化、关系聚合、共同记忆求交分离为可独立验证的函数。

查询顺序：校验中心权限 → 按中心类型筛选候选 ID → SQL 层聚合去重和排序分页 → 批量加载所需摘要 → 装配节点/边/证据。所有分支使用同一用户与状态过滤器；禁止先计算全库数量再做用户过滤。

使用 SQLAlchemy 的 JOIN、EXISTS、GROUP BY 和分页实现一级关系。禁止将全库照片加载到 Python/浏览器后建图，禁止逐节点串行查详情。直接照片证据不要求已有记忆，因此尚未使用记忆功能的用户仍可从人物探索拍摄地点和照片。

### 7.2 建议接口契约

以下为新增建议，尚未存在；统一使用 `BaseResponse[T]`，通过 `success()` / `fail()` 返回 code、msg、data。

| 接口 | 主要输入 | 主要输出 |
| --- | --- | --- |
| `GET /api/relations/neighbors` | root、types、limit、cursor | center、nodes、edges、按类型的分页信息 |
| `GET /api/relations/common-memories` | left、right、limit、cursor | objects、去重记忆卡片、next_cursor、has_more |
| `GET /api/relations/evidence` | left、right、kind、limit、cursor | 授权后的依据记忆/照片列表 |
| `GET /api/relations/search` | type、q、limit、cursor | 可选对象及消歧信息；仅当前用户范围 |

`Node` 最低字段：id、type、label、可选 thumbnail、结构化 detail_target、availability。`Edge` 最低字段：source、target、relation_kinds、memory_count、photo_count、evidence_summary。计数单位固定，不能混用。

`detail_target` 由类型和参数组成，前端映射到内部路由或浏览器，不能接受任意 URL。时间字段按现有接口约定序列化。cursor 应绑定根节点、类型、用户和排序条件；筛选变化后作废。用户不能通过改 cursor 或 node ID 越权。

分页期间数据变化不保证完整快照；使用稳定排序游标并按节点 ID 去重，刷新后重新计算。删除和权限变化必须实时过滤，不得为了保持分页快照继续返回失效数据。

### 7.3 数据模型与地点兼容

首版不新建通用 graph_nodes/graph_edges 表。原始业务表继续作为事实来源，关系按需派生。

建议为 MemoryPlace 补充可空的标准地点键、行政区结构化路径及解析状态/版本，以避免在线反复扫描历史文本地点。最终字段名在技术设计阶段固定；用户原始 name 保留。历史回填仅接受有唯一证据的解析，无法确认的保留 unresolved，不猜测。

回填采用可重试分批任务；只有当前节点所需少量未回填地点可按需解析，不能因打开关系页同步重建全库。照片地点、人脸、记忆成员变更触发相关投影失效或重算；读取端仍校验实时证据。新增节点键是派生索引，不作为旧数据能否打开的前置条件。

候选索引方向：MemoryPerson 的 `(face_identity_id, memory_id)`、MemoryPlace 的 `(标准地点键, memory_id)`，以及符合用户和删除过滤的照片/人脸/记忆连接索引。已有索引先检查查询计划再补充，避免重复创建。

任何 ORM/索引变更均提供 PostgreSQL 与 SQLite Alembic 迁移；同一 PR 每种数据库只保留一个合并迁移文件。覆盖空库升级、存量升级、回填中断重试，以及撤回功能后的原有页面兼容性。

### 7.4 前端结构

建议新增统一关系页、桌面图组件、移动卡片组件、比较结果组件、`src/api/relations.ts`、`src/types/relations.ts` 和 Pinia 探索 store。

两端共用规范化节点/边、当前中心、筛选、比较对象、分页信息和历史栈；仅展示组件不同。历史存当前中心和分页/视口/滚动位置，不保存整个图库。

优先验证已有 ECharts 的 GraphChart；通过项目集中入口按需注册，关系页懒加载。实施前用代表性 41 节点原型验证点击、拖动、稳定布局和缩放；若验证不通过，再评估专用图组件，不提前增加第二套图形依赖。

首次读取优先不加跨请求服务端结果缓存。前端可保留本次探索状态，但返回历史时重新校验数据；检测到版本变化或失效对象后更新显示。以后如增加缓存，必须以用户、参数和数据版本隔离，删除/隐藏操作同步失效。

## 8. 性能与可用性目标

以下为建议验收门槛，开发阶段必须记录测试硬件、数据库版本和数据集后实测，不能视为已达成：

- 基准数据：单用户 10 万张照片、1000 个人物、1 万段记忆，并包含一个关联大量照片的热门人物/地点；另设第二用户验证数据隔离。
- 在约定的参考环境（建议 4 vCPU、8GB 内存、SSD）上分别测试 PostgreSQL 与 SQLite；无并发写入及 5 个并发探索请求均记录结果。
- neighbors/common-memories 查询暖态 P95 ≤ 800ms；冷态 P95 ≤ 2s；计时包含权限、聚合及响应序列化。达不到时依据查询计划优化后重测，不以缩小结果正确性换速度。
- 关系接口 JSON 响应建议 ≤ 200KB，不内嵌图片；只下发缩略图引用。浏览器首批可操作目标 ≤ 2s（约定 100ms 往返延迟），大图预览按需加载。
- 桌面在最大节点数下缩放和选择无持续卡顿；移动端没有隐藏运行的力导向画布。低性能设备可切换列表。
- 限额在服务端强制执行，超限返回规范错误；对昂贵查询设置超时和请求取消，不允许无限递归/全量展开参数。

## 9. 可解释性、纠错与数据更新

边的摘要至少能打开一个依据列表。列表展示“你关联的记忆”“识别到人物的照片”“带地点信息的照片”，不向普通用户暴露 SQL、confidence 原值等实现细节。

纠错入口跳转现有人物、记忆或照片详情进行修改。返回后刷新相关中心与比较结果。失效的人脸、地点、删除照片、记忆状态变化都不应继续贡献自动关系；同一记忆下的其他有效依据可以继续保留该关系。

不使用语言模型生成关系事实。即便 AI 服务不可用，只要数据库已有有效数据，关联查询与浏览仍应可用。

| 工作包 | 产出 | 依赖 | 粗估工作量 |
| --- | --- | --- | --- |

建议通过功能开关上线：先自有测试数据，再小范围启用，观察慢查询、空结果和跳转失败，最后全量开放。关闭入口和新接口后既有人物/地点/记忆页面仍正常；派生地点字段保留，不删除用户业务数据。

### 11.2 必须覆盖的数据用例

测试数据：用户 U1 拥有人物 A、B、C；已确认记忆 M1 包含 A 的杭州照片 P1、B 的杭州照片 P2；M2 包含 A、B 同照的苏州照片 P3；M3 是包含 A、B 的候选记忆。U2 具有同名人物、同名地点和自己的照片。

| 编号 | 测试操作 | 预期 |
| --- | --- | --- |
| T01 | 选择 A+B | 共同记忆恰为 M1、M2；共同照片只有 P3；M3 不计入 |
| T02 | 选择 A+杭州 | 包含 M1；“在当地的照片”依据仅包含实际有 A 且位于杭州的照片 |
| T03 | 一段多城记忆中 A 仅在杭州照片出现，其他照片位于苏州 | A—苏州可显示同记忆关联，不能显示“在苏州拍到 A” |
| T04 | 没有任何已确认记忆但有同照/地点照片 | 直接照片关系可浏览；共同记忆为零，不自动创建事件 |
| T05 | P3 有多个重复人脸检测框 | 共同照片仍计为 1，不重复返回 M2 |
| T06 | 隐藏 B、删除 P3、归档 M1，分别执行并刷新 | 对应节点/证据/计数及时退出；其他有效关系不受误删 |
| T07 | 使用 U2 的节点 ID 或伪造 cursor 请求 | 返回不可用/非法请求，不泄漏摘要、头像、计数或证据 |
| T08 | 同名城市/区县来自不同父级行政区 | 图中是不同地点；详情精确过滤；仅名称入口要求消歧 |
| T09 | 只有“老家”等手工地点文本，无唯一地理证据 | 保留独立文本节点，可查看来源记忆，不误合并或产生死链 |
| T10 | 选择同一对象两次、两个不同记忆、记忆+其人物 | 分别阻止重复、正确空态、返回该记忆 |
| T11 | 合并/拆分已确认记忆 | 替代前记忆退出，新增记忆按现状计算，溯源关系不增加共同记忆数量 |
| T12 | 连续切换中心后旧请求迟到；进入详情后返回 | 旧响应不覆盖新中心；历史、筛选、比较状态正确 |
| T13 | 快速翻页期间修改/删除关联 | 无重复节点和越权数据，刷新后与真实数据一致 |
| T14 | 登出并切换用户/服务器 | 不显示上一个账号的图、卡片、比较对象或历史 |
| T15 | 最大节点数、长名称、主题切换、键盘操作 | 不溢出，暗色可读，列表可完成全部核心操作 |

测试分层：关系计算/去重/排序/消歧用单元测试；所有接口的权限、分页、迁移和双数据库行为用集成测试；三类入口→展开→返回→比较→详情闭环分别做桌面及移动端 E2E。性能另使用固定数据集记录基准。

本地与 CI 执行均走 `tests/scripts/run-tests.ps1`，环境变量使用 `tests/.env.test`；按 `tests/README.md` 选择层级和范围。当前实现已执行上述相关单元测试与本地浏览器验证；十万照片专项性能验收仍未执行。

| 决策 | 推荐默认值 | 影响 |
| --- | --- | --- |
