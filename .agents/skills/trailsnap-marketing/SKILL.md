# TrailSnap 产品运营

## 运营基线

- 第一受众是 NAS 用户；同时覆盖摄影爱好者、普通手机相册用户，以及喜欢仪式感的旅行记录者。单篇选择一个主要受众。
- 首要目标为产品曝光和 GitHub Star。体验、收藏、评论是辅助信号，不擅自改为付费转化或投放目标。
- 账号从零开始，尚无固定文风。初始采用清楚、亲切、具体的表达，测试实用教程、开发者分享、生活记录三种方向；不要把临时选择固化为用户偏好。
- 小红书与抖音默认图文/plog，不生成视频脚本或视频，除非用户另有要求。公众号承担深入介绍、教程和版本解读。
- 官网：https://trailsnap.cn/；演示：https://demo.siyuan.ink/；源码：https://github.com/LC044/TrailSnap 。使用前核验相关页面，不把访问失败当作服务下线。

## 按需读取

- 新版本预热、上线宣传、更新解读：读 [references/release-campaign.md](references/release-campaign.md)。
- 冷启动、选题排期、热点、教程、用户故事、竞品比较、复盘：读 [references/daily-operations.md](references/daily-operations.md)。
- 写平台内容或制作海报、图文组图：读 [references/content-production.md](references/content-production.md)。

## 工作方式

1. 确定本次受众、目标、平台和交付物，已有信息不重复询问。一般缺省按 NAS 用户、小红书图文、曝光优先推进；完整运营包才覆盖三平台。缺少版本号、真实故事素材等关键依据时，先查项目或连接来源，仍无法确定再问。
2. 核对产品事实后选择可展示的价值点。查阅根目录 `README.md`、目标版本 Release、`package/official-site/docs/guide/changelog.md` 和相关使用文档。以目标发布版本为准，当前分支和演示站可能领先于它；资料冲突时查实现或实测。
3. 把功能写成“具体场景 → 用户得到什么 → 截图或操作证据”。NAS 内容可从已有照片目录、检索、家庭回顾切入；硬件兼容、资源占用和部署难度须有依据。
4. 完成各平台文案初稿后，读取并调用 [humanizer-zh-pro](../humanizer-zh-pro/SKILL.md) 做一轮中文降 AI 味润色，覆盖标题、正文、图文页内文字和行动引导。此步骤同时适用于版本宣传与日常运营，在图片排版前完成；用户明确要求保留原文时遵从用户要求。
5. 润色后对照初稿与事实来源，保留产品名称、版本号、功能状态、数据、链接和使用条件，不为增加人情味而编造第一人称经历或用户评价。以自然、具体、符合平台语气为目标；没有检测报告时不编造 AI 率或宣称通过检测，润色说明与发布正文分开。
6. 使用润色后的定稿制作图片并完成发布建议。用户要成品时实际产出文件，不能只交提示词；工具或素材不足时明确已完成与缺失部分。单篇文案或海报不强制扩展为完整营销包。
7. 检查功能状态、图文一致性、链接、中文排版和平台适配。若排版后又修改文字，同步文案与图片。资料来源与待核实项放在内部备注，正文保持可直接使用。

## 文件与执行范围

- 普通运营内容默认放在仓库 `marketing/YYYY-MM-DD-主题/`；版本运营放在 `releases/v版本号/marketing/`。用户指定位置优先，日期按用户时区。仅创建本次需要的文件，冲突时另存修订版。
- 默认生成内容供用户手动发布。本技能不授予账号创建、对外发帖、评论私信、付费投放、自动排期或代码提交权限。已有明确授权的具体动作无需重复确认，执行前仍应有可审阅内容和明确目标账号。
- 仅做宣传不执行技术发版。若同时要求创建 Release，技术部分使用项目现有 `../release-publisher/SKILL.md` 流程，衔接方式见版本宣传参考。
- 最终提供成品路径、必要限制及建议下一步。不把内容生成称作已发布，也不承诺增长结果。
