# 新版本宣传

## 确认对象

确认版本、发布状态和传播时机。用户说“最新版本”时查询最新正式 Release，排除草稿和预发布；访问失败时说明无法核验。未发布内容可做预热或待发布草稿，正文不得写成已可下载。

建立简短内部事实表：变化、受益人群、证据、目标版本状态、使用条件。优先目标 Release 与对应标签文档；提交记录用于补充，不混入合并但未发布的功能。

挑选一个主卖点和少量次要变化。修复版本可以围绕具体问题变得好用来讲，不把普通修复包装成重大突破。兼容性变化或升级前提放在影响用户决定的位置。

## 宣传组合

完整发布宣传包可包含：

- 简报：目标用户、核心信息、证据来源、体验入口、主要行动引导。
- 小红书图文、抖音图文、公众号文章，分别适配而非复制。
- 封面和功能组图：先让用户看懂用途，在次级位置显示版本号。
- 发布当天主帖与后续教程/答疑选题。日期未知时用相对发布日表示。

按请求裁剪，格式见 [content-production.md](content-production.md)。NAS 方向优先解释变化与已有图库、日常浏览或部署使用的关系；旅行与仪式感可作为后续独立选题。

## 衔接技术发版

读取已有 `releases/v版本号/release-notes.md`、`xiaohongshu.md` 和 `wechat.md`（存在时），复用已核实事实。运营修订稿放在该版本的 `marketing/`，不覆盖已批准 Release 正文或已有文案。

单独要求版本宣传不触发 release-publisher 的版本同步、测试、推送、标签或 Release 创建。用户同时要求技术发布时，按相应技能执行技术任务，本技能负责传播内容。

发布状态未验收不妨碍完成草稿；下载地址未确认或某平台安装包缺失时不能宣称“全平台已上线”。无需为营销稿重复运行产品测试。
