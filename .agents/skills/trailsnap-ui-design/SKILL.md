# TrailSnap UI 设计

以照片与回忆为内容中心，让界面融入现有设计系统。用户明确指定新的视觉方向时按其要求设计，同时保留主题、可访问性和平台约束。

## 开始前

- 定位仓库根目录并读取适用的 `AGENTS.md`；本文源码路径均相对于仓库根目录。
- 阅读 `package/website/src/style.css`、`package/website/src/styles/ui.css` 与最接近目标页面的组件，以当前源码为准。确认组件实际 props、slots 和 exports，不猜测接口。
- 主题、样式和通用控件接入见 [设计基础与组件](references/design-system.md)；页面布局、媒体浏览、菜单弹层和验收见 [页面模式与验收](references/page-patterns.md)。只读任务相关部分。
- 只改善当前需求范围，发现旧样式不等于需要顺带改版。

## 设计原则

- **从用户目标出发。** 先明确用户要完成什么、最短操作路径是什么，再确定信息层级与控件。避免为解释界面而增加文案或操作步骤。
- **常用操作直接可见。** 桌面与移动端都保留当前任务的主要入口；低频、辅助和高级操作收入“更多”等二级菜单，避免继续层层嵌套。
- **用界面表达功能。** 优先使用熟悉的图标、控件形态、选中态和即时反馈；按钮与菜单使用简短动作名称。含义明确时可只用图标，有歧义时保留短标签，不让用户靠猜测操作。
- **只保留有用的文字。** 删除重复标题和显而易见的说明。表单优先呈现必要字段，低频配置按需展开；保留字段标签、格式要求、错误原因和关键后果，补充帮助按需就近出现，不用 placeholder 或悬浮提示替代必要信息。
- **精简不能增加理解成本。** 沿用一致的交互与图标含义，保证操作可发现、状态可辨认。照片与正文使用清晰实体表面；玻璃效果用于导航和浮动控制层，复用现有样式，避免装饰干扰内容。

## 实现约束

- Vue 使用 `<script setup lang="ts">`，共享状态使用 Pinia，HTTP 请求通过 `package/website/src/api/*`；沿用项目现有技术栈。
- 优先复用 `package/website/src/components/ui/`；照片浏览复用 `UnifiedPhotoPage` 与现有画廊。菜单、选择器和弹层按引用文档选用现有组件，避免重建已有交互系统。
- 中性色使用 `--ts-color-*` 或共享语义类，主题强调色使用 `primary-*`、`--theme-primary` / `--theme-rgb`，不硬编码品牌色。每个 `text-gray-*`、`bg-white` 及其变体配套 `dark:` 样式；Element Plus 继承全局明暗配置，不在实例内覆盖内部颜色。
- 子组件使用 `injectTheme()`，不重复创建主题 provider 或状态。图表、Canvas 和动态颜色读取 `currentTheme.value.primary` / `.rgb` 并随主题更新；涉及明暗时同时响应 `isDarkMode`。
- 全局导航、滚动容器和安全区遵循现有布局归属，不重复增加留白或嵌套全高滚动区。
- 图标优先沿用模块现有的 `lucide-vue-next`。图标按钮提供可理解的 `aria-label`，展开和选择状态提供相应 ARIA 属性；交互元素支持键盘且焦点可见。
- 根据可用空间和输入方式适配，不把桌面等同于鼠标、移动端等同于触屏。补充提示支持 hover/focus，必要信息不依赖悬浮；分页、连续加载和刷新方式按任务及现有模式选择，不因屏幕尺寸强制切换。手势操作保留可发现入口。

## 实施与验收

1. 用共享组件与 token 实现布局，补齐本次功能涉及的加载、空数据、错误重试、提交中和禁用状态。
2. 检查核心入口是否可见、低频操作是否合理收纳、图标是否易懂、文案是否必要；按 [页面模式与验收](references/page-patterns.md#按改动选择验收) 选择明暗主题、视口和交互检查，有可用环境时进行浏览器验证。
3. 构建和测试分别遵循 `package/website/README.md` 与 `tests/README.md`，测试统一使用 `tests/scripts/run-tests.ps1`，配置来自 `tests/.env.test`。仅修改 Skill 文档时验证 Skill 与引用，不运行应用测试。
4. 使用 Playwright CLI 时遵循可用的 playwright 技能。开发账号为 `trailsnap` / `trailsnap`；登录失败询问用户，不自行创建账号。

用户只要方案时提供可落地的设计；要求实现时完成代码与相关验证。交付说明改动、实际检查及剩余限制，未运行或未截图验收时如实说明。
